# 文档权威与重复合同审计

Status: proposed  
Review date: 2026-08-10

> **历史证据声明**：本文件仅保留截至 2026-08-10 09:03 CST 的工作树快照、当时未决判断和机械计数，不再作为现行实施合同。产品与工程结论已由[首版规格](spec.md)、[领域词汇](../../CONTEXT.md)、[ADR](../../docs/adr/)、本目录中 `Status: resolved` 的答案登记和[现行事项](issues/)取代；有冲突时以后者为准，本文计数与状态使用前必须重新验证。

当前仓库已经有足够多的规格，但同一规则经常在多个文档中完整复制。本文提出一张最小权威地图，供维护者确认后清理重复；它不自动改变任何既有文档的效力。

## 1. 建议的单一权威地图

| 内容类型 | 建议唯一权威 | 其他文档应如何引用 |
| --- | --- | --- |
| 用户可观察行为、状态转换、成功/失败/恢复场景 | `.scratch/windows-initial-setup-workbench/spec.md` | 事项引用需求 ID；设计/架构只说明本层如何满足，不复制整套行为 |
| 统一领域词汇 | `CONTEXT.md` | 只定义“是什么”和禁用同义词；不放字段、状态机或模块规则 |
| 难逆、非显然、有真实取舍的决定及原因 | `docs/adr/` | 规格和工程文档链接 ADR，不重写历史理由；替代时显式 supersede |
| 模块边界、依赖方向、装配和无界面测试原则 | `docs/engineering/architecture-and-code-quality.md` | ADR 记录为何采用；事项只验收自己拥有的合同 |
| WinUI 3 布局、交互、无障碍和动效验收 | `docs/design/winui3-apple-inspired.md` | 规格保留结果行为；事项 24 维护资源和共性，不拥有所有页面功能 |
| 当前机器可读软件目录事实 | `catalog/software-catalog.toml` | 维护指南解释填写；审核稿和事项不能成为第二份运行目录 |
| 目录填写方法 | `docs/maintainers/software-catalog-input.md` | 只解释字段和流程，不承载运行时状态机或完整 UI 合同 |
| 工作拆分、所有者、依赖和完成证据 | `.scratch/.../issues/*.md` | 引用规格 ID/架构/设计，不复制别的事项完整验收 |
| 官方事实、版本快照、实验和证据限制 | `docs/research/` | 明确非规范；决定落入 ADR/规格后只保留来源和日期 |
| 第三方内容、构建来源、实机与发布证据的审核状态 | `.scratch/windows-initial-setup-workbench/preimplementation-evidence-register.md` | 研究只能提出结论；只有登记册记录适用范围、审核人和日期后的 `accepted` 才能满足门禁 |

| 项目入口与当前阶段 | `README.md` | 只做导航和诚实状态，不声称全部文档都已最终确认 |
| 贡献、Agent 操作规则 | `CONTRIBUTING.md`、`AGENTS.md` | 只保留贡献/代理约束，链接工程与设计权威，不复制产品合同 |

## 2. 冲突时的处理提案

1. 维护者在 `grill-with-docs` 中的新确认是待同步证据，不会自动使旧 ADR 或规格静默失效；先记录冲突和影响，再显式同步。
2. 已接受 ADR 与新确认冲突时，不能只改 ADR 原文；保留历史并新增 superseding ADR，或明确修订状态与理由。
3. 主规格与事项冲突时，事项应改成实现/验证规格，而不是让事项发明另一套行为。
4. `CONTEXT.md` 与规格冲突时，先判断是词义还是行为：词义回 CONTEXT，行为回规格；不得在定义里隐藏状态机。
5. 研究或候选稿不能覆盖正式决定；它们只能提供证据、选项和待同步记录。
6. 机器可读目录与 Markdown 列表冲突时，运行时只读 TOML；发布流程必须把 Markdown 中的已确认内容显式晋级后才生效。

## 4. 推荐的清理顺序

1. 另一个 `grill-with-docs` 任务已经同步“恢复但仍未保存”的核心语义；本任务不重复改写，只等待它收口启动呈现 Q1，并在后续写回前重新读取最新磁盘状态。
2. 先回答当前前沿 Q4a-b/Q10/Q8/Q9/Q2/Q3/Q11a-b/Q12-Q15/Q5a-e/Q6；再按依赖展开 Q4c-h、Q5f-l、Q7、`REDIST-D2..D10`、`RELEASE-D2..D7` 与其余 `INSTALLER-D*`，关闭会推翻 ADR、安全控制面、持久化、内容权利与发行矩阵的产品问题。
3. 新增或 supersede 必要 ADR；只记录真实取舍，不为每个字段建 ADR。
4. 一次性更新主规格中的原子需求和状态机，并重新生成需求-事项覆盖审计。
5. 精简 CONTEXT 的实现字段与正式术语碰撞。
6. 把架构、设计、维护指南和事项中的重复段落缩成各自层面的合同与链接。
7. 最后修 README/CONTRIBUTING 导航，避免在正式权威尚冲突时宣称全部目标已确认。

## 5. 可机械检查的门禁

- 每个规格 ID 唯一、连续，并至少有一个候选所有者。
- 每个高风险行为只在主规格出现完整状态机，其他文档包含链接和本层增量。
- 每个 ADR 有可判断的当前状态；被替代决定通过编号关系可追溯。
- CONTEXT 的 `_Avoid_` 不引用任何正式术语，定义不含实现字段或流程。
- 软件事实不同时存在于两份机器可读维护文件。
- 研究文档首页明确日期、来源边界和非规范状态。
- README 的阶段描述与源码、构建、CI、发行制品的实际存在情况一致。
