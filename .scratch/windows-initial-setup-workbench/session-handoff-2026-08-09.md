- 已确认调试模式通过设置开关即时启用并跨重启保留，输出最高可用粒度的本机结构化日志，同时脱敏且不自动上传；开启后提供日志位置、诊断导出和软件目录编辑器，关闭后恢复普通日志粒度并隐藏调试工具。一次诊断导出形成一个格式版本可识别、自包含的文件，使未接触原 Windows 测试机的开发者只凭该文件即可还原工作台可观察的构建与相关环境、有效目录和批次、覆盖范围内的用户命令与事件顺序、失败阶段、原始错误和最后可信状态；所有已知或可检测的采集缺口及最后落盘后的未知区间必须明确标记，不能要求测试者另外提供截图、口述步骤或环境清单。日志允许保留非唯一硬件型号、驱动版本、网络状态和规范化路径，但凭据、计算机名、用户名、唯一设备标识、MAC/IP、SSID、用户目录名称和敏感 URL 必须排除或匿名化。
- 已确认图形化软件目录编辑采用“保存草稿 → 应用”的两阶段行为：编辑和保存只更新目录编辑草稿，不改变当前软件列表、选择、规划或执行；已经保存但尚未应用的草稿跨正常关闭和重新打开保留，重开后仍显示“已保存未应用”，可继续编辑、明确应用或删除，绝不自动应用，删除草稿也不改变当前有效目录、既有批次或历史。同一次运行中存在未保存修改时，切换页面、切换标准视图与高级视图或关闭调试模式不弹出关闭确认，不丢失修改，也不自动保存、放弃或应用；重新打开编辑器后仍显示“未保存更改”。只有用户主动关闭整个工作台时，才提供“保存草稿并关闭”“放弃未保存修改”和“返回编辑”；保存成功后才关闭，放弃只移除上次保存后的修改并保留此前草稿，返回编辑取消关闭，所有路径均不应用目录。只有用户明确点击“应用”，且当前已保存内容重新通过与文件加载相同的核心校验并达到运行时加载门槛后，才完整替换当前有效目录。整包错误使应用失败并保留旧目录、草稿和可定位错误；允许的局部依赖错误随整份新目录切换并禁用受影响项，不混用旧定义，因此不属于部分应用。应用成功只影响之后的软件列表、主动规划和新建批次，不改变维护目录发布状态，既有批次快照及历史不变。工作台异常退出或电脑断电后，下次启动应尽量找回尚未保存的目录修改，并明确标为“恢复的未保存修改”；找回内容仍未保存，绝不自动保存、应用或覆盖此前已保存版本。用户显式保存后，它才转为“已保存未应用”并清除对应恢复状态；放弃只删除恢复的未保存内容，不影响此前已保存草稿、当前有效目录、既有批次或历史。恢复失败必须如实显示，不能把内容伪报为已找回。恢复的写入频率和内部存储格式暂不规定。
- 已确认运行时加载校验与正式发布门禁分别产生结果且不能互相替代；运行时通过是正式发布通过的必要但不充分条件，运行时失败时发布结果不能通过。`release_state = "draft"` 或其他仅发布级问题不会单独阻止运行时可加载的已保存草稿在调试模式中应用为“本机试用目录”；整包级运行错误仍然阻止应用。应用不改变 `release_state`，不表示发布检查通过，也不能让该目录进入正式发行包。本机试用只是同一当前有效目录的持续身份，界面、日志和之后的新批次快照都要记录；关闭调试模式只隐藏编辑入口，不撤销目录或隐藏其未发布状态。设置页手动导入的同类软件目录使用相同身份，不能绕过提示和记录；导入成功后在设置页的软件与驱动目录当前状态或导入区域原位立即显示，焦点返回触发导入的命令，后续恢复不重复播报。

### DirectX 只读资料结论

- 随附说明把 DirectX Repair 定义为免安装的系统级检测与修复工具，主要处理 DirectX 异常和 `0xc000007b`，增强版还可检测或修复 C++ 组件。
- 它支持先检测再修复；强力修复只应在普通修复无效时使用。因此后续设计应保留检测结果、风险说明和强力操作的单独确认，不能把强力修复无条件静默执行。
- 随附配置声明支持 .NET Framework v4.0 和 v2.0.50727；说明称 Vista 及后续 Windows 可直接运行。
- 微软官方说明：现代 Windows 已包含 DirectX 主运行时；官方 DirectX End-User Runtime 主要补充旧游戏使用的 D3DX、XAudio、XInput 等旧版并行组件，并不改变系统 DirectX 版本。后续应把“官方旧版运行库安装”和“第三方 DirectX 检测修复”区分为两个能力。
