# 事项 20：ITBar7Layout Windows 一次性交接包

## 目的

事项 20 的生产目录和适配器已冻结并实现 Windows 11 经典右键菜单的一个 CLSID，以及 Windows 10 风格资源管理器的两个 CLSID。`ITBar7Layout` 的资料值未进入生产代码，因为当前仓库没有足够的 Windows 实机证据证明该二进制布局值在目标版本上可安全写入、检测和恢复。

## 可追溯观察

- 来源：`https://zhuanlan.zhihu.com/p/690092810`
- 读取方式：一次只读网页快照，2026-08-12；网页内容仅作交接证据，不是运行时输入。
- 来源示例声明适用于 Windows 11 22H2，并给出 `HKCU\\Software\\Microsoft\\Internet Explorer\\Toolbar\\ShellBrowser` 的 `ITBar7Layout` `REG_BINARY` 示例。
- 观察到的示例开头为：`13,00,00,00,00,00,00,00,00,00,20,00,00,00,10,00,01,00,...`；完整二进制布局值依赖来源页面，未被项目审核冻结。

## Windows 验证交接

在 Windows 11 25H2 实机或隔离用户配置上，由维护者一次性完成以下核对：

1. 在不修改工作台状态的条件下备份当前 `ITBar7Layout` 类型、完整字节和资源管理器可观察布局。
2. 仅应用已实现的两个固定 CLSID 映射，记录资源管理器样式是否已经达到预期；确认没有 `ITBar7Layout` 时是否仍满足目标。
3. 在隔离用户上按来源示例写入完整值，重启资源管理器并记录字节、界面效果、失败行为和恢复后的原始值。
4. 若确需该值，先把完整字节、适用范围、检测和恢复语义固化为项目拥有的类型化受控能力，再新增适配器合同与真实 Windows 证据；不得开放二进制输入字段。
5. 若两个 CLSID 已足够，明确标记 `ITBar7Layout` 为无需执行的来源附加项，保留本交接记录，不把文章示例转入目录执行语义。

## 当前边界

本包不是生产能力，不是自动测试通过证明，也不授权工作台导入 `.reg`、网页内容或任意 `REG_BINARY`。真实 Windows Explorer 重启、界面效果、UAC 和恢复验证仍未验证。
