# 第十三轮 Grill 答案登记

Status: resolved  
Date: 2026-08-21  
Scope: 动态稳定版本、安装器架构与 DirectX Web Installer 的受控安装边界

本轮只收口已进入前沿的产品与发行边界；不开始产品实现、目录启用、构建、候选安装、GitHub Release 或真实设备验证。

## 已确认决定

- Q20：选择方案 A。来源解析发现同一声明发行分支的新稳定版本，而该版本尚无精确适用的受控安装档案时，暂停当前软件，等待档案适配；不得以通用交互式档案启动新版本的官方安装器。该暂停遵守既有的逐软件边界，不阻断工作台或无关软件。
- Q21：选择方案 A。在 x64 Windows 上，厂商只提供 x86 安装器时可以作为兼容安装器受控执行；来源解析结果、批次快照、执行记录和结果检测必须保留实际安装器架构。该选择不把 x86 安装器伪装为 x64，也不解除软件发行分支、稳定版本、受控安装档案或结果检测的要求。
- Q22：选择方案 A。DirectX 保留 `9.29.1974.1` End-User Runtime Web Installer 的固定版本策略，将它视为稳定发行分支内固定的官方引导程序例外；不把它伪称为“动态解析的最新完整包”。它仍须满足受控安装档案、在线联网要求、安装后置行为和结果检测的发布级校验后才可启用或进入发行目录。

## 同步边界

- Q20 收紧 `SRC-15`、`SRC-16` 的动态稳定版本路径：新的解析结果不自动跨越受控安装档案的适用版本边界。
- Q21 明确“没有适用安装包”的架构判断允许在 x64 Windows 上接受已知的 x86 兼容安装器；其他架构、版本或包类型事实不明时仍按既有 fail-closed 规则暂停。
- Q22 是对 DirectX 的版本策略例外，不扩展为其他软件可长期使用会漂移的安装文件直链，也不改变完整安装包优先于在线安装器的通用规则。
- 当前 `catalog/software-catalog.toml` 继续保持 `release_state = "draft"`，DirectX、Java、.NET 和 PowerShell 7 继续未启用；本记录不是来源解析、档案适配、生产安装或真实 Windows 证据。
