本文集中记录开始实现前后需要补齐、可审计的事实与工程证据。它不是许可意见、威胁模型结论或发布批准；“本地已有”“能够安装”“维护者希望随包”都不等于证据通过。ADR-0035 与 ADR-0036 已确认：来源、签名、摘要、许可、身份、再分发和 provenance 的记录不作为用户主动更新、受控执行或候选资源随包、公开发布的项目级门槛。

## 1. 证据状态

| 状态 | 含义 |
| --- | --- |
| `not-started` | 尚未取得或审核证据 |
| `collecting` | 已有线索，但证据范围或版本仍不完整 |
| `needs-decision` | 事实已足够，仍需维护者作产品或风险决定 |
| `accepted` | 证据、适用范围、审核人与日期均已记录，可用于指定门禁 |
| `rejected` | 证据不支持该用途；保留研究结论，不得表述为已获许可或已验证，但不单独决定候选资源是否随包或公开发布 |
| `expired` | 上游版本、条款或适用范围变化，必须重新审核 |

`accepted` 只表示证据、适用范围、审核人与日期齐全，可供需要该事实的工程合同消费；它不再决定候选资源能否随包或公开发布。状态必须附证据位置、适用版本/架构、审核人和审核日期；口头确认不能单独把状态改成 `accepted`。

## 2. 第三方内容与再分发台账

### 2.1 必填字段

每个拟随公开制品携带或由项目镜像的二进制，至少记录：稳定内容标识、上游主体、原始下载页与精确下载 URL、取得日期、原始文件名、版本、架构、文件摘要、签名/发布者、许可或再分发条款证据、允许的地域与渠道、是否允许改名/重打包、归属与 NOTICE 要求、复核日期、审核人、结论和回退来源。

动态官网解析但不由项目再分发的内容也要记录来源所有权、HTTPS/重定向边界和发布者预期；其门禁与“允许随包”分开判断。

## 3. 高权限下载与执行证据

本节保留高权限路径的已知风险、实现合同和可观察事实；Q4 已确认不把信任或真实性证据作为项目级门槛，Q5 已由 ADR-0029 冻结持久化边界，Q8 已确认真实设备证据不阻断公开发行。缺失证据必须如实记录，不能被写成已验证。

一手事实、现行冲突和候选验证矩阵见[常驻管理员工作台的下载、缓存、执行与自更新安全研究](../../docs/research/elevated-download-execution-security.md)。研究完成不等于下表证据通过；其中将 Q4、Q5 或 Q8 写作前置门槛的旧列为历史建议，当前决定以 ADR-0029、ADR-0034、ADR-0035 和 ADR-0036 为准。

| --- | --- | --- | --- |
| 目录输入到 URL 解析 | 允许协议、主机所有权、逐跳重定向、DNS 与私网/特殊用途地址、大小/时间限制和失败关闭测试 | 当前允许原始 HTTP(S) 且会自动识别页面/直链；研究已证明 URL 分段、TLS 与最终发布者真实性不是同一保证 | 风险与实现观察项，非项目级信任门槛 |

## 5. 需求追踪记录格式

每个规范需求至少映射到一张所有者事项。每个对外行为和风险门禁再映射到自动测试、无界面合同测试或实机证据之一；“文档提到”不等于“已验证”。推荐记录字段：

| 字段 | 含义 |
| --- | --- |
| `requirement_id` | 主规格中的唯一原子需求 ID |
| `owner_issue` | 负责提供行为或合同的唯一事项 |
| `consumer_issues` | 依赖该合同但不重复拥有它的事项 |
