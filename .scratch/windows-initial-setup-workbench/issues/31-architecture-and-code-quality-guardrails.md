# 建立架构与代码质量门禁

Type: task
Status: needs-info
Blocked by: 01

## Goal

把易维护、低耦合、高内聚、界面与核心分离以及可局部扩展落实为首版实现和发布的硬性门禁，使新增目录内容或内置受控能力时无需改动无关模块，并确保技术先进性不会以牺牲可读性、可测试性和长期维护成本为代价。

## Acceptance Criteria

- [ ] 模块职责、公开接口和单向依赖关系已有明确说明；界面层依赖核心接口，核心通过自己拥有的接口请求平台能力，平台适配器不得反向依赖界面或把平台细节泄漏给可移植核心。
- [ ] 应用只有一个明确的装配入口负责创建并连接核心、目录、持久化和平台适配器；业务模块不得各自隐式创建跨层依赖或使用服务定位器绕过装配入口。
- [ ] 核心状态是任务规划、执行进度、恢复状态和结果的唯一事实来源；界面只提交意图并显示核心状态，不维护能够与核心分歧的第二份业务状态。
- [ ] 调试模式、当前有效软件目录和目录编辑草稿各自只有一个核心所有者；`release_state`、运行时加载结果、正式发布门禁结果和本机试用身份是由目录核心统一拥有的不同事实，但正式发布通过必须以运行时整包校验通过为前提，运行时失败时正式发布结果只能是失败或不可判定、不能通过。本机试用只是当前有效目录的持久属性，不是第三份目录或界面临时状态。编辑器只提交类型化的编辑、保存草稿、删除草稿和应用意图，不直接解析或写入 TOML，也不复制目录校验或生效规则；保存不改变当前有效目录，已保存未应用草稿跨正常关闭和重新打开保留，删除草稿不改变当前目录或既有记录，应用重新校验当前已保存草稿后才完整替换。同一次运行中的未保存修改继续由目录核心拥有，页面、视图和调试模式切换不得清除、持久化或应用它们，也不得触发只有关闭工作台才需要的三项决策。异常退出或电脑断电后找回的“恢复的未保存修改”、已保存未应用草稿与当前有效目录是三个分别建模的事实；找回不得覆盖或损坏已保存版本，也不得把恢复内容提升为已保存或已应用状态。
- [ ] 恢复的未保存修改继续受未保存状态合同约束，界面与核心均拒绝应用；显式保存成功后才原子地更新已保存未应用草稿并清除对应恢复状态，保存失败保留恢复内容和此前已保存版本，放弃只删除恢复的未保存部分且不影响此前草稿、当前目录、既有批次或历史。找回失败不能产生成功恢复事实。恢复写入频率和内部存储格式属于适配器实现选择；启动时由界面显示不阻断的持续“继续编辑”入口，用户主动进入编辑器，核心状态语义不依赖具体导航实现。
- [ ] 依赖图不存在循环依赖，界面代码不直接修改注册表、配置、进程、文件系统或其他系统状态。
- [ ] 同一业务规则只在一个明确的核心模块或目录契约中定义；界面、平台适配器和多个功能模块不得复制或各自解释同一规则。
- [ ] 不存在跨功能共享的全局可变业务状态；确需跨模块共享的状态必须由职责明确的核心对象拥有，并通过受控接口访问。
- [ ] 可移植核心能够在不启动 WinUI 3、无需管理员权限、无网络且不真实修改电脑的条件下完成自动测试，覆盖规划、状态变化、失败恢复、结果判定和日志语义。
- [ ] 无界面调度合同使用可控测试调度器覆盖单核路径、受限并行上限、取消、异常与结果合并，并证明结果与串行计算具有相同业务结论；并行内部计算不得创建第二份批次状态、改变批次顺序或跨实例互斥，也不得并行启动安装器、系统优化、软件优化、权威提交、结果确认或恢复判断。
- [ ] 无界面测试覆盖软件目录图形化编辑的增删改、保存草稿不生效、已保存未应用草稿跨正常关闭、异常退出、断电后重新打开保留且不自动应用、仅有已保存草稿时关闭不弹未保存确认、重开后的已保存草稿可继续编辑或明确应用、删除草稿不改变当前目录和既有记录、同一次运行中切换页面、切换标准视图与高级视图及关闭调试模式均不弹关闭确认、不丢失修改且不自动保存或应用、重新打开编辑器仍显示未保存状态、已有已保存草稿后产生未保存修改时应用请求被拒绝且既不应用旧草稿也不隐式保存新修改、未保存修改下主动关闭的三项选择、保存成功关闭后重开为更新后的“已保存未应用”且当前有效目录不变、保存失败保持打开且不部分覆盖此前已保存版本、放弃只回到此前草稿、返回编辑取消关闭且所有路径均不应用目录、调试模式关闭后的临时编辑会话只允许编辑、保存或放弃且应用请求在界面与核心中均被拒绝、正常应用时重新校验、运行时整包失败时保留旧目录与草稿、运行时通过但发布未通过时完整切换并标记本机试用、关闭调试模式不撤销身份、发布流程继续拒绝、既有批次快照不变、TOML 兼容往返，以及调试日志粒度切换、本机试用来源与应用关联、结构化关联和集中脱敏；另覆盖异常退出和断电后尽量找回未保存修改、恢复内容与已保存草稿及当前目录隔离、应用拒绝、显式保存后的状态迁移和恢复状态清除、保存失败保护旧版本、仅放弃恢复部分及找回失败不产生成功事实。测试不固定恢复写入频率和内部存储格式；启动呈现由界面验收确认持续“继续编辑”入口，核心测试不依赖自动导航。凭据、计算机名、用户名、唯一设备标识、MAC/IP、SSID、用户目录名称与敏感 URL 使用固定测试值证明被排除或匿名化，允许的非唯一硬件型号、驱动版本、网络状态和规范化路径仍可用于诊断；真实文件与日志适配器通过同一合同替换。
- [ ] 诊断合同测试向测试适配器注入目录、来源、下载、安装程序、恢复和异常退出故障，只把单个导出文件交给读取端时仍能还原构建与环境、用户命令、关联事件、失败阶段、原始错误和最后可信状态，并准确显示采集缺口且不泄漏敏感内容。
- [ ] 界面与核心之间、核心与平台适配器之间均有合同测试，覆盖正常结果、失败结果、取消、重启屏障和不受支持状态，确保替换界面或适配器不会改变既有业务语义。
- [ ] 凡既有内置受控能力能够表达的普通软件、下载来源、驱动入口、系统设置或软件优化方案，只增加目录定义及其数据；自动检查会证明既有页面、主流程和无关能力模块无需修改。
- [ ] 新增一种内置受控能力时，改动只涉及对应核心接口、生产与无副作用测试适配器、唯一装配入口、必要的版本化目录模式及相关无界面测试、合同测试和架构检查；未知执行语义或未知能力会使旧版本拒绝整份候选目录并保留当前有效目录，不得修改无关页面、无关目录类型或其他执行能力。
- [ ] 构建和持续检查会自动检测循环依赖、越层依赖、界面直接使用系统操作能力、违反模块边界以及未完成的合同测试；任何违反项都会阻止发布。
- [ ] 架构检查阻止图形化目录编辑器直接链接目录文件或执行适配器，并证明调试模式不能关闭目录校验、日志脱敏或安全边界；本机试用路径不能修改或伪造正式发布门禁结果，也不能把试用目录送入发行制品。
- [ ] 自动检查负责可机械识别的依赖、状态和边界问题，代码评审同时使用状态所有权、删除检验和规则归属检查重复业务规则及跨功能全局可变业务状态；任一硬性缺陷都阻止发布，不得用事项内例外批准绕过，确需改变规则时必须先修改规格和 ADR。
- [ ] 编译器、语言特性、库和框架优先采用满足产品约束的最新稳定方案；实验性或复杂的新技术只有在改善现有目标且不降低可读性、可测试性、工具链稳定性和双架构可构建性时才能进入生产边界。
- [ ] 架构门禁具有可重复执行的项目命令，并在开发者发布证据中明确记录检查结果；“功能暂时可用”不能替代通过架构与代码质量门禁。
