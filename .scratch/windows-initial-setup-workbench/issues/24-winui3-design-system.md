# 建立 WinUI 3 的 Apple 风格设计系统

Type: task  
Status: ready-for-agent  
Blocked by: 01

## Goal

依据专用设计文档建立 Windows 原生、Apple 风格适配的界面基础，并覆盖标准视图与高级视图。

## Acceptance Criteria

- [ ] 使用 WinUI 3 与 Fluent Design 原生交互习惯，不仿制 macOS 窗口和导航。
- [ ] 设计系统可由 C++/WinRT 与 XAML 实现，不要求 .NET 或在界面层复制业务规则。
- [ ] 建立布局、字体、图标、材质、反馈、动效和风险操作规则。
- [ ] 定义标准视图与高级视图的信息层级及共享状态绑定规则，为应用设置页实现即时切换提供可复用的界面基础。
- [ ] 标准视图可完成推荐流程；高级视图增加低频选项和手动控制但不解除安全边界。
- [ ] 导航和推荐流程统一使用“系统优化”，顺序为“驱动 → 系统优化 → 软件安装 → 软件优化”，不再向用户显示“系统设置”作为一级页面名称。
- [ ] 系统优化页优先呈现“推荐总体优化”摘要，下一层再展开可勾选的单项；组合与单项使用同一状态，避免同一设置出现两套结果。
- [ ] 低影响系统优化可默认勾选，明显改变界面或使用习惯且影响较大的项目默认不选；经典右键菜单和 Windows 10 风格资源管理器始终默认不选。
- [ ] 超出设置已知 Windows 适用范围时，标准视图显示“可能不适用”和说明；只有具备明确恢复规则时，高级视图才显示经风险确认的“仍然尝试”，两种视图都保留恢复信息。
- [ ] 资源管理器重启提示用一次清楚的选择呈现“立即重启资源管理器”和“稍后处理”，说明任务栏和窗口会短暂关闭，并能持续显示“等待资源管理器重启”。
- [ ] 系统优化与软件优化不显示当前用户、软件账号或整台电脑的范围标签，改用简短、具体的实际影响说明。
- [ ] 软件优化页在两种视图中保持相同的已安装软件分组和选择，高级视图只增加版本、检测与修改细节，未安装软件不展示。
- [ ] 软件自身提供的资源管理器右键扩展显示在对应软件优化方案中；Windows 自身的菜单和资源管理器样式只显示在系统优化页。
- [ ] “暂不支持自动处理”的软件优化项保持可见，提供手动设置和来源入口，不以弱化样式或隐藏方式造成已支持的误解。
- [ ] 软件优化的强制命令只在高级视图显示，标准视图保留完整原因、安全处理方式和无状态丢失的高级视图入口。
- [ ] 多软件正常优化只显示一次分组确认摘要，额外强制风险在触发前分别确认，不产生连续的普通确认弹窗。
- [ ] 收起“可以优化”提示不会永久隐藏方案或反复弹出，软件优化页继续提供明确状态和入口。
- [ ] 软件优化页只保留当前状态和最近结果，完整历史通过明确入口在“历史与日志”页定位查看。
- [ ] 主要流程支持鼠标、键盘、触摸和屏幕阅读器。
- [ ] 通过浅色、深色、高对比度、减少动画、减少透明度和 200% 文本缩放验收。
- [ ] 动效不锁定输入，材质不叠加，文本不截断或重叠。
- [ ] Windows 10 22H2 或系统材质能力不可用时使用实体背景回退，不因缺少 Mica/Acrylic 阻止功能。
- [ ] 字距保持 `0`，字号不随窗口宽度缩放。
