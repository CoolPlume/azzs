# 建立 WinUI 3 的 Apple 风格设计系统

Type: task  
Status: ready-for-agent  
Blocked by: 01

## Goal

依据专用设计文档建立 Windows 原生、Apple 风格适配的界面基础，并覆盖标准视图与高级视图。

## Acceptance Criteria

- [ ] 使用 WinUI 3 与 Fluent Design 原生交互习惯，不仿制 macOS 窗口和导航。
- [ ] 设计系统可由 C++/WinRT 与 XAML 实现，不要求 .NET 或在界面层复制业务规则。
- [ ] 建立布局、字体、图标、材质、反馈、动效和风险操作规则。
- [ ] 界面不假定固定分辨率、单显示器或单一 DPI；4K、225% 显示缩放是首版必达场景，显示缩放与 Windows 文本缩放分别适配，字号不按分辨率或窗口宽度比例改变，主要文字、命令、状态带、进度、列表、对话框、浮层和命中区域保持可读、可见、可点击且不重叠。
- [ ] 窗口跨不同分辨率、DPI 或显示缩放的多个显示器移动，或显示器接入、断开、主显示器改变后，重新布局而不重启；当前页面、选择、焦点、键盘导航、未提交输入、批次进度与滚动语义保持，原窗口位置不可见时恢复到可用工作区。
- [ ] 定义标准视图与高级视图的信息层级及共享状态绑定规则，为应用设置页实现即时切换提供可复用的界面基础。
- [ ] 标准视图可完成推荐流程；高级视图增加低频选项和手动控制但不解除安全边界。
- [ ] 导航和推荐流程统一使用“系统优化”，顺序为“驱动 → 系统优化 → 软件安装 → 软件优化”，不再向用户显示“系统设置”作为一级页面名称。
- [ ] 系统优化页优先呈现“推荐总体优化”摘要，下一层再展开可勾选的单项；组合与单项使用同一状态，避免同一设置出现两套结果。
- [ ] 低影响系统优化可默认勾选，明显改变界面或使用习惯且影响较大的项目默认不选；经典右键菜单和 Windows 10 风格资源管理器始终默认不选。
- [ ] 超出设置已知 Windows 适用范围时，标准视图显示“可能不适用”和说明；只有具备明确恢复规则时，高级视图才显示经风险确认的“仍然尝试”，两种视图都保留恢复信息。
- [ ] 资源管理器重启提示用一次清楚的选择呈现“立即重启资源管理器”和“稍后处理”，说明任务栏和窗口会短暂关闭，并能持续显示“等待资源管理器重启”。
- [ ] 系统优化与软件优化不显示当前用户、软件账号或整台电脑的范围标签，改用简短、具体的实际影响说明。
- [ ] 软件优化页在两种视图中保持相同的已安装软件分组和选择，高级视图只增加版本、检测与修改细节，未安装软件不展示。
- [ ] 软件安装页在两种视图中保持相同的软件目录、分类、可选择状态和勾选结果；不存在仅高级视图可选的软件，高级视图只增加细节和低频控制。
- [ ] 设置页以即时、可持久化的开关提供调试模式，开启时清楚显示状态、额外日志影响、日志位置、诊断导出和图形化软件目录编辑器入口；调试状态不随标准视图与高级视图切换。
- [ ] 图形化软件目录编辑器使用密集、稳定、可缩放的列表与详情布局，按字段类型提供合适控件，错误就地显示且可定位；分别提供“保存草稿”和“应用”命令，并分开显示草稿生命周期与当前目录身份。草稿生命周期至少区分未保存更改、已保存未应用和校验失败，当前目录身份区分普通有效目录与本机试用目录。保存后的软件列表保持不变；已经保存但尚未应用的草稿在正常关闭和重新打开后原位恢复为“已保存未应用”，可继续编辑、明确应用或删除且不自动执行。同一次运行中存在未保存修改时，离开编辑器页面、切换标准视图与高级视图或关闭调试模式均不弹确认、不丢失修改、不自动保存或应用，重新打开编辑器后仍显示“未保存更改”。只有主动关闭整个工作台时才使用一次居中模态确认，提供“保存草稿并关闭”“放弃未保存修改”和“返回编辑”；保存失败留在编辑器，放弃项不默认聚焦且只移除未保存部分，任何选项都不应用目录。若调试模式已关闭，保存失败或返回编辑只临时恢复原编辑会话，不改变调试模式偏好或日志粒度，再次离开后入口继续隐藏；临时会话中的“应用”保持禁用并提示先重新开启调试模式。整包应用成功后才切换；局部依赖错误随新目录切换并把相关项显示为禁用，不与强制或部分应用混淆。高频编辑、筛选、验证、状态反馈与日志刷新即时完成，不播放页面、弹簧或庆祝动效，也不存在强制应用无效整包、任意命令、脚本或插件的界面入口。
- [ ] 异常退出或电脑断电后成功找回的目录修改使用完整文字“恢复的未保存修改”，与“已保存未应用”和当前有效目录清楚分开；不得使用绿色完成、勾选、庆祝动效或其他已保存、成功语义。恢复内容仍按未保存状态呈现，“应用”保持禁用并就地说明须先保存；显式保存后转为“已保存未应用”并清除对应恢复状态，放弃只移除恢复的未保存部分且不改变此前草稿、当前目录、既有批次或历史。恢复失败不能显示为已找回。启动时只显示不阻断的持续“继续编辑”入口，用户主动进入编辑器；该提示不得改变上述状态语义。
- [ ] 本机试用目录在标准视图与高级视图的软件安装页、推荐流程软件阶段、设置页的软件与驱动目录当前状态及编辑器当前目录区（调试模式开启时）使用持续、不可关闭且有完整文字的静态状态带，说明它已通过本机加载检查但未通过正式发布检查、只影响之后的新任务。调试工具区导入成功后在原位置立即显示；关闭调试模式时隐藏编辑和导入入口，但不隐藏本机试用身份。重新启动后按已保存的调试模式状态决定入口是否显示，无论入口是否显示都不隐藏本机试用身份。编辑器应用后焦点留在“应用”，调试工具区导入后焦点返回并留在触发导入的命令；只礼貌播报一次状态变化，不依赖颜色或图标，不使用绿色完成、勾选、Toast、音效、淡入、弹跳或庆祝动效，并在高对比度、4K、225% 显示缩放及常用文本缩放下保持可读。
- [ ] 需要额外提示的普通软件在卡片内就地显示简短提示，选中后在安装批次确认摘要中再次显示；两种视图均能看到必要风险，普通勾选不逐次弹出阻断式对话框。
- [ ] 来源解析失败时在当前软件卡片内就地呈现准确状态、“重新尝试”“查看原始地址”“选择其他来源”和返回后的“重新检测”；来源手动交接不显示应用内下载进度或完成动效，重新检测结果即时更新为“外部安装已识别”或原失败状态。识别成功后可以显示该软件自身的软件优化入口，但其他软件的依赖选择只在用户下一次触发规划后更新；外部安装标记保持可见，关闭或重启后恢复时直接呈现同一静态状态，不自动执行或播放完成反馈。
- [ ] 推荐流程中的外部安装识别成功后，就地显示“继续”并保持当前上下文；不自动跳转页面或播放完成转场，用户点击后才进入后续步骤，独立软件安装页不显示该流程命令。
- [ ] 外部安装识别成功本身不立即改变其他软件选择；用户点击“继续”或在独立软件页主动重新规划后，依赖已经满足的软件原位恢复为可选择且保持未勾选，仍受阻的软件显示准确原因，界面不播放完成动效，也不自动创建批次、下载或安装。
- [ ] 重新检测失败时原位保留失败原因，只显示“重新检测”和“暂时跳过”，没有“强制标记成功”；暂时跳过使用未完成状态的静态反馈，不播放成功动效，也不因切换高级视图增加绕过入口。
- [ ] 暂时跳过的软件持续显示在概览与推荐流程总结的未完成区段，可定位回软件卡片重新检测；正常关闭、异常退出、Windows 重启和发行形态切换后静态恢复，不自动检测、不弹出启动提醒或播放循环动效，识别成功后移出未完成区段但历史仍可查看。
- [ ] 软件自身提供的资源管理器右键扩展显示在对应软件优化方案中；Windows 自身的菜单和资源管理器样式只显示在系统优化页。
- [ ] 只有非首版必达项才能显示“暂不支持自动处理”；已安装且版本受支持的搜狗输入法为全部首版必达项提供正常可执行控件，缺少执行能力时显示实现错误而不是手动设置入口。
- [ ] 搜狗输入法两项安装阶段偏好在受支持安装程序中由工作台自动处理；安装后的全部已确认选项可逐项选择、执行和查看检测结果。
- [ ] 手动应急处理只在已实现的受控路径运行时失败或遇到未识别的新版本后出现，视觉上与成功状态明确区分，不能成为正常流程或首版完成证明。
- [ ] 软件优化的强制命令只在高级视图显示，标准视图保留完整原因、安全处理方式和无状态丢失的高级视图入口。
- [ ] 多软件正常优化只显示一次分组确认摘要，额外强制风险在触发前分别确认，不产生连续的普通确认弹窗。
- [ ] 收起“可以优化”提示不会永久隐藏方案或反复弹出，软件优化页继续提供明确状态和入口。
- [ ] 软件优化页只保留当前状态和最近结果，完整历史通过明确入口在“历史与日志”页定位查看。
- [ ] 主要流程支持鼠标、键盘、触摸和屏幕阅读器。
- [ ] 通过浅色、深色、高对比度、减少动画、减少透明度、4K、225% 显示缩放及常用文本缩放验收。
- [ ] 在集成显卡、独立显卡和混合图形设备下遵从 Windows 图形适配器选择，不提供手动 GPU 选择器；材质、Composition 和动效不可用或性能不足时回退为实体背景和静态反馈，功能、状态、无障碍和输入路径不降级。
- [ ] 建立按频率决定动效的统一规则：键盘触发、一级导航、连续勾选、进度数值和日志刷新即时完成，不播放页面、位移、缩放或弹簧动效。
- [ ] 指针按下优先使用 WinUI 3 原生反馈；只有自定义可点击表面允许约 83ms 的轻微缩放，键盘触发相同命令时不缩放。
- [ ] 建立全应用唯一的 0ms、83ms、167ms、250ms 语义动效资源和平台曲线；普通自定义动效不超过 250ms，退出通常短于进入，页面不得各自复制参数。
- [ ] 动效优先使用原生控件和 Theme animation/transition，必要时才使用 Composition；XAML 始终拥有布局、焦点、命中测试、控件语义和无障碍结构，Composition 只增强呈现而不建立第二套业务界面树。
- [ ] 普通路径不持续动画布局属性，也不让 Theme、Storyboard 与 Composition 争用同一视觉属性。
- [ ] Popover/Flyout 从触发位置建立空间关系，模态对话框保持居中，任何元素都不从零缩放出现；ConnectedAnimation 只用于真实共享对象，关闭冲突页面转场，并在启动失败时静态完成导航且不重试动画。
- [ ] 快速反向和重复触发从当前可见状态立即改向，不排队、不锁定输入；动画完成事件不提交业务状态、开始系统操作或决定结果。
- [ ] 集中监听 Windows 动画开关，系统运行中关闭动画后立即取消空间、缩放和弹簧动效；应用内设置不能覆盖系统关闭决定，静态焦点、状态、文字和无障碍反馈保持完整。
- [ ] Hover 只增强支持悬停的鼠标或笔，触摸与键盘不依赖 Hover 即可发现和完成同一功能；同一组相邻工具提示在首次提示后即时切换。
- [ ] 有效动效偏好允许时，流程完成只播放一次勾选与短淡入；系统关闭动画时直接显示最终勾选和结果文字；任何路径都不使用彩屑、烟花、弹跳、音效、循环或阻塞输入的庆祝。
- [ ] 自动检查覆盖集中时长、即时路径、减少动画、布局动画禁令、动效唯一所有者和完成事件边界；真实 WinUI 性能结果缺失时按开发者证据标为“未实机验证”，不冒充性能通过。
- [ ] 材质不叠加，文本不截断或重叠。
- [ ] Windows 10 22H2、系统材质能力或图形能力不可用时使用实体背景回退，不因缺少 Mica/Acrylic/视觉增强阻止功能。
- [ ] 字距保持 `0`，字号不随窗口宽度缩放。
