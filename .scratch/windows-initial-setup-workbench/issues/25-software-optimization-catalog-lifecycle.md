# 实现软件优化目录生命周期

Type: task  
Status: ready-for-agent  
Resolution: open
Blocked by: 01, 02
Owner: issue-25
Consumers: 18, 21, 26, 27, 28, 29
Verification: 软件优化目录的模式、生命周期、错误隔离、导入、回退及搜狗版本基线交集测试。
Evidence freshness: 绑定当前提交、模式与目录修订及支持的软件版本基线。

## Goal

加载、更新、调试模式手动导入和回退独立的软件优化目录，并以稳定身份和局部隔离规则承载受控软件优化方案。

## Acceptance Criteria

- [ ] 软件优化目录与软件和驱动目录、系统设置目录分别版本化、更新、调试模式手动导入和回退，发行版内置可离线加载的有效版本；普通和高级视图没有导入入口。
- [ ] 首版内置软件优化目录与软件目录共同满足搜狗稳定安装器及其安装结果版本的兼容基线；空支持范围或两类目录基线不相交时拒绝首版发布。
- [ ] 软件优化目录只包含目标软件描述和由目标软件提供或拥有的软件优化方案，不包含软件安装项、驱动入口或 Windows 自身的系统优化项；目标软件提供的资源管理器右键扩展仍属于该软件的优化。
- [ ] 目录自行携带目标软件稳定标识、安装检测、版本检测及可选的软件安装项关联，能识别非工作台安装的软件。
- [ ] 目录可以为非首版必达目标或超出声明支持版本的目标提供只用于识别、明确显示“暂无可用优化”的描述；已安装且版本受支持的首版必达目标缺少方案时属于实现错误，不得进入该区域。
- [ ] 每个方案和选项拥有不可变、不可复用的稳定标识，并声明适用软件版本、实际影响、风险、退出与重启要求、执行和状态检测规则。
- [ ] 目录可以为每个方案和选项保存可查看的说明来源；网页或文章变化不会直接改变执行规则，只有经过维护并加载新的目录版本后才生效。
- [ ] 非首版必达项暂时不能可靠自动处理时，可保留“暂不支持自动处理”说明、手动设置入口及来源，但不能形成自动执行步骤；首版必达项必须随目录提供有效的受控执行与检测定义，缺少任一能力即阻止首版发布。
- [ ] 目录可以为首版必达项声明运行时失败后的手动应急说明，但该说明不能替代受控执行定义，也不能使手动结果冒充工作台执行成功。
- [ ] 方案级和选项级必需关系、冲突关系可被结构化表达，并能进入批次快照和历史。
- [ ] 加载目录时可忽略未知展示或说明内容；未知模式版本或会改变目标、来源、依赖、受控能力、执行、检测、恢复、重启、撤回或其他操作语义的内容，连同缺少必需字段、无法解析或稳定标识冲突，均拒绝整包并保留上一份可用版本。
- [ ] 目标检测、依赖、冲突、执行或验证规则的局部错误只禁用相关方案，显示“目录配置错误”且没有强制执行入口。
- [ ] 没有有效目录时只禁用软件优化新操作，其他页面、历史、日志和已知紧急撤回信息继续可用。
- [ ] 恢复有效目录后重新识别目标和方案，不自动恢复旧选择或旧批次。
- [ ] 更新、调试模式手动导入或回退目录不会执行优化、改变当前软件配置或改写既有批次快照。
- [ ] 普通下架方案不能用于新执行；目录层保留既有批次继续所需的冻结数据以及历史和方案快照，不向执行器发出普通下架中断信号，实际继续执行由事项 27 负责。
- [ ] 调试模式手动导入先显示文件路径、目录版本和项目数量，并由用户确认后加载、拒绝或应用；所有结果如实记录。
- [ ] 调试模式手动导入只验证目录结构与内容规则，不提供签名或哈希来源证明；首版不提供软件优化目录编辑器，也不把自制软件优化目录列为正式支持能力。调试模式中的图形化软件目录编辑器只维护软件目录，不因此扩大到本事项的独立软件优化目录。
- [ ] 允许在调试模式导入较低版本；确认前列出将失去的新增或更新方案，并保留被替换版本用于回退。
