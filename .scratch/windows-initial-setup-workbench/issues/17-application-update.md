# 实现应用主动更新与失败回退

Type: task  
Status: needs-info  
Blocked by: 01, 02

## Goal

提供用户主动控制的 GitHub 应用更新，并在任何更新阶段失败时保留可用旧版本和设备状态。

## Acceptance Criteria

- [ ] 支持从 GitHub 手动下载和工作台内一键更新。
- [ ] 一键更新只列出正式稳定发行，排除 draft、预发布、beta、preview、nightly 和其他测试发行；工作台外的手动下载不受该筛选限制。
- [ ] 当前运行测试发行时，提供用户主动的“切换到最新稳定版”操作；不得因发现稳定发行而自动降级或替换。
- [ ] 一键更新和稳定版切换只选择同发行架构、同内容版、同便携版或安装版形态的正式稳定制品；缺少匹配制品时明确显示不能自动更新并提供 GitHub 手动下载入口，不自动切换制品。
- [ ] 当前正式稳定版只在可确认候选版本更高时更新；相同、较低或无法比较的版本不进入候选，工作台内不提供选择旧稳定版的入口。
- [ ] 新版本已经启动但无法进入工作台时，提供“重试新版本”和“恢复旧版本”的用户选择，不自动恢复；用户选择重试后再次无法进入工作台时自动恢复旧版本。两种选择都保留设备状态、执行历史和更新事实。
- [ ] 自动恢复旧版本后，旧版本仍无法进入工作台时，显示更新故障恢复界面，保留本机数据并提供手动下载和诊断资料；不重置本机数据，也不再自动下载、替换或覆盖任何版本。打开下载入口、下载或导出诊断资料不结束恢复状态，只有某个版本实际成功进入工作台后才结束。
- [ ] 更新故障恢复状态只在某个版本能正常使用工作台且原有记录仍可见后结束；应用窗口出现、打开下载入口、下载、导出诊断资料或用户主张“已恢复”均不算恢复成功。
- [ ] 更新故障恢复界面以静态错误状态列出失败版本、时间和当前未恢复状态，优先提供当前匹配的正式稳定制品及浏览全部 GitHub Release 的入口。无网络时仍显示可复制下载地址、故障摘要和诊断导出；只读历史与日志可用，初始化操作、设置修改、清理和再次启动已失败版本均不可用。
- [ ] 当前版本不是最新正式稳定发行时，明确提示仅支持最新正式稳定版并提供适用更新入口，但不阻止继续使用当前版本。
- [ ] 不后台静默下载、不强制替换应用。
- [ ] 更新前披露发行包未签名且项目不提供完整性校验信息。
- [ ] 下载、替换或新版启动失败时自动恢复上一版本。
- [ ] 更新和回退不改变恢复记录、执行历史、待恢复流程或有效紧急撤回信息；后者继续按跨软件安装、系统优化和软件优化的阻止规则生效。
- [ ] 更新结果和失败原因写入详细本机日志。
- [ ] 存在工作台拥有的活动安装批次、优化批次、系统设置执行，或其等待确认、等待重启、待恢复状态时，一键更新清楚显示为已延后，不下载、替换或中断当前任务，并提供返回当前任务入口；来源手动交接不构成此类阻塞。任务结束后不自动开始更新，仍等待用户再次主动触发。
