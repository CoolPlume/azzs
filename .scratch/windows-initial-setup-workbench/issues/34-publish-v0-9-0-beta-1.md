# 自动发布 v0.9.0-beta.1

Type: task
Status: ready-for-agent
Resolution: open
Blocked by: 21, 23, 30, 33
Owner: issue-34
Consumers: 35
Verification: 受保护 main 上的 GitHub Actions 权限、触发与幂等审查、八制品重建门禁及发布后 tag、prerelease、资产和说明核对。
Evidence freshness: 仅对 v0.9.0-beta.1 的目标提交、工作流修订和本次发布状态有效；本票不得复用于后续 beta。

## Goal

在公开仓库基线和早期只读 CI 已稳定后，为发布阶段增加最小写权限任务，并由发布流水线自动发布功能完整、八制品齐全的 `v0.9.0-beta.1`。

## Acceptance Criteria

- [ ] `v0.9.0-beta.1` 覆盖完整四阶段推荐初始化流程、全部一级页面、三类正式目录、全部首版必达能力、历史、恢复、应用更新、调试模式和目录编辑器，不把功能子集或空壳称为 beta。
- [ ] 标准版 x64/ARM64 便携版和机器级安装版、断网救援版 x64/ARM64 便携版、超大离线版 x64/ARM64 便携版共八个制品均由事项 21 的最终候选生成并通过全部自动门禁。
- [ ] 复用事项 01 已建立的早期只读 CI，不放宽其拉取请求、集成分支或普通构建权限；本事项只在发布工作流、固定工具与输入、权限和触发条件通过审查后增加最终发布任务，不能把 Actions 已启用或构建通过误记为 beta 已发布。
- [ ] 版本化 `v0.9.0-beta.1` 发布意图进入受保护的 `main` 后，由 GitHub 托管 Windows runner 从该提交自动重建候选并执行全部门禁；不使用公开仓库的 self-hosted runner，也不允许 pull request、fork 或其他不可信事件取得写权限或发布凭据。
- [ ] 工作流和构建检查默认使用只读权限；只有所有前置任务通过的最终发布任务取得最小 `contents: write`。发布任务核对版本、目标提交、既有 tag 和 Release，重复触发时保持幂等，版本冲突或半发布状态必须失败并保留诊断，不覆盖既有公开发行。
- [ ] GitHub Release 使用 `v0.9.0-beta.1` tag 并明确标记为 prerelease；应用内一键更新和稳定版候选筛选不会列出该发行。
- [ ] 公开仓库基线已经完成；本次 beta 不再逐次等待人工发布批准，流水线只在资产、发布说明和开发者发布证据完整且门禁全部通过时执行外部发布。
- [ ] 发布说明不把 beta 称为正式稳定发行、受支持版本、`1.0` 或已经完成实机、兼容性、来源、安全、身份、权利、签名、摘要或 provenance 验证。
- [ ] 开发者发布证据准确记录设计与实现、自动检查和真实设备证据；缺少实机证据时只在开发者证据中记录“未实机验证”。
- [ ] 发布后核对 tag、prerelease 标记、八个资产、名称、架构、下载可用性和公开说明；任何部分失败都保留可诊断结果，不把半发布状态写成成功。
- [ ] 若阻断缺陷需要后续 beta，另建对应版本的原子发布票；不得重用本票跨多个外部 Release。
