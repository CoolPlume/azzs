# 完成生产软件安装闭环

Type: task  
Status: ready-for-agent  
Resolution: open
Blocked by: 06, 08, 09, 19
Owner: issue-38
Consumers: 21
Verification: 在锁定提交、`release_state = "release"` 的软件目录维护文件、受控安装档案和来源观察事实下，以真实 Windows 11 x64 候选运行生产组合根，逐项记录来源解析结果、网络事实、存在检测、受控下载、安装档案启动与交互、安装后置行为、重启后的恢复和结果检测；假适配器、合同通知或仅构建结果不能满足本票据。
Evidence freshness: 证据只对精确候选提交、目录修订及发布状态、受控安装档案和解析能力版本、来源观察时间、外部安装资源版本、Windows build 与实际适配器实现有效；任一输入、来源事实或生产组合变化后，必须重新运行受影响的 Windows x64 闭环并记录未知或未执行项。

## Goal

把已有软件选择、软件目录、安装批次和批次控制的核心合同接入真实的生产软件安装能力，使发行前可以证明工作台从来源解析结果到安装结果确认的受控闭环实际可用。

## Boundary

事项 06、08、09、19 的 `Resolution: completed` 保留其已有的选择、状态机、目录与 x64 构建/合同层结论。它们不是生产来源解析、受控下载、真实安装器执行或结果检测已经完成的证明。

当前生产组合根中的 `UnavailableControlledSourceResolver`、`OfflineNetworkObserver`、`UnavailableSoftwarePresenceDetector` 和 `UnavailableControlledPackageDownloader` 是明确的 fail-closed 占位边界，不是生产能力。应用更新当前的 fail-closed 状态也不由本事项结票；事项 21 已通过其既有的事项 17 前置关系保留该独立发行门禁。

## Acceptance Criteria

- [ ] 生产组合根为软件安装路径注入真实的受控来源解析、网络观察、软件存在检测和受控下载适配器；发行配置不能再把四个 `Unavailable`/离线占位适配器当作可用能力。适配器暂时不可用、输入无效或事实未知时继续 fail-closed，并且不启动后续软件。
- [ ] 真实来源解析只消费软件目录维护文件声明的来源用途和原始地址，并为每个可执行项目生成完整、可追溯的来源解析结果：原始地址、来源用途、显示名称、来源解析方式、稳定版本、实际资源或托管机制、软件包架构、安装包类型、联网要求、解析时间和解析能力版本。无法可靠得到任一执行事实时，按“来源规则待实现”“暂时无法解析”“来源失效”“没有适用安装包”或“安装包信息待确认”停止当前项目；不得猜测地址、版本、架构或静默换源。
- [ ] 网络观察反映真实可用性，并把离线或连接中断与网络可用时的来源失效区分为“等待联网”和“来源失效”。网络事实变化只能按冻结的批次和重试规则创建新的来源解析结果或批次快照，不能改写历史快照。
- [ ] 软件存在检测以稳定、可审查的 Windows 事实识别目标软件及受控安装档案所需的版本或状态；用户声称已经手动安装、来源手动交接或仅有安装器进程退出都不能补造“已安装”或“安装成功”。检测未知时保留准确的未知或失败状态。
- [ ] 受控下载只取得来源解析结果或批次快照指定的实际资源，正确处理进度、取消、临时文件和软件包缓存边界；托管安装来源继续使用其官方机制且不伪装为可缓存文件。下载、缓存或网络异常不得把未完整资源交给安装档案，也不得接收用户在工作台外取得的安装文件。
- [ ] 每个可自动执行的安装器只在受控安装档案适用版本、交互处置和受控参数均已匹配时启动。未知安装器、未知参数、未知交互或不受支持的新版本不得退化为任意脚本、命令、点击或静默成功；已知交互仍按“受控自动处置 -> 工作台交互确认 -> 官方安装界面”逐级处置，账户与个人资料步骤只由用户在官方安装界面完成。
- [ ] 生产路径观察安装器首进程、受控安装档案声明的安装后置行为、已知重启要求和重启后的恢复；首进程退出不是完成边界。工作台只能在实际结果检测符合批次快照预期时记录“安装成功”并继续下一项。
- [ ] 结果或安装后置行为无法可靠判断时，当前项目进入“安装结果待确认”并暂停整个安装批次；记录已观察事实和用户选择，不得把确认写成自动检测成功。失败、停止、强制终止、关闭重开和重试仍保持事项 08、09 的串行、历史和恢复语义。
- [ ] 用于发行的目录修订通过发布级结构和能力校验并为 `release_state = "release"`；当前 `catalog/software-catalog.toml` 的 `release_state = "draft"`、未启用首版范围条目或缺失受控安装档案时，本事项保持 `Resolution: open`。本机试用目录、模拟目录或目录合同通过均不能替代此条件。
- [ ] 针对真实 Windows 11 x64 候选，以正式目录中每种实际来源解析/取得机制和每种受控安装档案完成代表性端到端验收，至少覆盖来源解析、网络中断或离线、存在检测、受控下载或托管取得、安装档案启动、交互回退、安装后置行为、结果检测以及“安装结果待确认”的 fail-closed 暂停。原始日志、候选、目录、安装档案、来源观察事实与逐项结果可追溯；未执行的来源、软件、安装器版本、重启或设备场景明确标为未验证。
- [ ] 事项 06、08、09、19 的假适配器、状态机合同、目录模式检查、GitHub CI、x64 构建或 mock 通知继续作为基础回归证据，但不单独解除本票据或事项 21 的阻断。只有本票据的生产闭环验证通过后，事项 21 才可把相关软件安装能力计入发行门禁。
