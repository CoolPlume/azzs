# 实现软件优化批次执行器

Type: task  
Status: ready-for-agent  
Blocked by: 02, 09, 25, 26, 28

## Goal

按冻结方案串行执行一个或多个软件优化，提供验证、停止、失败重试、暂停状态交接及完整执行记录，而不自动撤销已经完成的修改。

## Acceptance Criteria

- [ ] 执行一个方案也创建独立优化批次，不绕过快照、安全检查、历史或恢复规则。
- [ ] 批次冻结目标软件版本、方案和选项标识、实际选择、执行与检测规则、关闭和重启要求。
- [ ] 多软件按确定顺序串行执行；单项失败不阻断没有依赖关系的后续方案，优化失败不改写软件安装结果。
- [ ] 目录校验、规划等无副作用 CPU 密集型辅助工作可以受限并行，但不得并行修改多个软件、启动第二个管理员操作、越过优化批次占用或并发提交优化结果与恢复事实。
- [ ] 软件安装批次与优化批次在同一设备的所有实例间互斥；现有批次执行、等待确认、等待重启或待恢复时显示当前进度入口而不启动新批次。
- [ ] 执行方式按官方设置方式、软件自身配置修改、设置界面自动操作的优先顺序选择，只执行目录预定义内容。
- [ ] 批次只修改由目标软件提供或拥有的行为，包括该软件提供的资源管理器右键扩展；Windows 自身的菜单或资源管理器样式必须交给系统优化，不能在此重复执行。
- [ ] 非首版必达项标记为“暂不支持自动处理”时不会作为自动步骤进入批次；首版必达项缺少受控执行器或检测器属于实现错误并阻止首版发布，不能用手动入口绕过。
- [ ] 首版必达项的受控路径在运行时失败后可以提供手动应急处理，但原步骤保持“优化失败”“版本不适用”或“优化结果待确认”等真实状态，不能伪装成工作台自动执行成功。
- [ ] 优化批次开始后，软件优化目录的普通更新、回退或方案下架不改变冻结快照及后续执行；只有紧急撤回可以阻止尚未开始的相关步骤。
- [ ] 每次执行、重试或恢复新修改前应用当前有效紧急撤回信息，被阻止步骤保持未执行并记录原因。
- [ ] 目标软件退出、强制关闭、版本强制执行和批次确认按页面形成的执行计划处理；无法确认软件退出时不修改配置，所有额外风险分别确认。
- [ ] 强制执行保存实际软件版本、方案适用软件版本、风险提示版本和用户确认结果，并明确区别于正常执行。
- [ ] 每个选项执行后验证目标状态；确认达到目标才显示“已优化”，无法判断时进入“优化结果待确认”。
- [ ] 用户对待确认结果可打开目标软件检查后选择“已完成”；只有按当前状态重新判断仍可执行时才提供“重试”。确认重试后先记录选择和原批次剩余状态、结束原批次并释放占用，再创建新批次；下架、撤回或其他阻止原因就地显示。
- [ ] 中途失败保留已完成修改，逐项区分已优化、优化失败和未执行，不提供自动恢复。
- [ ] 重试按当前目录、目标软件版本与状态、选项关系和紧急撤回信息创建新批次；下架或撤回方案不能重试。
- [ ] 需要重启时产出并持久化“等待重启”状态，交接给事项 12 建立统一重启屏障；本事项不实现重开后的恢复、重检或取消流程。
- [ ] “停止优化”等待当前步骤安全结束后停止后续内容；高级视图的“强制终止优化”披露不完整配置风险。
- [ ] 正常关闭先等待当前步骤到达安全结束点，并把后续步骤保持为待处理而不是“未执行”；异常退出导致结果未知时留下可供事项 12 恢复为“优化结果待确认”的状态，不直接重跑。
- [ ] 持久化结果足以让事项 12 在重新打开后保持暂停，并按“取消只放弃未执行步骤、已完成修改不恢复、原批次保留只读历史”的规则处理；本事项不实现重开或取消入口。
- [ ] 执行记录保存方案和选项快照、逐项结果、强制操作、确认方式、停止、正常关闭暂停、异常退出、最后已持久化步骤及重启交接状态；取消和恢复后的重新检测结果由事项 12 补充。
