## Goal

建立便携版与安装版共享、可跨应用和 Windows 重启保存的设备级状态及详细本机日志。

## Acceptance Criteria

- [ ] 恢复记录、推荐流程记录、批次进度和必要设备状态保存在设备级位置。
- [ ] 已经保存但尚未应用的目录编辑草稿在“保存草稿”成功时即写入设备级位置；正常关闭、异常退出或电脑断电后重新打开，恢复该已保存版本为“已保存未应用”，可继续编辑、明确应用或删除且绝不自动应用。删除草稿不改变当前有效目录、既有批次或历史。
- [ ] 工作台异常退出或电脑断电后，下次启动应尽量找回目录编辑器尚未保存的修改；成功找回的内容明确标为“恢复的未保存修改”，仍属于未保存状态，绝不自动保存或应用。恢复的未保存修改、已保存未应用草稿与当前有效目录分别建模，找回过程不得覆盖或损坏已保存版本；恢复后的应用请求继续被拒绝，显式保存成功后才转为“已保存未应用”并清除对应恢复状态，放弃只移除恢复的未保存部分，不影响此前草稿、当前目录、既有批次或历史。恢复失败不得把内容标为已找回；启动时只显示不阻断的持续“继续编辑”入口，不自动打开编辑器。
- [ ] 来源手动交接记录保存在设备级位置，跨正常关闭、异常退出、Windows 重启及便携版与安装版切换继续可用；恢复原始地址、交接记录、最近检测结果和“重新检测”，已经识别成功时保留“外部安装已识别”，暂时跳过且尚未成功时继续列入未完成列表并保留原失败原因。推荐流程已识别但尚未继续时恢复“继续”入口，不自动访问地址、下载、安装、检测或继续流程。
- [ ] 优化批次、已完成优化状态和有效紧急撤回信息保存在设备级位置，并由便携版与安装版共享。
- [ ] 便携版、安装版和应用版本切换后可读取同一份状态。
- [ ] 同一设备上的不同工作台实例共享当前安装或优化批次的占用状态；现有批次完成、停止结束或取消前，其他实例不能启动另一批次。
- [ ] 日志仅保存在本机，默认永久保留且不自动上传。
- [ ] 日志记录时间、结果、退出码及来源、版本、架构、优化方案与选项、强制操作和确认方式等必要上下文；安装器交互还记录交互项类别、自动处置、工作台确认或官方界面处理的层级、预期选择、可观察结果、用户确认和回退原因。账户与个人资料步骤只记录官方界面交接和可观察结果，不记录口令、验证码、付款、令牌、Cookie、表单内容或其他个人资料。
- [ ] 结构化日志保留稳定事件顺序、关联标识、构建与已脱敏环境摘要、原始错误和最后可信状态，并能明确表示所有已知或可检测的事件丢弃、截断、异常退出、平台未提供和最后落盘后的未知区间，为单文件异机诊断提供可判断覆盖边界的输入。
- [ ] 系统优化记录区分从“推荐总体优化”选中与单独选中的设置，并保存实际执行的设置稳定标识、Windows 版本与内部版本号、已知适用范围、超范围尝试确认、资源管理器重启选择与结果及恢复数据状态。
- [ ] 日志可导出和清空；清空不影响来源手动交接记录、恢复记录、安装或优化历史、待恢复状态及有效紧急撤回信息。
- [ ] 首版不采集或发送使用遥测，执行日志不会被当作遥测上传。
- [ ] 状态存储异常有明确错误并且不会静默破坏已有记录。
- [ ] 当前权威状态与最后可信代次都无法通过校验时进入显式不可修改的状态损坏恢复模式；不得创建空状态、继续初始化或发起任何设备修改。原始字节、事务残留和诊断事实继续保留，只允许诊断导出、读取仍可恢复的历史，以及在逐类说明数据影响后由用户明确确认重新初始化。
- [ ] 重新初始化形成新的权威代次，并把受影响数据类别与确认事实写入诊断记录；损坏内容不得被标为已恢复，仍可读取的历史不得因重新初始化而被改写或伪造。
- [ ] 无界面持久化故障注入覆盖当前代次与最后可信代次同时损坏、残留临时写入或替换事务、只读恢复能力、诊断证据保留、所有修改意图被拒绝及明确重新初始化出口。
