# 实现串行软件安装批次

Type: task  
Status: ready-for-agent  
Blocked by: 02, 06, 07

## Goal

以不可变快照和确定顺序执行软件安装，并让单项异常不破坏无关项目。

## Acceptance Criteria

- [ ] 创建批次时消费软件选择能力提供的来源解析结果，再冻结目录、依赖、来源类型、链接或托管机制、版本、架构及用户选择的安装阶段选项；批次执行器不另建第二套解析逻辑。
- [ ] 可下载文件来源由工作台在应用内下载批次快照指定的安装文件，显示进度且不以打开浏览器代替下载。
- [ ] 下载期间可以切换页面；下载完成后启动当前安装程序，并等待当前项目处理完成再进入下一项，不预下载后续软件。
- [ ] 托管安装来源调用其官方机制，可靠呈现可用进度且不伪造下载数值或软件包缓存。
- [ ] 下载进度显示已下载量与总大小、当前速度和预计剩余时间；无法可靠计算的值显示“正在计算”，数值更新不引发布局跳动。
- [ ] 当前下载项显示同步进度条；总大小未知时使用不确定状态，取得总大小后切换为确定进度；状态可被屏幕阅读器识别且频繁更新不会持续干扰。
- [ ] 多软件批次显示按项目数计算的整批进度条、“已处理数量 / 总数量”和当前软件；失败、跳过与等待状态正确计入已处理数量。
- [ ] 同时支持目录声明的交互式安装与静默安装，不支持静默的软件仍可打开官方安装界面。
- [ ] 对目录声明支持的安装阶段选项按冻结选择执行；首版必达偏好缺少执行器时判定为实现错误并阻止发布。已有执行器本次失败时暂停并提供重试及准确的手动应急清单，不将手动操作记成自动完成。
- [ ] 标准视图按目录声明默认静默安装；高级视图的交互式选择和需要必要选择的软件得到正确执行。
- [ ] 静默安装失败时记录失败，提供静默重试和打开官方安装程序，不自动弹出安装界面且不阻断无关后续软件。
- [ ] 安装程序结束后按目录规则自动检测结果；确认成功后继续，确认失败时记录失败，无法判断时暂停为“安装结果待确认”。
- [ ] “安装结果待确认”提供“已完成”和“重试”，用户选择及时间写入历史与日志且不冒充自动检测成功。
- [ ] 确认安装完成后保存可供软件优化发现能力消费的安装结果并触发重新识别；本事项不自行判断优化资格。
- [ ] 安装批次不弹出优化对话框，也不因后续优化提示或结果改写安装完成状态；具体资格判断与非阻塞提示由事项 26 负责。
- [ ] 软件按确定顺序串行执行，不并行启动安装程序。
- [ ] 已安装软件默认跳过，且不被误标为最新版。
- [ ] 安装失败、等待联网、来源失效或依赖阻塞使用明确状态。
- [ ] 官网解析失败时只暂停当前软件，不自动换源或把旧直链作为当前最新版执行。
- [ ] 单项失败不终止无依赖关系的后续项目。
- [ ] 重试生成新的单项批次快照，不改写原历史。
