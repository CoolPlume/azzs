## Goal

以不可变快照和确定顺序执行软件安装，并让单项异常不破坏无关项目。

## Acceptance Criteria

- [x] 创建批次时消费软件选择能力提供的来源解析结果，再冻结目录内容、模式版本、修订、`release_state`、本机试用标记、本次目录应用关联标识、依赖、原始地址、来源用途、解析方式、实际资源或托管机制、版本、架构、安装包类型、联网要求、解析时间、解析能力版本及用户选择的安装阶段选项和安装器交互处置；`draft` 同一修订可继续变化，批次执行器不能只凭修订号重读目录或另建第二套解析逻辑。
- [x] 可下载文件来源由工作台在应用内下载批次快照指定的安装文件，显示进度且不以打开浏览器代替下载。
- [x] 下载期间可以切换页面；下载完成后启动当前安装程序，并等待当前项目处理完成再进入下一项，不预下载后续软件。
- [x] 托管安装来源调用其官方机制，可靠呈现可用进度且不伪造下载数值或软件包缓存。
- [x] 下载进度显示已下载量与总大小、当前速度和预计剩余时间；无法可靠计算的值显示“正在计算”，数值更新不引发布局跳动。
- [x] 当前下载项显示同步进度条；总大小未知时使用不确定状态，取得总大小后切换为确定进度；状态可被屏幕阅读器识别且频繁更新不会持续干扰。
- [x] 多软件批次显示按项目数计算的整批进度条、“已处理数量 / 总数量”和当前软件；失败、跳过与等待状态正确计入已处理数量。
- [x] 同时支持目录声明的交互式安装与静默安装；对受控安装档案已知且可可靠识别的条款、隐私和附加推广交互项优先自动处置，不能自动处置时依次退到工作台内明确确认和官方安装界面；已知可靠的附加推广默认拒绝。登录、注册、验证码、付款和个人资料步骤不进入自动处置或工作台确认，始终由用户在官方安装界面完成，工作台不读取、代填、传递或保存内容，不能把任意页面操作当成受控自动化。用户未完成这些步骤时当前软件项为“安装器交互待处理”，只提供重新尝试或停止批次，不启动下一项；该状态跨关闭和 Windows 重启保留，下次打开不自动打开官方界面或继续批次。
- [x] 对目录声明支持的安装阶段选项按冻结选择执行；首版必达偏好缺少档案或受控处置路径时判定为实现错误并阻止发布。自动处置运行时失败时暂停当前交互项，依次使用工作台确认和官方界面回退，不将任何回退记成自动完成、安装结果待确认或手动应急处理。
- [x] 标准视图按目录声明默认静默安装；高级视图的交互式选择和需要必要选择的软件得到正确执行。
- [x] 静默安装失败时记录失败，提供静默重试和打开官方安装程序，不自动弹出安装界面且不阻断无关后续软件。
- [x] 工作台已经启动的批次安装程序达到受控安装档案声明的完成边界后按目录规则自动检测结果；首进程退出不等于完成。确认成功后继续，确认失败时记录失败，结果或安装后置行为无法判断时暂停为“安装结果待确认”。
- [x] “安装结果待确认”只用于上述批次安装器，提供“已完成”和“重试”；根进程退出但后置行为未知时同样进入该状态，暂停期间不得启动下一项。用户选择、已观察到的完成事实及时间写入历史与日志且不冒充自动检测成功；来源手动交接不得进入或复用该状态。
- [x] 确认安装完成后保存可供软件优化发现能力消费的安装结果并触发重新识别；本事项不自行判断优化资格。
- [x] 安装批次不弹出优化对话框，也不因后续优化提示或结果改写安装完成状态；具体资格判断与非阻塞提示由事项 26 负责。
- [x] 软件按确定顺序串行执行，不并行启动安装程序。
- [x] 目录校验、规划等无副作用 CPU 密集型辅助工作可以受限并行，但不得借此预下载、并行启动安装器、提前处理下一项、绕过当前项目完成边界或突破跨实例的受控操作占用。
- [x] 批次创建后即使维护者保存或应用新的目录编辑草稿、关闭调试模式或用另一目录替换本机试用目录，执行中、暂停、等待确认、等待重启或待恢复的批次仍使用创建时快照及其中冻结的目录发布状态和本机试用标记，不取消、重排、补项或改写历史；新目录只供之后主动规划并新建的批次使用。
- [x] 已安装软件默认跳过，且不被误标为最新版；“外部安装已识别”在新一轮依赖与批次规划中同样证明软件存在，但不改变其外部安装标记或既有历史。
- [x] 安装失败、等待联网、来源失效或依赖阻塞使用明确状态。
- [x] 地址解析失败时只暂停当前软件并保留准确原因，不自动换源、猜测候选文件或把旧直链作为当前最新版执行。
- [x] 来源手动交接不进入批次执行器：未解析项目不会形成安装批次项目，用户从原始地址取得的文件不会被工作台接收、缓存或启动，也不能用于补造来源解析结果或安装批次快照；交接和重新检测由软件选择或推荐流程负责，既有安装批次历史保持不变。
- [x] 来源手动交接重新检测失败后的“暂时跳过”不能作为软件存在事实或成功结果进入依赖与批次规划；依赖该软件的项目保持阻塞，无依赖关系的项目继续遵守单项异常不破坏其余项目的规则。
- [x] 暂时跳过的软件后来识别成功时只更新存在事实；用户下一次主动发起依赖规划后，才按当前目录和设备状态重新计算。新满足依赖的软件恢复为可选择状态并保持未勾选，不复用旧快照，也不自动创建批次、下载或安装。
- [x] 直链、跳转、普通网页、GitHub 和托管来源均先由唯一来源解析能力产出完整结果；批次执行器只消费冻结结果，不重新读取软件目录维护文件、访问网页或判断 URL。
- [x] 单项失败不终止无依赖关系的后续项目。
- [x] 重试生成新的单项批次快照，不改写原历史。
