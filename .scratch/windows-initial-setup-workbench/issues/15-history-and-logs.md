# 实现历史与日志页面

Type: task  
Status: ready-for-agent  
Blocked by: 02, 08, 11, 12, 24, 27, 28

## Goal

让用户查看不可变执行历史、逐项状态和详细本机日志，并能导出诊断资料。

## Acceptance Criteria

- [ ] 分别展示推荐流程记录、软件安装批次、软件优化批次、系统优化操作、取消记录及目录、来源、方案和版本快照。
- [ ] 系统优化历史区分“推荐总体优化”选择来源与单项选择，最终始终列出实际执行的设置及逐项结果、原值恢复记录和撤销结果。
- [ ] 对带 Windows 适用范围的设置，历史与日志保存实际 Windows 版本及内部版本号、目录声明的已知范围、超范围尝试确认、资源管理器重启选择与验证结果。
- [ ] 历史逐项显示规格定义的统一状态和必要原因。
- [ ] 已取消批次、下架设置和目录移除项保留只读历史。
- [ ] 重试创建新记录，不覆盖原记录。
- [ ] 自动检测确认与用户确认的安装和优化结果均可区分；安装器交互还区分受控自动处置、工作台交互确认和官方界面处理，记录预期选择、可观察结果、用户确认和回退原因，且不与安装结果待确认混用。账户与个人资料步骤只记录官方界面交接和可观察结果，不记录其输入内容。安装结果待确认还记录已观察到的完成事实和安装后置行为未知原因，两类“结果待确认”的用户选择作为不可改写记录保留。
- [ ] 来源手动交接作为软件选择或推荐流程记录，保留软件稳定标识、原解析失败原因、打开的原始地址、交接时间、每次重新检测的时间和结果、用户选择“暂时跳过”的时间、当前是否仍列入未完成列表，以及推荐流程中用户点击“继续”的时间；后来识别成功只更新当前状态，不删除既有交接历史。它不创建安装批次，“外部安装已识别”与工作台完成的安装使用不同状态，日志不虚构未观察到的下载或安装过程。
- [ ] 优化历史完整展示强制执行、强制关闭、强制终止、停止、取消、重启交接、自动或用户确认、失败、普通下架和紧急撤回，且可由软件优化页的最近结果直接定位。
- [ ] 正常关闭暂停与异常退出分别记录；异常退出记录最后已持久化步骤、结果未知状态和恢复后的重新检测结果。
- [ ] 支持查看、导出和清空详细日志。
- [ ] 调试模式使用最高可用粒度记录命令、状态转换、目录校验、来源解析、依赖规划、下载、缓存、安装程序、安装器交互项与处置层级、完成边界、安装后置行为、结果检测、恢复、适配器结果、耗时、重试、更新延后原因和关联标识；已取得的具体原因不得退化为笼统失败。
- [ ] 调试日志在写入前脱敏口令、令牌、Cookie、授权头、计算机名、用户名、唯一设备标识、MAC/IP、SSID、用户目录名称和地址或路径中的凭据，不记录无关文件内容，不自动上传；设置页可打开日志位置和导出诊断资料，关闭调试模式后恢复普通粒度但不删除既有日志。非唯一硬件型号、驱动版本、网络状态和规范化路径等允许诊断字段继续保留。
- [ ] 一次诊断导出形成一个版本化、自包含且已脱敏的文件；未接触测试机的开发者只查看该文件即可确认工作台构建、Windows 与相关硬件驱动环境、当前有效目录的模式、修订、`release_state`、本机试用标记、最近目录应用关联标识与加载和发布结果、相关批次冻结的目录身份、用户命令与状态顺序、失败组件和阶段、原始错误、重试及最后可信状态，不依赖远程访问、截图、口述步骤或另一份环境清单。
- [ ] 导出文件明确标记调试覆盖范围、事件序号、最后落盘点、异常结束、所有已知或可检测的丢弃、截断、刷新失败、平台未提供或脱敏缺口，以及最后落盘后的未知区间；采集不完整时仍可导出，但不能把缺失事实显示成正常或完整。
- [ ] 清空日志不影响来源手动交接记录、恢复记录、安装或优化历史、已生效设置、已完成优化、待恢复流程或有效紧急撤回信息。
- [ ] 日志、历史和恢复记录使用独立聚合；并发清空先提交截止事件并切换到新日志段，空间不足时停止非关键日志并记录可检测缺口，绝不自动删除历史或恢复记录。
