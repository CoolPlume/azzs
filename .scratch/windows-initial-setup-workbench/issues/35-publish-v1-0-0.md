# 发布 GitHub v1.0.0 正式版本

Type: task
Status: needs-info
Resolution: open
Blocked by: 21, 23, 30, 33, 34
Owner: issue-35
Consumers: none
Verification: 对 v1 候选重跑八制品和全部门禁，核对反馈 triage、阻断缺陷与独立授权，并在发布后检查稳定 Release。
Evidence freshness: 仅对获授权的 v1.0.0 目标提交、工作流修订、反馈快照和本次八制品有效；beta 旧结果不得复用。

## Goal

在 beta 结果门槛满足并取得维护者独立发布授权后，把最终八个制品作为 GitHub `v1.0.0` 正式稳定发行发布。

## Information Needed

- 维护者在最终候选、发布说明、开发者发布证据和 beta 反馈摘要可检查后明确授权发布 `v1.0.0`。

## Acceptance Criteria

- [ ] 不使用固定观察天数；截至最终候选的全部已收反馈完成 triage，所有已知发布阻断缺陷关闭或经修复后重新验证。
- [ ] 没有收到反馈不被记录为实机验证、兼容性验证或用户验收通过；真实设备证据缺失时继续按 ADR-0034 记录“未实机验证”。
- [ ] 八个最终制品和全部自动门禁基于拟发布提交重新通过，未直接复用 beta 的旧结果或资产。
- [ ] 维护者对 `v1.0.0` 的独立发布授权已追加到 `## Comments`；首次公开仓库授权或 beta 自动发布策略不能替代本次授权。
- [ ] 复用已经审查的 GitHub Actions 发布路径时，只有上述独立授权记录存在后才能触发正式发布任务；beta 的自动触发条件不得创建、替换或提升 `v1.0.0` Release。
- [ ] GitHub 使用 `v1.0.0` tag 创建非 prerelease 的正式 Release，上传八个最终资产和对应发布说明、限制与风险披露。
- [ ] 发布后核对 tag、稳定状态、八个资产、名称、架构、下载可用性和公开说明；一键更新只在严格版本与匹配制品规则满足时识别该正式稳定发行。
- [ ] 事项 22 的实机证据可以在发布前或发布后补充；未完成时不阻断发布，也不进入普通界面或面向用户的 GitHub 发布说明。
