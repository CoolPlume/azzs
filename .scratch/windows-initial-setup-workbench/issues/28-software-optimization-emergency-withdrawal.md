# 实现跨类别紧急撤回通知

Type: task  
Status: ready-for-agent  
Blocked by: 02, 25

## Goal

独立检查、保存和应用项目发布的紧急撤回通知，在不静默更新普通目录的前提下阻止已知严重风险、尚未开始的软件安装、系统优化和软件优化操作。

## Acceptance Criteria

- [ ] 联网启动后及每次创建、执行、重试或恢复软件安装、系统优化或软件优化前自动检查紧急撤回通知。
- [ ] 检查只更新安全阻止信息，不加载应用或三类目录的普通更新，也不发送使用遥测。
- [ ] 通知包含修订号、发布时间、受影响操作的稳定标识和类别、受影响版本范围、原因及撤回或解除状态。
- [ ] 相同或更旧修订不能覆盖设备已接受的较新结果；只有更新修订可以调整或解除撤回。
- [ ] 有效紧急撤回信息保存在设备级位置，由便携版与安装版共享。
- [ ] 目录更新、导入、回退、应用更新和日志清理不会清除有效紧急撤回信息。
- [ ] 离线或检查失败时沿用上次结果，显示通知时间并提示可能过期；首次失败且没有本地结果时，允许新的软件安装、系统优化和软件优化操作，但持续显示“未能检查最新紧急撤回信息”，不得伪称检查成功。
- [ ] 已知紧急撤回的受影响操作不能新执行；该规则优先于普通下架和批次快照，并对运行中、暂停中或等待重启的既有批次阻止尚未开始步骤。已经开始或完成的操作结果、恢复记录和历史继续保留，工作台不得自动终止、撤销或把保留记录表述为仍可安全继续。
- [ ] 撤回可以覆盖软件安装、目标软件拥有的普通配置和资源管理器右键扩展步骤，以及 Windows 自身的系统优化步骤；操作类别由目录稳定标识与通知共同确定，不按页面归属猜测。
- [ ] 向页面、流程总结、历史和日志提供结构化的撤回原因、受影响内容、通知修订和处理结果；具体呈现分别由软件选择、系统优化、软件优化、流程和历史事项负责。
