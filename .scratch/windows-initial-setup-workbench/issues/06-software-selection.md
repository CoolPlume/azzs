# 实现软件选择、来源与版本界面

Type: task  
Status: ready-for-agent  
Resolution: open
Blocked by: 03, 05, 24
Owner: issue-06
Consumers: 08
Verification: 来源解析、依赖闭包、手动交接与双视图一致性的核心和 UI 合同测试及失败负例。
Evidence freshness: 绑定当前提交、目录修订、解析能力版本；外部来源事实带 observed_at，并在新规划时重验。

## Goal

让用户在软件页清楚选择基础软件、普通软件、安装来源和稳定版本。

## Acceptance Criteria

- [ ] 基础软件和普通软件分区展示，基础软件默认勾选。
- [ ] 取消基础软件时提示影响；存在已选依赖时阻止取消并说明原因。
- [ ] 选择存在未选必需依赖的软件时，一次列出全部新增必需依赖并等待用户明确确认；拒绝后不选择原软件或新增依赖，不得静默补选。
- [ ] 每个软件提供“安装最新版”，来源可用时展示部分历史稳定版。
- [ ] 官网发布页作为来源时，“安装最新版”显示在线解析所得的当前稳定版本，不依赖目录中长期写死的安装文件直链。
- [ ] 维护者只填写来源用途和原始地址；工作台自动识别直链、跳转、普通网页、GitHub 或托管来源，并在需要时使用对应软件或站点的受控解析能力取得实际版本和安装文件。
- [ ] 在创建批次前通过唯一的来源解析能力产出原始地址、来源用途、解析方式、版本、实际地址或托管机制、架构、安装包类型、联网要求、解析时间和解析能力版本，供界面显示并交给批次冻结。
- [ ] 来源显示名称由解析能力从提供方或仓库信息确定性生成，缺少时回退到本地化用途与主机名，重名时追加仓库或短路径；维护者不需要填写地址技术类型或显示名称。
- [ ] 来源无法解析时提供重新尝试、查看原始地址和选择已列出其他来源的入口，不静默切换来源；按原因区分“来源规则待实现”“暂时无法解析”“来源失效”“没有适用安装包”和“安装包信息待确认”。
- [ ] 用户选择“查看原始地址”后，界面明确说明浏览器可能显示页面或直接开始下载，下载和运行由用户在工作台外完成，并提供返回后的“重新检测”；不提供安装文件拖放、文件选择、缓存导入或代为启动入口。
- [ ] 重新检测到目标软件时显示“外部安装已识别”，不显示为工作台下载安装成功，也不宣称已经确认最新版、来源或架构；未检测到时保留原解析失败状态和可用处理入口。
- [ ] 重新检测仍未发现目标软件时只提供“重新检测”和“暂时跳过”，即使用户确认已经安装也不提供强制标记成功或“安装结果待确认”；暂时跳过不满足依赖、不进入软件优化发现，也不产生安装成功记录。
- [ ] 暂时跳过且仍未识别的软件持续显示在设备级未完成列表，保留未完成原因、最近检测结果和“重新检测”；关闭、重启或切换便携版与安装版后仍可使用，恢复时不自动检测，后来识别成功才改为“外部安装已识别”并移出未完成状态。
- [ ] 未完成软件后来由用户主动检测成功时先更新其存在事实，并在用户下一次触发依赖规划时重新评估此前受其阻塞的软件；推荐流程只在用户点击“继续”后规划。当前依赖已经全部满足的软件恢复为可选择状态并保持未勾选，仍有其他依赖缺失的保留阻塞原因，任何项目都不自动创建批次、下载或安装。
- [ ] “外部安装已识别”满足只要求软件存在的依赖判断；需要具体版本等额外条件时重新检测，外部安装标记和原交接记录始终保留。
- [ ] 来源手动交接由软件选择状态或推荐流程记录，至少保留软件稳定标识、原解析失败原因、打开的原始地址、交接时间，以及每次重新检测的时间和结果；不为未解析项目创建安装批次，重新检测结果不会改写既有安装批次历史。
- [ ] 关闭或重启后恢复来源手动交接时，软件卡片继续显示原始地址、最近状态和“重新检测”：已经识别成功时保留“外部安装已识别”，尚未成功时保留原失败原因；恢复本身不访问来源、不执行检测，也不改变软件状态。
- [ ] 来源手动交接位于推荐流程时，识别成功后显示“继续”而不自动进入后续步骤；独立软件安装页只更新软件状态，不显示不存在的流程续接操作。
- [ ] 官网同时提供完整安装包和在线安装器时默认选择完整安装包；只有在线安装器可用时明确提示安装过程需要联网。
- [ ] 安装前在标准视图显示解析所得的版本、官网来源和联网要求；高级视图增加架构、安装包类型和实际下载地址。
- [ ] 标准视图与高级视图显示相同的软件安装项、分类、可选择状态和勾选结果；切换视图不得增加、隐藏或禁止选择软件，高级视图只增加同一软件项的细节和低频控制。
- [ ] 图形化目录编辑器保存目录编辑草稿时，本页继续显示当前有效目录且选择不变；只有“应用”成功后才按新当前有效目录刷新软件列表和之后的规划，不把未应用草稿当成可选软件来源。新当前有效目录属于本机试用目录时，软件页在标准视图和高级视图持续显示“正在使用本机试用目录”及未发布影响，关闭调试模式或重新启动后仍显示，直至另一份有效目录明确替换。
- [ ] 当前有效软件目录变化影响尚未创建批次的既有选择时，保留选择并逐项说明原因，要求用户移除、重新选择或选择其他当前可用项；不得静默移除、沿用旧目录执行或自动创建批次。
- [ ] 需要额外提示的普通软件仍在两种视图的共用清单中可选并默认不勾选；卡片就地显示简短提示，选中后在安装批次确认摘要中再次显示，不在每次勾选时弹出阻断式对话框。
- [ ] Game Cheats Manager、Cheat Engine、Office Tool Plus、Internet Download Manager 和几何画板遵守上述展示规则。
- [ ] 每个软件只在精选目录指定的发行分支内选择最新版，不因其他产品分支版本号更高而切换。
- [ ] 支持静默安装的软件在标准视图默认静默安装，高级视图可改为交互式安装；需要必要选择的软件默认交互式安装。
- [ ] 软件存在安装阶段选项时，在创建批次前逐项显示其效果和默认选择；这些选项与安装后的软件优化明确分开。
- [ ] 首版必达安装阶段偏好必须声明正常受控执行能力，缺少能力时显示实现错误并阻止发布；已经具备能力但本次运行失败时才显示官方安装程序中的手动应急步骤，且不伪装成自动完成。
- [ ] 不展示 beta、preview 或 nightly 版本。
- [ ] 来源名称、链接、优先级和离线可用性可见并可按软件选择。
- [ ] 项目第三方包源只作为用户明确选择的备用来源。
- [ ] 软件目录维护文件可以把任意受支持形式的 GitHub 地址声明为 `project_backup`；工作台自动识别具体处理方式，但仍遵守主动选择的备用来源规则，五个需要额外提示的普通软件也可按目录与制品清单配置该来源。
- [ ] 断网或连接中断显示“等待联网”，网络正常但页面、发布数据或资源无效才显示“来源失效”。
- [ ] 标准视图突出推荐来源与最新版；高级视图可展示来源、历史稳定版和架构等详细控制，且不改变安全规则。
