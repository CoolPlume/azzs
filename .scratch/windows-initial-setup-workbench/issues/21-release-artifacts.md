## Goal

生成可通过 GitHub Releases 发布、无需目标系统预装运行时的全部首版发行制品。

## Acceptance Criteria

- [ ] 标准版提供 x64 与 ARM64 的便携版和机器级安装版；机器级安装版通过 UAC 安装到整台设备，不提供用户级或双作用域安装模式。断网救援版与超大离线版各只提供 x64 与 ARM64 的便携版，共八个制品。
- [ ] 提供标准版、断网救援版和超大离线版；标准版只携带工作台运行时，断网救援版增加受控制品边界允许的救援伴随工具，超大离线版再按构建清单增加离线软件包。
- [ ] 所有工作台发行包自带自身运行时依赖。
- [ ] 八个制品均包含同一调试模式、极详细日志和图形化软件目录编辑能力；三类目录的手动导入仅在调试工具区出现，“保存草稿”与“应用”在所有制品中保持相同的两阶段语义，不依赖额外开发运行时。
- [ ] 每种发行制品都能把调试会话导出为一个版本化、自包含且已脱敏的诊断文件；该文件不依赖测试机上的额外开发工具或另一份人工环境资料即可用于异机定位工作台可观察的问题。
- [ ] 超大离线版内置选定软件及其离线依赖，并与缓存明确区分；断网救援版内置的救援伴随工具遵守受控制品边界。
- [ ] 首版超大离线版构建清单明确列出所携带的候选资源；Game Cheats Manager、Cheat Engine、Office Tool Plus、Internet Download Manager 和几何画板与其他候选软件一样可以被携带或作为项目备用源，具体内容由制品清单决定。`SEC-08` 禁止内容不进入任何制品。
- [ ] 所有标为 ARM64 机器级安装版的资产都使用原生 ARM64 的安装器、bootstrapper、卸载器和必要自定义动作；现有 x64 机器级安装版在 ARM64 设备上只能经受控的互斥机器级迁移替换，迁移保留共享设备状态并清理旧程序文件和安装登记，不产生并存的用户级或双作用域产品。
- [ ] 机器级安装版提供 Windows 标准 Repair，只恢复当前版本安装器拥有的机器级程序文件和声明资源，不重置或删除 `ProgramData` 中的动态状态。
- [ ] 机器级安装版的普通卸载只删除安装器拥有的机器级程序文件和安装登记，不删除 `ProgramData` 中的状态、历史、目录、草稿、检查点、偏好、缓存或日志；显式删除本机数据是独立的受保护操作。
- [ ] 首版构建固定工具和输入版本，并能解释同一固定构建器上两次构建的差异；不随发行包或 GitHub Release 提供最终资产摘要、源码关联或 provenance，首版也不承诺跨干净构建器 bit-for-bit 相同。
- [ ] 发布说明披露未签名、无校验值和 SmartScreen 风险。
- [ ] GitHub Release 中的文件命名和说明让用户能选择正确架构与版本。
- [ ] 预发布、beta、preview、nightly 或其他测试发行在 GitHub Release 中明确标记为预发布，避免被一键更新误列为正式稳定发行。
- [ ] `1.0` 前只固定一个功能完整、八制品齐全的 `v0.9.0-beta.1`；本事项生成可交给事项 34 的候选八制品、构建入口和机器可读门禁结果，但不放宽早期只读 GitHub Actions 权限、不创建 tag 或 GitHub Release，也不把候选生成记为外部发布成功。阻断缺陷需要重验时可按需准备后续 beta 候选。
- [ ] 发布说明把 Windows 10 22H2 称为最低目标版本，并说明不提供跨版本兼容性测试保证。
- [ ] 首版发行流程不包含 macOS 制品，也不暗示已提供 macOS 兼容性。
- [ ] 发行制品由固定版本的稳定工具链和依赖生成，不依赖 preview、nightly 或浮动 latest。
- [ ] Windows 发行包由 C++/WinRT、XAML 和 C++26 核心组成，不依赖 .NET 运行时。
- [ ] 三类内置目录均随发行包离线可用；系统设置目录包含两项已确认的 Windows 首版必达优化，软件与软件优化目录共同包含搜狗输入法的两项安装阶段偏好及全部已确认安装后优化项。
- [ ] 软件目录维护文件以 `release_state = "release"` 通过发布级结构和能力校验；首版范围的 QQ、搜狗输入法、Game Cheats Manager、Cheat Engine、Office Tool Plus、Internet Download Manager、几何画板、Java、.NET、DirectX 和 PowerShell 7 均已启用并填充目录所需来源和安装档案。维护目录发布状态仍为 `draft`、条目仍未启用或其他结构、能力门禁未通过时不得生成首版制品；来源、许可、身份与再分发研究不能单独否决候选资源随包或公开发布。即使同一目录已经在某台电脑应用为本机试用目录并运行正常，也不能收入任何正式制品或作为发布通过证据。
- [ ] 每个首版必达项都具有工作台受控执行、结果检测和自动化检查；若其中任何一项只能显示手动说明、“暂不支持自动处理”或“暂无可用优化”，则不得生成可发布制品。
- [ ] 内置目录记录至少一个构建时当前稳定的搜狗安装器与对应已安装版本基线，并完整覆盖两个安装阶段偏好及全部安装后优化；“腾讯元宝”属于已知且可可靠处置的附加推广，默认拒绝。其他允许自动处置的安装器交互在运行时失配时按工作台确认和官方界面逐级回退；登录、注册、验证码、付款和个人资料步骤始终由用户在官方界面完成，不得通过声明零个受支持搜狗版本绕过能力门槛。
- [ ] 无界面核心流程、界面与核心合同、核心与平台适配器合同、单向依赖、状态唯一来源和受控扩展隔离检查全部通过；强制代码评审同时确认高内聚、接口深度、状态所有权、删除检验和规则唯一归属；循环依赖、界面直接系统操作、重复业务规则、跨功能可变全局状态或第三方可执行插件入口均阻止发布。
- [ ] 动效发布检查证明键盘与高频路径即时、语义资源集中、快速反向不排队、系统动画关闭分支可用、布局属性动画禁令生效，且动画完成事件不承担业务状态；普通自定义动效最长 250ms，有效动效偏好允许时完成反馈保持克制，系统关闭动画时直接显示最终结果。
- [ ] 开发者发布记录分别写明设计与实现完成情况、自动化检查结果和真实设备验证结果；未进行真实 Windows 或搜狗环境验证时明确标为“未实机验证”，但不因此阻止构建或发布。
- [ ] “未实机验证”仅记录在开发者发布证据中，不得显示在普通应用界面或面向用户的 GitHub 发布说明中；面向用户的文案也不得声称已经完成真实设备验证。
