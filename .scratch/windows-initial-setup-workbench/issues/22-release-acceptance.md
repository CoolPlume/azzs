# 补充首版真实环境验证记录

Type: task  
Status: ready-for-human  
Blocked by: 21

## Goal

在条件允许时，于代表性的新装 Windows 11 设备上补充首版范围、发行形态和一条龙流程的真实环境证据；本事项不建立跨 Windows 版本兼容性矩阵，也不是首版发布门槛。

未执行本事项时，开发者发布记录必须明确标为“未实机验证”。源代码审查和自动化检查不能冒充真实设备验证；该状态仅进入开发者发布证据，不得出现在普通应用界面或面向用户的 GitHub 发布说明中，面向用户的文案也不得声称已经完成真实设备验证。

## Acceptance Criteria

- [ ] 在 Windows 11 x64 与 ARM64 上分别完成标准版联网场景。
- [ ] 验证低于 Windows 10 22H2 的版本提示设计允许继续运行且不作兼容承诺，不要求完成旧系统功能验收。
- [ ] 安装版与便携版均在未预装工作台运行时的系统上成功启动。
- [ ] 超大离线版在完全断网时完成本地可用的系统优化和软件安装。
- [ ] 验证驱动导致的网络、显示、硬件变化和重启恢复场景。
- [ ] 验证目录错误、来源失效、下载中断、停止与强制终止场景。
- [ ] 验证来源自动解析失败时只能查看目录原始地址，用户在工作台外自行下载和运行；工作台不接收或启动该文件，返回后主动重新检测只显示“外部安装已识别”或保留原失败状态，不伪造下载进度、来源事实或工作台安装成功。识别成功的软件可以满足只要求存在的依赖并进入软件优化发现，所需版本仍须单独检测。
- [ ] 验证来源手动交接跨工作台关闭、异常退出、Windows 重启以及便携版与安装版切换保留；它不会单独建立重启屏障、触发登录后自动打开或恢复后自动检测，原始地址、失败原因和入口仍可用。
- [ ] 验证推荐流程在外部安装识别成功后不会自动继续，用户点击“继续”才重新判断剩余内容；识别成功但尚未继续时关闭或重启，恢复后仍停留在同一续接点。独立软件安装页只更新外部安装状态，不显示流程专属“继续”。
- [ ] 验证来源手动交接重新检测失败时没有任何强制标记已安装的入口；“暂时跳过”不会满足依赖、进入软件优化发现或生成安装成功记录，依赖该软件的项目保持阻塞，无依赖关系的其他项目按既有规则继续。
- [ ] 验证暂时跳过的软件持续列入未完成列表，关闭、异常退出、Windows 重启及便携版与安装版切换后仍保留失败原因和“重新检测”，不会自动检测；后来识别成功才移出未完成状态且交接历史不被删除。
- [ ] 验证后来识别成功时只更新目标软件存在事实；独立软件页在用户下一次主动规划、推荐流程在用户点击“继续”后，才让当前已满足依赖的软件恢复为可选择且保持未勾选，不会自动创建批次、下载或安装；仍缺其他依赖的项目保持阻塞。
- [ ] 验证调试模式目录导入、内置资源被当前目录移除、兼容目录回退、未知展示字段可忽略及未知执行语义拒绝整包并保留当前有效目录的场景。
- [ ] 验证设置撤销、下架设置、应用更新失败回退和共享设备状态。
- [ ] 验证系统优化页的“推荐总体优化”可展开并调整单项，且总体方案与单项入口共享当前状态、执行结果、历史和逐项撤销。
- [ ] 在 Windows 11 25H2 验证经典右键菜单和 Windows 10 风格资源管理器默认不选，可直接应用、恢复 Windows 11 默认状态并保留原状态恢复数据；除核对注册表与检测状态外，还人工确认应用后的界面效果确实出现、恢复后的 Windows 11 默认界面确实恢复。
- [ ] 验证上述两项的“立即重启资源管理器”风险说明及“稍后处理”状态；等待资源管理器重启不会误建成 Windows 重启屏障，重启后会重新检测实际结果。
- [ ] 验证超出目录已知 Windows 适用范围时，标准视图显示“可能不适用”并禁用普通执行，高级视图仅在恢复能力可用且单独确认风险后允许“仍然尝试”。
- [ ] 验证取消流程不会丢失已执行但仍等待重启验证的设置状态。
- [ ] 验证正常软件优化、版本不适用强制执行、强制关闭目标软件和强制终止优化的风险入口。
- [ ] 验证优化部分失败不自动恢复、停止与取消只放弃未执行步骤、重试创建新批次及重启后由用户继续。
- [ ] 验证普通下架保留既有批次和历史，紧急撤回阻止尚未执行步骤，离线陈旧通知显示准确提示。
- [ ] 验证软件优化页只显示已安装软件，标准与高级视图共享状态，完整历史统一进入“历史与日志”页。
- [ ] 验证搜狗输入法从官网取得最新版，且在声明支持且仍可可靠识别的安装程序版本中由工作台自动关闭搜索候选并阻止安装腾讯元宝；模拟自动处置运行时失败时，先使用工作台确认、再回退官方安装界面，二者均不伪报自动成功、安装结果待确认或手动应急处理。
- [ ] 验证已识别且可可靠处理的附加推广默认拒绝；登录、注册、验证码、付款和个人资料步骤只在官方安装界面由用户完成，工作台不代填、读取、传递或记录内容，也不会显示工作台交互确认。
- [ ] 验证当前运行测试发行时只有用户主动触发“切换到最新稳定版”才会尝试更新；没有同发行架构、内容版和便携版或安装版形态的正式稳定制品时显示不能自动更新与手动下载入口，不自动换制品。
- [ ] 验证搜狗输入法安装后方案逐项覆盖并实际执行全部已确认项目，搜狗提供的 PDF 工具、磁盘管理和压缩右键扩展归入软件优化，而 Windows 自身的菜单与资源管理器样式只出现在系统优化。
- [ ] 验证已安装且版本受支持的搜狗输入法不会把任何首版必达项显示为“暂不支持自动处理”或“暂无可用优化”；遇到未识别的新版本或已实现路径的运行时失败时，手动应急处理与成功状态明确区分。
- [ ] 验证来源文章内容变化不会直接修改执行规则，只有加载经过维护的新目录版本后才改变可执行内容。
- [ ] 验证调试模式可即时开启并跨重启保留，日志达到规格要求的详细粒度且敏感身份信息和凭据被排除或匿名化、不自动上传；一次导出只产生一个自包含诊断文件，未接触测试机的开发者只查看该文件即可定位代表性的目录、来源、下载、安装程序、恢复和异常退出故障，并能看见所有已知或可检测的采集缺口、最后落盘后的未知区间，以及当前目录的 `release_state`、本机试用标记、目录应用关联标识、运行时加载结果和正式发布门禁结果；图形化软件目录编辑器与 TOML 使用同一模型和校验，保存草稿后软件列表不变，保存成功的版本在正常关闭、异常退出或断电后重新打开仍显示“已保存未应用”且不自动应用，可继续编辑、明确应用或删除，删除草稿不影响当前目录及既有记录；仅有已保存未应用草稿时直接关闭不显示未保存确认。存在未保存修改时，分别验证切换页面、切换标准视图与高级视图及关闭调试模式均不显示关闭确认、不丢失修改、不自动保存或应用，重新打开编辑器仍显示“未保存更改”；已有已保存草稿后再产生未保存修改时，“应用”不可用且核心拒绝任何直接调用，既不应用旧草稿也不隐式保存新修改，并就地提示先保存。只有主动关闭工作台才显示“保存草稿并关闭”“放弃未保存修改”和“返回编辑”。验证保存成功后才关闭，重开后得到包含新修改的“已保存未应用”且当前有效目录不变；保存失败不关闭、不部分覆盖此前已保存版本且未保存修改继续保留；放弃只移除上次保存后的修改，返回编辑取消关闭，三种结果均不应用目录。另验证“关闭调试模式 → 关闭工作台”的组合：保存失败或返回编辑会临时恢复原编辑会话，但不重新开启调试模式或极详细日志，修改不丢失且目录不应用，再次离开后入口仍隐藏；临时会话只允许编辑、保存或放弃，“应用”在界面和核心中均被拒绝并提示先明确重新开启调试模式。整包应用成功后才完整切换当前有效目录，整包失败保留旧目录与草稿，局部依赖错误随新目录切换并禁用相关项，本机应用不改变维护目录发布状态，既有批次快照和历史不变，任意脚本、命令或插件不能强制成为当前有效目录。
- [ ] 验证工作台异常退出或电脑断电后，下次启动会尽量找回目录编辑器尚未保存的修改；成功找回时明确显示“恢复的未保存修改”，不会自动保存、应用或显示成“已保存未应用”，并与此前已保存草稿和当前有效目录分别恢复。恢复内容不得覆盖或损坏已保存版本，“应用”在界面与核心中继续被拒绝；显式保存成功后才转为“已保存未应用”并清除对应恢复状态，放弃只删除恢复的未保存部分，不影响此前草稿、当前目录、既有批次或历史。注入找回失败时不得伪报已找回。验收不预设恢复写入频率和内部存储格式，并验证启动时显示不阻断的持续“继续编辑”入口，用户主动进入编辑器而非自动打开。
- [ ] 验证运行时可加载但 `release_state = "draft"` 或存在其他仅发布级问题的软件目录可以从已保存草稿明确应用或从调试工具区手动导入为本机试用目录，运行时整包错误或未知执行语义仍阻止应用和导入；设置页的软件与驱动目录当前状态在导入后原位立即显示该身份，软件安装页、推荐流程软件阶段、编辑器、批次快照和诊断资料也能识别。关闭调试模式时编辑和导入入口隐藏，重新启动后按已保存的调试模式状态决定入口是否显示；无论入口是否显示，“正在使用本机试用目录”的静态文字状态都继续可见。编辑器应用后键盘焦点仍留在“应用”命令，调试工具区导入后焦点返回并留在触发导入的命令；屏幕阅读器可识别且不重复播报，不出现绿色完成样式、勾选、Toast、音效、淡入、弹跳或庆祝反馈；正式构建继续拒绝该目录，开发者证据不得把本机运行写成发布通过。
- [ ] 验证系统优化与软件优化不以当前用户、软件账号或整台电脑作为页面分类，只用通俗说明准确描述实际影响。
- [ ] 普通用户可以独立走完推荐流程并理解最终总结。
- [ ] 若执行本事项，验证键盘与鼠标连续切换一级导航、键盘焦点移动和勾选均即时完成，鼠标与触摸按下反馈清楚，触摸无需 Hover 即可发现全部主要操作。
- [ ] 若执行本事项，快速反复打开和关闭浮层或详情时，动效从当前状态立即改向且不丢输入；有效动效偏好允许时完成反馈只有一次勾选与短淡入，没有彩屑、弹跳、音效或阻塞。
- [ ] 若执行本事项，在应用运行中把 Windows 动画开关从开切到关再切回开，确认关闭时空间、缩放、弹簧和完成动效立即停用，重新开启后只恢复允许的动效；两种状态下焦点、状态、文字、无障碍反馈和业务结果保持完整。
- [ ] 若执行本事项，记录 4K、225% 显示缩放与 Windows 文本缩放的实际值；在两块分辨率、DPI 或显示缩放不同的显示器间移动窗口并断开原显示器，记录布局、焦点、滚动语义、输入、选择、进度、窗口可见性和状态保持结果。同步记录 Windows 自动选择的图形适配器类别、逻辑处理器数与受限并行上限；集成、独立或混合图形设备的视觉回退不得被写成完整实机兼容性结论。未执行时只保留“未实机验证”。
- [ ] 若执行本事项，在下载、日志、目录解析和状态更新并发的 Release 构建中记录 WPR/WPA XAML Frame Analysis，核对导航、滚动、浮层、取消和快速反向没有可重复慢帧或输入延迟；证据同时记录构建、设备、Windows 与 Windows App SDK 版本、分辨率、刷新率、文本缩放、输入方式、动画设置、响应与帧目标及证据路径。未执行时只保留“未实机验证”，不写成性能通过。
- [ ] 若执行本事项，规格第 19 节全部验收场景留有可追溯的真实设备结果；若未执行，开发者发布记录只写“未实机验证”，不得写成通过。
- [ ] 验收范围不包含 macOS，但确认可移植核心边界没有暴露 WinUI 3 或 Win32 类型。
