## 4. 内容边界问题

`CONTEXT.md` 还承载了本应位于规格、模式或架构文档的细节：

- `enabled = false`、`release_state` 和 `release_state = "draft"` 是具体模式字段，不是领域定义本身。
- “保存、应用、替换、只影响后续列表/规划/批次”等状态转换属于行为规格。
- WinUI 3、TOML、GitHub Release、HTTP(S) 和特定文件格式多处进入定义；只有它们构成领域概念身份时才应保留。
- 写入、加载、自动检查、导出、重启恢复与进程行为属于规格或架构合同。
- 目录、流程、执行记录和恢复状态的定义过度依赖彼此的排除清单，导致新增一个术语时要修改多处。

这不表示这些规则应删除；应把规则迁回主规格、目录模式、设计或架构文档，再让词汇表用一到两句回答“它是什么”。

## 5. 仍缺少或过载的状态词

以下是领域建模候选，不能在维护者确认前直接加入正式词汇：

| 主题 | 当前问题 | 候选拆分 |
| --- | --- | --- |
| 软件当前状态与操作结果 | “已安装”“已完成”“安装成功”跨检测、用户确认和执行结果混用 | 当前状态与本次操作结果分别建模 |
| 来源解析失败 | 网络、页面结构、无匹配资源、架构不匹配、来源失效可能都落到相近文案 | 先定义可恢复性与责任，再决定用户短词 |
| 架构选择 | “架构回退”有概念，但缺少明确结果状态 | 原生匹配、兼容回退、无适用包 |
| 软件版本检查 | 候选审核稿确认“已是最新版”，正式状态表未完整吸收 | 当前、可更新、无法确认 |
| 队列生命周期 | “未执行”“暂时跳过”“等待联网”“待确认”缺少统一终态/非终态分类 | 待处理、阻塞、终态、可重试 |
| 目录发布 | 运行时加载、本机试用与正式发布已有术语，但 UI 状态和证据状态仍可能互相代替 | 目录身份、校验结果、发布证据分层 |

## 6. 建议的清理批次

1. 机械移除所有指向正式术语的 `_Avoid_` 项；若定义本身尚未说明差异，只在该定义中补一句边界，不发明新的 `_Different from_` 格式。
2. 保留真正同义、过时或误导的称呼，例如“在线版”“小白模式”“苹果皮肤”；逐项检查是否仍只有一个概念。
3. 把模式字段、状态转换、流程、文件格式和模块边界迁回各自权威文档，再压缩词汇定义。
4. 先由维护者确认“当前状态与操作结果”的分层，再补缺失状态词；不能边清理边偷定产品语义。
5. 最后运行重复词、空 `_Avoid_`、正式术语碰撞、定义长度和本地链接检查，并让事项标题、测试名和界面短词回用统一语言。

## 7. 验收条件

- `_Avoid_` 不再引用任何正式术语。
- 每个 `_Avoid_` 都能回答“它是否只是同一概念的不推荐叫法”；不能回答则移除。
- 每个定义保持一到两句，回答“是什么”，不承担状态机或实现合同。
- 主规格、ADR、事项和目录模式仍保留被迁出的规则，且链接到相应权威位置。
- 清理差异不改变已确认行为；任何语义变化单独进入 `grill-with-docs` 决策树。

## 8. 06:32 领域状态缺口归并

本次复核把四组容易被实现者误读的状态词单独列出。它们不是新的根问题，分别归并到 Q3/Q6/Q16/Q17/Q19 及事项 08、12、14、15、16、17、19、21、22；在维护者回答前不修改正式词汇表：

| 现有表述 | 尚未闭合的语义 | 需要冻结的区分 | 归并位置 |
| --- | --- | --- | --- |
| “驱动交接中”“已完成”“需要重启” | 外部用户/厂商动作、工作台观察、重启屏障和流程聚合结果混在一起 | 外部交接状态、工作台验证状态、待重启状态、流程结果分别记录 | Q3、Q6、Q17；事项 14/16 |
| “流程完成” | 暂时跳过、外部安装已识别、待确认项目可能被错误压成成功终态 | 流程终态、步骤结果、未决/待确认步骤的聚合规则 | Q6、Q17；事项 08/12/16 |
| “应用成功/导入成功” | 本机试用、目录载入、用户保存和公开发布证据不是同一事实 | `applied`、`failed`、`rejected`、`unknown` 等操作结果与目录/发布身份分层 | Q6、Q16/Q18；事项 19/21/22/32 |
| “已确认”文档状态 | `spec.md:3` 与架构文档的文档状态可能被理解成全部产品决策已定 | 文档状态、产品决策状态、实现证据状态使用命名空间或明确限定词 | 文档权威审计；事项 30/31 |

最小负向验收：外部交接未回传、步骤被暂时跳过、目录只在本机应用、导入来源无法验证、重启后尚未复核和文档仍含未决 Q 时，均不得显示或记录为无条件的“完成/成功/已确认”。
