## 2. 状态分层

明日处理文档时继续保持以下三个轴，不要用一个 `ready` 或“完成”覆盖它们：

1. **规格状态**：事实、推荐、未决、已确认、supersede 关系。
2. **工程状态**：文档可执行、样机可执行、产品实现、合同测试通过、实机证据通过。
3. **发行状态**：开发构建、候选 Release、公开 Release；第三方资源再分发状态另按 `accepted` 过滤。

`ready-for-agent` 只表示当前事项元数据允许 agent 处理，并不表示产品实现或公开发行已经解除阻塞。`not-started`、`needs-info`、`blocked`、`not-run`、`pass` 和 `waived` 也必须在具体证据上下文中解释。

## 5. 状态合同接手字段（06:40）

以下字段是现有 Q/事项的建议验收输入，不是新增正式模式或已确认 API：

| 场景 | 追加字段 | 必须阻止的误判 |
| --- | --- | --- |
| 驱动/外部交接 | `entry_id`、目标身份、`handoff_id`/attempt、主体、外部结果来源、重启/屏障/恢复 ID、用户选择、观察时间、证据引用 | 页面关闭、外部进程退出、用户口述或重启后未复核不得成为“驱动已完成” |
| 流程聚合 | `flow_id`、阶段/项目 ID、聚合规则版本、项级状态/操作结果、阻塞原因、续接点、重试资格、批次引用、用户确认事件 | 总结展示、全跳过、外部识别或待确认不得无条件成为流程成功 |
| 目录保存/应用/导入 | `operation_id`/attempt、source kind、候选修订/摘要、运行时校验、发布门禁、本机试用标记、提交结果、替换代次、操作者/同意、观察时间 | 可解析、本机应用、用户同意或保存成功不得成为来源可信、发布通过或旧批次改写 |
| 软件来源手动交接 | `handoff_id`/attempt、软件稳定标识、解析失败、原始地址、主动重检时间线、版本/架构可信度、未完成列表、流程续接点 | “外部安装已识别”不得成为工作台安装成功、安装结果待确认或自动创建/解锁批次 |

推荐的最小证据组合：无界面状态转换/聚合真值表、失败与未知故障注入、关闭/重启恢复、重复调用或旧快照重放，以及可定位的 Windows 实机日志；缺少某类证据时保持 `needs-info`。
