# Windows 初装工作台首版规格

状态：已确认

确认日期：2026-08-09

适用版本：首个公开版本

## 1. 文档目的

本文档定义“初装工作台”首版的产品范围、用户流程、功能行为、异常处理和验收标准。本文已经确认 QQ、搜狗输入法、两项资源管理器相关系统优化及其来源；其余软件、系统优化项、驱动助手和厂商页面清单将在后续补充。

领域术语以根目录 `CONTEXT.md` 为准，难以逆转的设计取舍见 `docs/adr/`。本文档负责描述用户可观察的产品行为。

## 2. 产品目标

`GOAL-01` 初装工作台应帮助普通用户在一台刚安装完成的目标 Windows 电脑上，独立完成驱动准备、系统优化、常用软件安装和项目提供的软件优化。

`GOAL-02` 首版完成标准是：普通用户能走完“驱动 → 系统优化 → 软件安装 → 软件优化”的推荐流程，理解每项结果，并能处理失败、跳过、等待联网和等待重启等情况。

`GOAL-03` 各功能页面应可独立使用，推荐流程不得成为阻止用户直接操作的强制向导。

`GOAL-04` 本规格已经确认的系统优化、软件安装阶段偏好和软件优化选项均为首版必达项；工作台必须能够实际发起并完成这些操作，不能以只展示方案、长期标记“暂不支持自动处理”或要求用户自行修改来代替实现。

## 3. 适用范围

### 3.1 目标环境

- `SCOPE-01` 最低目标版本为 Windows 10 22H2，目标范围同时包括 Windows 11；适用场景为全新安装后或尚未正式投入使用的 OEM 初始环境。
- `SCOPE-02` 工作台是本机运行的 Windows 图形应用，不以浏览器或命令行为主要交互界面。
- `SCOPE-03` 首版面向普通个人设备，不以升级而来的旧系统、企业受管设备或 Windows Server 为目标环境。
- `SCOPE-04` 系统优化与软件优化按被调整功能属于 Windows 还是目标软件划界，不以当前用户、软件账号或整台电脑作为用户可见分类或方案准入条件；每项操作仍须用通俗文字准确说明实际影响。

### 3.2 Windows 版本策略

- `SCOPE-05` “最低目标版本”表示产品按设计面向的最早版本，不构成经过兼容性测试的支持承诺。
- `SCOPE-06` 首版不建立跨 Windows 版本的兼容性测试矩阵。
- `SCOPE-07` 检测到早于 Windows 10 22H2 的版本时，启动阶段显示当前版本、目标版本和可能无法正常工作的警告，但允许用户继续运行。
- `SCOPE-08` 低于最低目标版本时，工作台不得把警告伪装成成功兼容，也不得因版本号本身阻止启动；具体功能仍可因实际缺失的系统能力进入不可用或失败状态。

### 3.3 首版不做

- 不直接匹配、下载或安装具体硬件驱动。
- 不提供跑分、烤机或其他硬件测试。
- 不允许用户输入任意软件下载地址、注册表改动或 PowerShell 命令。
- 不提供目录编辑器，也不正式支持用户自制目录包。
- 不审查第三方软件来源，不验证软件包签名或哈希。
- 不自动重启 Windows，不在登录后静默继续管理员操作。
- 不在后台静默更新应用或目录包。
- 不承诺提供全部软件或全部历史版本的离线安装包。
- 首版不发布或测试 macOS 版本，也不建设跨平台共享界面层。

## 4. 发布与运行

### 4.1 发布形态

- `REL-01` 项目通过公开 GitHub 仓库和 GitHub Releases 发布。
- `REL-02` 同时提供便携版和安装版。
- `REL-03` 同时提供较小的在线版和体积较大的离线资源版。
- `REL-04` 在线版只内置工作台自身运行所需的全部依赖；离线资源版还内置一部分推荐软件的离线软件包。
- `REL-05` 在线版联网时可按单个软件从项目 GitHub 获取项目维护的离线包，但该来源只是备选来源之一。
- `REL-06` 同时发布 x64 与 ARM64 工作台包；x64 是默认优先展示的发行架构，ARM64 Windows 应使用 ARM64 工作台包。
- `REL-07` Windows 首装环境不需要预先安装工作台运行时或框架依赖。
- `REL-08` 开发者可见的发布记录必须分别标明“设计与实现完成”“自动检查通过”和“实机验证通过”；没有真实 Windows 或目标软件验收证据时明确记录“未实机验证”，不得在开发记录中推断为通过。
- `REL-09` “未实机验证”仅记录在开发者发布证据中，不得显示在普通用户界面或面向普通用户的 GitHub 发布说明中；面向用户的文案也不得声称已经完成真实设备验证。该状态不改变首版不建立跨版本兼容性测试矩阵的决定。

便携版、安装版、在线版、离线资源版和发行架构是不同发布维度；具体 Release 文件如何组合由发布设计决定，但上述能力都必须提供。

### 4.2 管理员权限

- `SEC-01` 工作台启动时请求一次 UAC 管理员授权，并在本次启动到退出期间保持管理员身份。
- `SEC-02` 所有软件安装、系统优化和软件优化操作必须通过各自当前有效的精选目录表达，不能借常驻管理员权限直接执行用户输入的任意命令、脚本、注册表内容或目标路径。目录预定义的受控注册表操作不属于用户输入；任何一类手动导入目录都因无法验证来源，必须按 `CAT-21` 和 `CAT-22` 充分披露后再由用户确认。
- `SEC-03` 工作台应清楚显示当前正在执行的操作及其结果，避免管理员操作在无可见反馈时发生。

### 4.3 未签名发行

- `SEC-04` 项目长期不为应用发行包配置 Windows 代码签名。
- `SEC-05` 项目不随发行包提供 SHA-256 校验值或源码提交关联。
- `SEC-06` 下载和更新说明必须明确披露发布者及文件完整性无法由项目提供的信息验证，并说明可能出现 SmartScreen 提示。

### 4.4 关闭与恢复

- `RUN-01` 用户关闭工作台窗口时，本次常驻管理员会话结束；工作台不以后台服务形式继续启动新的初始化操作。
- `RUN-02` 关闭时保存推荐流程记录、系统优化执行记录、安装批次、优化批次和待验证状态；重新打开后由用户明确选择是否继续。
- `RUN-03` 关闭窗口不等同于强制终止已经启动的外部安装程序。外部程序可能继续结束，工作台重新打开后应先验证其结果，再决定该项目的后续状态。
- `RUN-04` 关闭工作台后的恢复遵守现有批次快照、重启屏障和只读历史规则，不静默续跑。
- `RUN-05` 应用内下载尚未完成时关闭工作台，即使当前处于暂停状态，也应停止下载并按 `CACHE-15` 清理未完成临时文件；重新打开后只恢复待处理状态，等待用户明确重新开始。
- `RUN-06` 用户正常关闭工作台且当前软件优化步骤正在执行时，关闭流程应沿用“停止优化”的安全结束边界，先等待当前步骤安全结束，再把后续步骤保持为待处理、保存批次状态并退出；普通关闭不把后续步骤标为“未执行”。应用异常退出或电脑意外断电而无法确认步骤结果时，重新打开后把该步骤置为“优化结果待确认”，先重新检测，不得直接重跑。

### 4.5 技术架构边界

工程技术选择规则见 [技术基线与更新策略](../../docs/engineering/technology-baseline.md)。

- `TECH-01` Windows 界面层采用 WinUI 3、C++/WinRT 与 XAML，C++ 核心层承担初始化业务逻辑；整个应用不依赖 .NET 运行时。
- `TECH-02` “前后端分离”是同一个桌面应用内部的职责与代码边界，不表示两个独立运行的程序，也不引入后台服务或本地网络接口。
- `TECH-03` WinUI 3 界面层负责接收用户意图、展示状态和调用核心能力，不复制目录校验、依赖规划、批次快照、恢复、日志或执行策略。
- `TECH-04` C++ 核心层拥有目录规则、操作规划、批次状态、恢复状态、执行日志和结果语义，并通过小型明确接口向界面层提供能力。
- `TECH-05` 核心接口不得暴露 WinUI 3 控件或页面类型，界面生命周期也不得成为业务状态的唯一存储位置。
- `TECH-06` 两层共享同一个常驻管理员会话；关闭界面即关闭工作台，不保留能继续启动任务的独立后端进程。
- `TECH-07` 未来 macOS 版本接受按 macOS 交互习惯重新制作界面，不复用 WinUI 3 界面代码。
- `TECH-08` C++ 核心内部将可移植的目录语义、依赖规划、快照、状态与结果规则，同 Windows 专属的设置、硬件、进程、权限和重启操作分开。
- `TECH-09` 可移植核心的接口和数据模型不得依赖 WinUI 3 或 Win32 类型；Windows 专属能力通过明确的平台适配边界接入。
- `TECH-10` Windows 与未来 macOS 可以复用确实跨平台的核心规则和数据契约，但不假设两端共享同一套系统设置、驱动入口或平台操作。
- `TECH-11` macOS 只是未来迁移窗口，不属于首版发行、测试或验收范围，也不要求现在建设通用跨平台界面框架。
- `TECH-12` C++ 核心以 C++26 作为语言标准和编译模式，不把整个项目降级到旧标准作为常规兼容方案。
- `TECH-13` C++26 具体特性只有在所选稳定工具链对 x64 与 ARM64 均提供可靠支持时才进入生产代码；不为展示新语法而牺牲发行可靠性。
- `TECH-14` WinUI 3、Windows App SDK、编译器、SDK 和依赖优先选择实施时最新的稳定版本，不把 preview、nightly 或实验发行作为首版发布基线。
- `TECH-15` 技术选择必须同时满足 Windows 10 22H2 最低目标、自包含发行、离线启动、x64/ARM64 和现有恢复语义；“更新”不能覆盖这些产品约束。
- `TECH-16` 试验性能力只能放在可替换边界或独立验证中，不得进入持久化数据格式、目录契约或界面与核心之间的稳定接口。
- `TECH-17` 发布所用工具和依赖固定到明确版本，并在每个发布周期主动评估可用的稳定更新，不使用会随时间漂移的“永远取 latest”构建。
- `TECH-18` Windows 界面宿主与可移植核心都以 C++26 编译模式为目标；C++/WinRT 生成代码和界面代码只使用稳定工具链可靠支持的特性子集。
- `TECH-19` XAML 负责界面结构与资源表达，C++/WinRT 负责 WinUI 3 交互适配；界面后置代码不得成为核心业务规则的第二份实现。
- `TECH-20` Windows 平台适配层必须为首版必达项提供足够的受控执行能力，包括系统和软件注册表读写与删除、配置读写、目标进程与状态检测，以及前述方式不可用时范围受限且步骤由目录冻结的 Windows UI Automation；该能力同时覆盖安装器选项和安装后的软件设置，每种方式都必须接受核心层规划、记录结果并支持对应验证。
- `TECH-21` 首选执行方式不可用时应按目录声明切换到下一种受控方式；如果某个首版必达项没有任何可验证的受控实现，该项必须阻止首版发布，不得通过移除选项、改成说明链接或要求用户手动操作来绕过。

## 5. 界面设计与信息架构

详细设计准则见 [WinUI 3 的 Apple 风格适配](../../docs/design/winui3-apple-inspired.md)。

### 5.1 一级页面

`NAV-01` 应用包含以下一级页面：

1. 概览
2. 驱动
3. 系统优化
4. 软件安装
5. 软件优化
6. 历史与日志
7. 应用设置

- `NAV-02` 应用启动后默认进入概览页。
- `NAV-03` 一级页面应始终可以直接进入，不要求用户必须先完成推荐流程的前一阶段。
- `NAV-04` 概览页展示推荐初始化流程、当前阶段、需要用户处理的暂停状态和最近一次流程结果。
- `NAV-05` 具体软件、优化方案、设置和驱动入口应在对应页面中以可扫描的列表呈现，主要命令提供明确按钮。

### 5.2 Apple 风格适配

- `UI-01` 界面采用 Apple 风格适配：学习清晰层级、即时反馈、空间连续、克制材质、自然动效和用户掌控，不直接仿制 macOS 外观。
- `UI-02` 导航、窗口管理、键盘焦点、右键、触摸和常用控件行为遵守 WinUI 3、Fluent Design 与 Windows 用户习惯。
- `UI-03` 不复制 macOS 交通灯按钮、标题栏、Dock 式导航或只靠手势发现的主要操作。
- `UI-04` 工具界面保持安静、紧凑、可扫描，不采用营销式大标题、装饰性渐变、嵌套卡片或无功能价值的视觉装饰。
- `UI-05` 系统支持时，Mica 只用于应用根背景，Acrylic 只用于菜单和临时浮层；Windows 10、减少透明度或能力不可用时回退为实体主题背景，内容层级不得依赖透明材质。
- `UI-06` 按下时立即反馈，长任务持续显示当前项目、进度、下一步和停止能力；错误就地说明原因、影响和恢复动作。
- `UI-07` 动效只解释状态、空间关系或结果，不阻塞输入，进入与退出沿一致路径；默认无过冲，只有直接拖动或动量交互允许轻微回弹。
- `UI-08` 尊重 Windows 的减少动画、减少透明度、高对比度、文本缩放和屏幕阅读器设置；所有主要流程可只用键盘完成。
- `UI-09` 使用 Windows 系统字体和原生图标体系，字距固定为 `0`，字号不随窗口宽度缩放；文本放大和窄窗口下不得截断或重叠。
- `UI-10` 风险确认只用于真正危险或不可逆的操作；普通可恢复操作优先直接反馈和撤销，不反复打断用户。
- `UI-11` 标准视图为默认界面；用户可在应用设置中启用高级视图。
- `UI-12` 高级视图展示比标准视图更多的状态细节和控制项，切换时不得清除当前选择、进度、错误或恢复状态。
- `UI-13` 标准视图必须能够完成推荐初始化流程和常见独立操作，不得隐藏阻塞状态、关键风险、失败原因或必要恢复入口。
- `UI-14` 高级视图可以额外提供来源与历史版本、架构选择、缓存位置、目录导入或回退、详细日志等低频选项和手动控制。
- `UI-15` 高级视图不是权限或安全边界，不得绕过精选目录、来源规则、风险确认、恢复记录或批次快照，也不得开放任意命令、脚本或下载地址输入。
- `UI-16` 两种视图共享同一份领域状态、执行记录和用户选择；切换只改变呈现和可见控制，不创建第二套业务状态。
- `UI-17` 视觉增强按系统能力启用；缺少 Mica、Acrylic 或相应动效能力时使用可读、稳定的原生回退，不因视觉能力缺失阻止功能运行。
- `UI-18` 首次运行默认使用标准视图；用户选择高级视图后应保存该偏好，并在后续启动时继续使用。
- `UI-19` 标准视图与高级视图必须即时切换，不要求重启应用；切换期间正在显示或执行的任务不得被中断。
- `UI-20` 软件官网信息解析完成后，标准视图应在安装前简洁显示当前稳定版本、官网来源以及安装是否需要联网。
- `UI-21` 高级视图在相同信息之外显示软件包架构、完整安装包或在线安装器类型，以及本次解析得到的实际下载地址。
- `UI-22` 应用内下载应同时显示已下载量与总大小、当前下载速度和预计剩余时间，例如“1 MB / 100 MB”“2.7 MB/s”“还剩 3 分 23 秒”。
- `UI-23` 总大小、速度或剩余时间暂时无法可靠计算时，应显示“正在计算”或相应未知状态，不得显示虚构数值；取得数据后在原位置稳定更新，避免布局跳动。
- `UI-24` 当前下载项必须显示与已下载比例同步的进度条；总大小未知时使用不表示虚假百分比的不确定进度状态，取得总大小后切换为确定进度。
- `UI-25` 下载进度条和数值必须具有屏幕阅读器可识别的名称与状态；频繁更新不得造成布局跳动或连续干扰用户操作。
- `UI-26` 静默安装失败时，在该软件结果附近显示失败原因以及“重试静默安装”和“打开官方安装程序”两个明确操作，不自动弹出交互式安装界面。
- `UI-27` 多软件安装批次应同时显示按项目数计算的整批进度，包括“已处理数量 / 总数量”、当前软件名称和整批进度条；当前软件仍保留独立下载进度。
- `UI-28` 整批进度条不得根据文件大小或无法预测的安装时长伪造剩余百分比；失败、跳过和等待状态均计入已处理数量，并以文字分别说明结果。
- `UI-29` 当前下载项提供含义明确的“暂停下载”和“继续下载”操作；暂停状态保留已下载量，并与“停止批次”保持视觉和文字区分。
- `UI-30` 托管安装来源只显示其官方机制能够可靠提供的进度；无法取得总大小、速度或剩余时间时显示当前阶段和“无法估算”，不得套用虚假的应用内下载数值。
- `UI-31` 软件优化页的标准视图按“可以优化”“需要处理”“已优化”组织当前有方案的已安装软件，显示软件名称、效果摘要、主要状态、可选项和正常执行入口；高级视图在同一列表上增加实际版本、方案匹配、检测依据和具体修改内容，不改变分组或选择状态。
- `UI-32` 已安装但没有可执行优化方案的软件放入默认收起的“暂无可用优化”次级区域；未安装软件的优化方案不在标准视图或高级视图中展示。已安装软件处于首版声明支持版本且存在首版必达方案时，缺少可执行方案应显示实现错误并阻止发布，不得放入正常空状态区域。
- `UI-33` “强制执行”“强制关闭并继续”和“强制终止优化”只在高级视图显示；标准视图必须显示阻止原因、停止优化、正常关闭或重新检测等安全处理方式，以及即时开启高级视图的入口，切换后保留当前软件、选择和检测状态。
- `UI-34` 多软件优化在开始前使用一份按软件分组的批次确认摘要，普通方案不得再逐项弹出确认；“强制执行”“强制关闭并继续”等额外风险各自在实际触发前单独确认，不得把不同风险合并成一次笼统确认。
- `UI-35` 关闭或忽略安装结果附近的“可以优化”提示只收起本次非模态提示，不创建永久忽略状态；软件优化页继续显示该软件的当前状态，且不反复弹出被收起的提示。
- `UI-36` 软件优化页只显示当前状态和最近一次优化结果，并提供“查看全部历史”入口；完整记录统一在“历史与日志”页呈现，不在软件优化页复制第二套历史界面。
- `UI-37` 系统优化页在标准视图先展示“推荐总体优化”摘要和主要效果，再提供可展开的逐项选择；用户也可以跳过总体方案并直接使用单项设置。
- `UI-38` 推荐总体优化和单项设置列表引用同一系统设置项与状态；同一项只能保留一份选择、执行、恢复和历史，不得因两个入口重复执行或显示矛盾结果。
- `UI-39` 系统设置项超出项目已知适用的 Windows 版本时，标准视图显示“可能不适用”、已知范围和安全处理方式；只有该项具备明确恢复规则时，高级视图才可以提供单独的“仍然尝试”，并在执行前准确说明风险和恢复入口。
- `UI-40` 需要重启资源管理器才能生效的设置在完成后就地提供“立即重启资源管理器”和“稍后处理”；立即操作前说明任务栏和资源管理器窗口会短暂关闭，稍后处理时持续显示“等待资源管理器重启”。

## 6. 推荐初始化流程

- `FLOW-01` 推荐顺序固定为“驱动 → 系统优化 → 软件安装 → 软件优化”。
- `FLOW-02` 驱动阶段允许用户选择“已完成”或“暂时跳过”，之后进入系统优化阶段。
- `FLOW-03` 系统优化、软件安装与软件优化阶段允许用户只执行自己选择的项目；系统优化阶段默认展示推荐总体优化，但执行前仍可逐项调整或整体跳过。
- `FLOW-04` 任一阶段遇到必须先重启才能安全继续的操作时，进入重启屏障并暂停后续阶段。
- `FLOW-05` 工作台不得自行重启电脑；应提示用户为何需要重启、哪些操作尚未执行以及保存其他工作的风险，并提供“立即重启”和“稍后重启”操作。
- `FLOW-06` 流程完成或因重启屏障暂停时显示流程总结。
- `FLOW-07` 流程总结至少区分已完成、部分完成、失败、跳过、无适用项、未执行、结果待确认、等待重启、等待资源管理器重启和紧急撤回，并只对当前仍可执行的失败项提供重试，同时提供查看执行日志的入口。
- `FLOW-08` 推荐流程中的阶段状态不得限制对应一级页面的独立使用。
- `FLOW-09` 每次启动推荐初始化流程都形成独立的流程记录，用于保存四个阶段的进度和结果；流程记录与系统优化阶段创建的系统优化执行记录、软件安装阶段创建的安装批次及软件优化阶段创建的优化批次是不同对象。
- `FLOW-10` 用户取消暂停中的推荐流程时，流程记录作为只读历史保留；如果尚未进入系统优化、软件安装或软件优化阶段，不得虚构对应的系统优化执行记录、安装批次或优化批次。

## 7. 驱动与硬件

### 7.1 功能边界

- `DRV-01` 驱动页只提供硬件概览、驱动助手入口和厂商驱动页入口。
- `DRV-02` 工作台本身不匹配、下载或安装具体驱动包；具体驱动由驱动助手或厂商页面处理。
- `DRV-03` 首版精选驱动目录只覆盖后续清单指定的少数主流厂商和常见 OEM。

### 7.2 硬件检测

- `DRV-04` 硬件检测由用户按需触发。
- `DRV-05` 硬件概览至少覆盖 CPU、显卡、主板、网卡和整机 OEM 型号。
- `DRV-06` 检测结果只用于生成概览并推荐或高亮相关驱动入口。
- `DRV-07` 硬件检测应自行实现；可以借鉴图吧工具箱或类似项目的能力与界面思路，但不得直接复制其代码或资源。
- `DRV-08` 检测结果只在当前会话中缓存 10 分钟；缓存到期后再次进入驱动页时主动刷新，检测到硬件变化时也主动刷新，并提供用户主动刷新入口。
- `DRV-09` 检测失败、权限不足或用户取消时显示“未识别”，但固定厂商页和驱动助手入口仍可使用。

### 7.3 驱动入口及外部影响

- `DRV-10` 驱动助手未安装时，入口用于安装该助手；已经安装时，入口用于启动该助手。
- `DRV-11` 厂商驱动页入口打开项目维护的官方厂商页面。
- `DRV-12` 工作台应考虑显卡、网卡等驱动安装可能造成的显示变化、网络中断、硬件重新识别和重启要求。
- `DRV-13` 启动外部驱动助手或厂商操作前应保留当前流程进度，并把驱动阶段标记为“驱动交接中”；短暂网络、显示变化、应用关闭或外部重启不得丢失流程记录。
- `DRV-14` 外部驱动操作返回或工作台下次启动时，不自动判定驱动阶段完成，而是让用户选择“已完成”“需要重启”或“暂时跳过”。
- `DRV-15` 用户选择“需要重启”时，必须在进入系统优化阶段前建立重启屏障；重启恢复后重新获取必要的硬件与网络状态。

## 8. 系统优化

### 8.1 设置范围

- `SET-01` 系统优化页只展示项目维护的精选设置目录中的系统优化方案和系统设置项。
- `SET-02` 每个系统设置项都可独立触发；界面不按当前用户、软件账号或整台电脑分类，而应以通俗文字准确说明该项实际会影响什么。
- `SET-03` 每个设置项应说明目标效果、当前状态、是否需要重启以及能否撤销。
- `SET-04` 执行前检查当前状态；已经符合目标值时显示“已生效”并跳过重复修改。
- `SET-05` 设置项存在依赖关系时，应在执行前处理依赖，不能以错误顺序执行。
- `SET-06` 工作台只验证自身发起的设置是否达到目标效果，不承担通用 Windows 故障诊断。

### 8.2 撤销与恢复记录

- `SET-07` 对可逆设置执行修改前，记录该设置最近一次修改前的原值。
- `SET-08` 设置撤销应恢复该项记录的原值，而不是恢复某个统一默认值。
- `SET-09` 恢复记录保存在当前设备的公共应用数据位置，并由便携版与安装版共享。
- `SET-10` 恢复记录跨应用关闭、Windows 重启、发行版切换和便携版移动继续有效。
- `SET-11` 卸载安装版不自动撤销已经生效的设置，也不自动删除恢复记录。
- `SET-12` 用户可在应用设置中主动删除恢复记录；删除前应说明影响范围并再次确认。
- `SET-13` 存在等待重启或待恢复流程时，删除恢复记录按钮必须禁用并说明原因。
- `SET-14` 清空执行日志不得删除恢复记录。

### 8.3 目录更新后的撤销

- `SET-15` 更新系统设置目录不得自动改变当前电脑设置。
- `SET-16` 目录更新后，既有设置仍应使用原恢复记录撤销。
- `SET-17` 已从当前目录下架但仍有恢复记录的设置，继续显示在“可撤销的设置”中，只能撤销、不能再次应用。
- `SET-18` 已下架设置撤销成功后从可操作列表移除，只保留历史；撤销失败时保留入口、显示原因并允许重试。
- `SET-19` 撤销需要重启时保持“等待重启”，重启后验证恢复成功才移出可操作列表。
- `SET-20` 设置开始执行时保存设置稳定标识、目录版本、目标状态、验证规则、撤销语义和重启要求；目录随后更新或下架时，等待重启的验证和撤销仍使用该执行快照与恢复记录。

### 8.4 推荐总体优化

- `SET-21` 首版系统优化页同时提供一个“推荐总体优化”和可独立使用的系统设置项；总体方案不得成为使用单项设置的前置条件。
- `SET-22` 推荐总体优化是项目维护的可见选择组合，只引用已有系统设置项的稳定标识，不是隐藏脚本或不可拆分的原子操作；展开后必须显示全部成员及其默认选择。
- `SET-23` 用户可在开始前逐项勾选或取消；影响较小且适合大多数新装电脑的项目可以默认勾选，明显改变界面、习惯、功能或兼容性的项目默认不勾选。
- `SET-24` 用户开始总体方案后形成独立的系统优化执行记录，冻结所选设置、目录版本、执行顺序、验证规则和恢复规则；总体方案入口与单项入口共享每个设置的当前状态、恢复记录和历史，不得重复执行同一项。
- `SET-25` 所选设置按确定顺序执行；单项失败只阻止依赖它的项目，无依赖的后续项目继续。总结逐项显示成功、失败、跳过、等待重启、等待资源管理器重启和未执行，部分失败时总体结果不得笼统显示成功。
- `SET-26` 总体方案内每项分别保存修改前状态并可独立撤销；撤销一项不得改变同次执行中的其他项目，也不因单项失败自动回滚整组。
- `SET-27` Windows 自身的右键菜单模式、资源管理器界面等行为属于系统优化；第三方软件提供的资源管理器右键扩展属于该软件的软件优化。同一实际修改不得在两个页面重复提供。
- `SET-28` 系统设置项应声明项目已知适用的 Windows 版本范围；超出范围或版本无法识别时显示“可能不适用”，不得把社区方法描述为 Microsoft 提供的兼容性保证。
- `SET-29` “可能不适用”时，标准视图禁用普通应用操作并说明已知范围和安全处理方式；高级视图可在该项具备明确恢复规则时提供“仍然尝试”，执行前单独确认可能无效、界面异常或恢复失败的风险，且不得默认选择。

### 8.5 首版资源管理器相关设置

- `SET-30` 首版提供“Windows 11 经典右键菜单”设置项，方法来源与维护参考为 `https://www.zhihu.com/question/480356710`；项目已知适用范围为 Windows 11 至 25H2（含），该项纳入推荐总体优化但默认不勾选。
- `SET-31` 首版提供“Windows 10 风格资源管理器”设置项，方法来源与维护参考为 `https://zhuanlan.zhihu.com/p/690092810`；项目已知适用范围为 Windows 11 至 25H2（含），该项纳入推荐总体优化但默认不勾选。
- `SET-32` 两项都应直接提供“应用目标样式”和“恢复 Windows 11 默认样式”，由工作台执行系统设置目录中冻结的受控注册表操作；用户不需要下载、编辑、导入 `.reg` 或运行命令，网页内容也不得在运行时转化为执行指令。
- `SET-33` 无论应用还是恢复，执行前都保存该项当前状态和恢复数据；系统升级、目录更新、强制尝试失败或来源网页变化不得移除既有恢复入口。
- `SET-34` 两项变更完成后提供“立即重启资源管理器”和“稍后处理”；可合并的多项变更只需重启一次。立即重启前说明任务栏和已打开的资源管理器窗口会短暂关闭，重启后再验证目标状态。
- `SET-35` 用户选择稍后处理时状态为“等待资源管理器重启”，不得提前显示“已生效”，也不得建立阻止其他安全操作的 Windows 重启屏障；资源管理器或 Windows 重启、工作台重新打开后完成只读验证。Windows 10 上不提供这两项的应用操作，只说明系统已经使用相应原生界面，不写入 Windows 11 专用注册表设置。

## 9. 软件选择与安装

### 9.1 软件分类

- `SW-01` 软件安装页分为“基础软件”和“普通软件”两个区域。
- `SW-02` 基础软件是每台新装 Windows 默认勾选的一组软件。
- `SW-03` 用户可以取消基础软件，但工作台应提示取消可能造成的影响。
- `SW-04` 已选普通软件依赖某项基础软件时，工作台阻止取消该基础软件并说明依赖关系。
- `SW-05` 普通软件默认由用户自行勾选，也可以声明对其他软件的依赖。
- `SW-06` 首版只能选择精选软件目录中的软件，不能添加任意安装来源。

### 9.2 版本与已安装状态

- `SW-07` 每个软件默认提供“安装最新版”操作。
- `SW-08` “安装最新版”应解析当前来源可获取的最新稳定版；官网发布新稳定版后，下一次解析应反映新版本，而不要求发布新的工作台版本。
- `SW-09` 来源仍提供时，可以展示最新版之外的部分历史稳定版。
- `SW-10` 不展示 beta、preview、nightly 等预览版本。
- `SW-11` 用户选择历史版本时，应先明确来源，再选择该来源提供的版本。
- `SW-12` 执行前检测目标软件是否已存在；已经存在时标记为“已安装”并默认跳过。
- `SW-13` “已安装”只表示检测到软件存在，不表示它是最新版，也不得触发自动升级或重装。

### 9.3 安装批次

- `SW-14` 用户一次勾选的软件形成安装批次。
- `SW-15` 批次按确定顺序逐项串行执行；当前软件的来源处理、应用内下载、安装和结果确认完成或明确暂停后，才处理下一项，不预下载后续软件，也不并行启动多个安装程序。
- `SW-16` 单个软件失败时记录原因并继续执行无依赖阻塞的后续软件。
- `SW-17` 批次结束后支持对失败、来源失效、等待联网或被跳过的软件单独重试。
- `SW-18` 普通“停止批次”只阻止尚未开始的后续软件，并允许当前安装程序正常结束。
- `SW-19` 同时提供“强制终止”操作；执行前必须说明可能留下半安装状态的风险，并要求用户明确确认。
- `SW-20` 已完成安装不因停止或取消批次而自动回滚。
- `SW-21` 当前选择为可下载文件来源时，用户启动安装后，工作台在应用内解析并下载当前批次快照所指定的安装文件，正常路径不打开浏览器代替下载。
- `SW-22` 应用内下载持续显示软件名称、版本、已下载进度和当前状态；用户切换工作台页面不得中断下载。
- `SW-23` 安装文件下载完成并成为可用资源后，工作台将其作为当前批次项目启动；在该项目处理完成前不得下载或启动下一个软件。
- `SW-24` 工作台同时支持交互式安装和静默安装；不支持静默安装的软件继续通过官方安装界面由用户完成。
- `SW-25` 静默安装只适用于精选软件目录明确声明了受支持安装方式和结果检测规则的软件，不得把任意参数或用户输入命令传给管理员安装进程。
- `SW-26` 首版不承诺所有软件都能静默安装；静默能力缺失不得阻止该软件通过交互式安装完成。
- `SW-27` 精选软件目录确认支持静默安装的软件，在标准视图默认使用静默安装；高级视图允许用户在开始前改为交互式安装。
- `SW-28` 需要用户选择安装组件、安装路径或其他必要选项的软件默认使用交互式安装，不得为了表面上的全自动而跳过必要选择。
- `SW-29` 静默安装失败时，将当前软件标记为“安装失败”，提供重试静默安装和改用交互式安装的入口，不自动启动交互式安装；无依赖阻塞的后续软件继续执行。
- `SW-30` 静默安装或官方交互式安装程序结束后，工作台应按精选软件目录中的结果检测规则自动检查目标软件是否已经安装。
- `SW-31` 能可靠确认安装成功时，将当前软件记录为完成并继续下一项；能可靠确认失败时标记为“安装失败”，并按现有批次规则继续不受影响的软件。
- `SW-32` 无法可靠判断结果时，将当前软件标记为“安装结果待确认”并暂停批次，提供“已完成”和“重试”；用户选择及其时间必须写入历史和执行日志，不得伪装成自动检测成功。
- `SW-33` 当前选择为托管安装来源时，工作台调用该来源的官方取得与安装机制，不把它伪装成可缓存安装文件；进度和结果仍纳入当前串行批次。

### 9.4 安装阶段偏好

- `SW-34` 软件安装项可以定义由精选软件目录约束的安装阶段偏好；这些偏好只控制项目明确支持的安装器选项，不得接受任意安装器操作、脚本、命令或参数。
- `SW-35` 搜狗输入法使用 `https://shurufa.sogou.com/windows` 作为 Windows“安装最新版”的官网来源依据，其安装项提供两个推荐选择：自定义安装时关闭“开启搜索候选，让输入和信息获取更简单”，以及安装完成时不安装“腾讯元宝”。
- `SW-36` 搜狗的两个安装阶段选择在安装前明确展示并默认勾选，且属于首版必达能力；首版内置目录必须记录并支持构建该目录时从官网解析到的当前稳定安装器基线，对目录声明支持的搜狗安装器版本，工作台必须自动完成选择。没有可靠自动控制方式时不得把该安装器版本列为首版受支持版本，也不得以手动提示代替发布验收。
- `SW-37` 搜狗安装阶段偏好与安装后的“搜狗输入法推荐优化”是两个阶段：前者属于软件安装，后者只在确认搜狗已经安装后提示和执行；任一阶段失败不得改写另一阶段的真实结果。
- `SW-38` 已受支持安装器在实际运行中因界面变化或自动控制失败时，工作台应暂停、明确记录安装阶段偏好失败，并提供官方安装器中的应急手动步骤；该应急路径不得记为自动完成，也不改变 `SW-36` 的首版能力门槛。

## 10. 软件来源与版本快照

### 10.1 来源选择

- `SRC-01` 每个软件独立记录其安装来源，不使用一个后端覆盖全部软件。
- `SRC-02` 默认来源优先级依次为软件官网安装包、官方 GitHub Release、Microsoft Store、`winget` 和其他明确来源。
- `SRC-03` 目录维护者可依据单个软件的实际发布方式调整其来源顺序。
- `SRC-04` 项目第三方包源是项目 GitHub 中维护的备用来源，不覆盖官方或既定来源。
- `SRC-05` 用户可以在安装前主动选择项目第三方包源。
- `SRC-06` 首选来源不可用时，当前软件暂停并显示包含来源名称和链接的可选来源；工作台不得静默换源。
- `SRC-07` 选择项目第三方包源不增加额外风险确认，但工作台也不执行来源审查、签名验证或哈希校验。

### 10.2 来源失效与快照

- `SRC-08` 安装批次开始时冻结该批次所用的目录、依赖、来源、链接、版本和架构信息。
- `SRC-09` 批次执行中发生目录更新或官网链接变化，不得改写当前批次快照。
- `SRC-10` 网络可用时，快照中的链接、发布数据或资源无效，应将该软件标记为“来源失效”，继续执行其他软件。
- `SRC-11` 用户重新选择来源并重试时，重新获取该来源当前版本和链接，生成新的单项批次快照。
- `SRC-12` 原批次快照保持只读，用于历史追溯。
- `SRC-13` 项目备用包应记录明确的软件版本；官方来源已有更新而备用包尚未同步时，显示“备用包版本较旧”。

### 10.3 官网最新版

- `SRC-14` 精选软件目录可以把官网发布页记录为软件的首选来源依据；QQ 使用 `https://im.qq.com/index/#/windows`，搜狗输入法使用 `https://shurufa.sogou.com/windows` 作为各自 Windows 官网发布页。
- `SRC-15` 用户选择“安装最新版”时，工作台应从官网发布页或该页面使用的官方发布数据取得当前最新稳定版本，并选择适用于当前系统架构的官方安装文件；不得把某条会随版本变化的安装文件直链长期视为最新版。
- `SRC-16` 官网发布新稳定版或更换安装文件地址后，工作台下一次联网解析应采用新的官方安装文件，不要求先更新工作台或目录包。
- `SRC-17` 网络可用但官网改版、发布数据无效或无法解析时，只暂停当前软件并标记为“来源失效”，提供“重新尝试”“打开官网”和“选择其他来源”；不得静默换源，也不得把旧直链当作当前最新版继续使用。
- `SRC-18` 同一官网来源同时提供完整安装包和在线安装器时，默认选择完整安装包。
- `SRC-19` 官网没有可用完整安装包时，允许使用官方在线安装器，但必须明确标示“安装过程需要联网”；网络不可用时不得启动并将该软件标记为“等待联网”。
- `SRC-20` 在线安装器即使已经下载到本机，也不得标记为“离线可用”；只有安装所需文件和依赖完整时，资源才属于离线软件包。
- `SRC-21` 官网最新版解析完成后，工作台必须在安装前向用户显示解析所得的软件版本、官网来源和联网要求，不得等到安装启动后才披露。
- `SRC-22` 每个官网软件来源必须明确指定软件发行分支；首版没有另行说明时，选择面向普通个人用户的官方个人版。
- `SRC-23` “安装最新版”只能在目录指定的软件发行分支内比较稳定版本，不得因为企业版、国际版或其他分支版本号更高而改装成另一产品分支。
- `SRC-24` 精选软件目录必须把每个来源标记为可下载文件来源或托管安装来源；同一软件的不同来源可以采用不同类型。
- `SRC-25` 官网发布页、官方 GitHub Release 和项目第三方包源在能提供具体安装文件时采用应用内下载；Microsoft Store、`winget` 等托管安装来源使用各自官方机制，不进入软件包缓存。
- `SRC-26` 来源访问失败时先区分网络状态：设备离线或连接中断时标记为“等待联网”；网络可用但页面、发布数据或资源无效时才标记为“来源失效”。

## 11. 架构兼容

### 11.1 默认行为

- `ARCH-01` 工作台每次启动以及恢复重启屏障流程时重新检测 Windows 系统架构。
- `ARCH-02` x64 Windows 默认只选择 x64 兼容软件包，不显示多余的架构提示；软件只有 ARM64 包时显示不兼容并禁用。
- `ARCH-03` ARM64 Windows 优先选择 ARM64 软件包。
- `ARCH-04` ARM64 Windows 上某软件没有 ARM64 包、只有 x64 包时，才显示架构回退提示。
- `ARCH-05` 默认回退策略为“优先 ARM64，缺少时提示后回退 x64”。
- `ARCH-06` 多个软件需要回退时，默认按软件逐项确认，不合并为整批确认。
- `ARCH-07` 用户拒绝某项回退时，将该软件标记为“用户拒绝架构回退”并跳过，批次继续。
- `ARCH-08` 单独重试时按当前来源、版本和架构偏好重新评估，并重新请求必要确认；之前拒绝不成为永久设置。

### 11.2 用户偏好

- `ARCH-09` 应用设置提供三种架构偏好：
  - 优先 ARM64，缺少时提示后回退 x64；
  - 始终优先 ARM64，缺少时自动使用 x64；
  - 始终优先 x64。
- `ARCH-10` ARM64 用户选择“始终优先 x64”时，软件项显示存在 ARM64 包的非阻断提示，不再逐项弹窗。
- `ARCH-11` 用户在单次重试中手动改选 x64，只影响该软件本次重试，不改变全局偏好。

### 11.3 检测失败与架构变化

- `ARCH-12` 无法可靠检测系统架构时，只暂停需要架构选择的软件；系统优化和明确不区分架构的软件仍可执行。
- `ARCH-13` 检测恢复后，相关软件恢复可选，但不得自动改写或恢复旧批次；重新勾选或重试时生成新快照。
- `ARCH-14` 缓存可保留多个架构的资源，但只有当前系统兼容的包可安装；其他包标记为“不适用于当前系统”。
- `ARCH-15` 检测到系统架构变化时，未完成旧批次中不兼容的项目标记为“架构已变化”并暂停。
- `ARCH-16` 已完成安装的软件继续显示“已安装”，工作台不因架构变化自动替换或判定失败。
- `ARCH-17` 只有检测到架构切换时，软件页临时显示已安装软件的实际架构；用户确认或关闭提示后恢复普通显示。
- `ARCH-18` 架构切换及用户处理结果继续保留在执行日志中。

## 12. 离线资源与缓存

### 12.1 离线执行

- `OFF-01` 工作台在完全断网时仍能启动、浏览本地信息、执行本地可用的系统优化和软件安装。
- `OFF-02` 网络可用时默认优先使用联网来源。
- `OFF-03` 软件目录逐项标记“项目提供离线包”“仅能联网安装”“暂不支持安装”；离线资源版内置包另标记为“本机内置”。
- `OFF-04` 可离线执行的软件包必须声明已包含安装所需依赖和文件。
- `OFF-05` 依赖不完整或无法取得时，该软件标记为“等待联网”，不得启动安装。
- `OFF-06` 某个离线依赖不可用时，该软件和依赖它的后续软件等待联网；没有依赖关系的软件和系统优化继续。
- `OFF-07` 项目只承诺维护最新版和部分历史稳定版本，不承诺完整历史版本库。
- `OFF-08` 离线资源版内置软件包只能通过兼容的有效软件目录使用；当前目录已移除对应项时，资源仍可显示为本机存在但不可安装，用户可主动回退到兼容的有效目录，不得绕过目录直接执行。

### 12.2 缓存内容与期限

- `CACHE-01` 便携版与安装版共享工作台下载的软件包缓存。
- `CACHE-02` 缓存按软件稳定标识、版本、架构和来源区分，不能用另一来源的同版本文件替代用户已选择的来源。
- `CACHE-03` 默认在下载 7 天后自动删除缓存；应用设置提供立即删除、7 天、30 天和不自动删除四种选项。
- `CACHE-04` 用户可随时主动清理缓存。
- `CACHE-05` 清理只删除工作台下载缓存，不删除离线资源版随包内置的离线软件包。
- `CACHE-06` 联网执行“安装最新版”时，不得因为本地存在旧缓存而回退。
- `CACHE-07` 断网时只允许使用明确具备离线安装条件的缓存，并显示“使用缓存版本”和具体软件版本，不得显示为“安装最新版”。

### 12.3 缓存位置

- `CACHE-08` 默认缓存位置使用系统目录。
- `CACHE-09` 用户可以选择本机其他磁盘、网络共享路径或 U 盘等可移动位置。
- `CACHE-10` 切换位置不自动移动或删除旧位置内容，并提供手动清理入口。
- `CACHE-11` 自定义位置不可用、无权限或空间不足时，暂停需要下载的软件并提示用户，不得静默改用其他位置。
- `CACHE-12` 应用内下载任何软件包或使用软件包缓存前检查目标位置的可用空间；不足时跳过该软件，不启动可能中途失败的下载或安装。

### 12.4 下载完整性与并发

- `CACHE-13` 多个工作台实例可以共享同一缓存位置。
- `CACHE-14` 下载中的资源使用临时文件；只有完成标记后的资源才可供其他实例安装。
- `CACHE-15` 网络中断、程序关闭或存储介质断开后删除未完成临时文件，下次重新下载。
- `CACHE-16` 软件包下载失败时自动重试 2 次；仍失败则记录原因、继续批次并提供单项重试。
- `CACHE-17` 用户在下载阶段停止批次时，立即取消当前下载并删除临时文件，停止后续软件；已完成安装不回滚。
- `CACHE-18` 用户暂停当前下载时保留未完成临时文件，但该文件不得供安装或其他工作台实例使用；继续下载时，所选可下载文件来源支持续传则从已有进度继续。
- `CACHE-19` 所选可下载文件来源不支持续传或原下载资源已经变化时，“继续下载”应先说明需要重新下载，再删除旧临时文件并从头开始；不得把不同版本内容拼接为一个安装文件。
- `CACHE-20` 暂停下载只在当前工作台运行期间保留进度；关闭工作台时删除暂停项目的未完成临时文件，不提供跨启动续传。
- `CACHE-21` 下载完成的官方完整安装包、官方在线安装器和项目离线软件包均可进入软件包缓存，并遵守同一套默认 7 天及用户自定义保留期限。
- `CACHE-22` 再次安装相同软件、版本、架构和来源时，可以直接复用兼容的已完成缓存；当前官网已有新稳定版时，“安装最新版”仍按 `CACHE-06` 下载新版。
- `CACHE-23` 缓存在线安装器不改变其联网要求；断网时不得因为安装器文件已存在就将它作为可离线安装资源启动。

## 13. 目录包

### 13.1 类型与更新边界

- `CAT-01` 目录数据分为“软件与驱动目录包”“系统设置目录包”和“软件优化目录包”。
- `CAT-02` 三类目录包独立版本化、独立更新、独立回退和独立手动导入，互不联动。
- `CAT-03` 软件与驱动目录包包含软件、驱动入口、来源、依赖、版本和稳定标识；存在安装阶段偏好时，还必须包含偏好定义、支持的安装器版本、受控执行器引用和结果验证规则。该目录不包含系统设置或安装后的软件优化方案。
- `CAT-04` 系统设置目录包只包含系统优化方案、系统设置项、成员与设置依赖、适用范围、来源说明、风险、执行、验证、恢复、重启要求、版本和稳定标识，不包含软件、驱动、软件优化方案、缓存或架构信息。
- `CAT-05` 三类目录随应用发行版提供内置版本，保证首次启动及离线可用。
- `CAT-06` 用户可主动触发目录更新或手动导入；不得后台静默更新。
- `CAT-07` 更新失败时保留当前可用目录并记录失败；成功更新后保留上一份可用版本用于回退。

### 13.2 身份与兼容

- `CAT-08` 每个软件、系统优化方案、系统设置项、软件优化方案和软件优化选项分别拥有不可变、不可复用的稳定标识。
- `CAT-09` 改名、链接或实现方式变化但身份及关键行为语义不变时保留稳定标识；真正替换目标或改变安装、系统优化、软件优化、验证或撤销语义时使用新标识。
- `CAT-10` 每类目录包含模式版本和必需字段集合。
- `CAT-11` 加载时使用已识别字段并忽略未知字段；缺少必需字段、无法解析或稳定标识冲突时拒绝整包。
- `CAT-12` 拒绝更新包时继续使用上一份可用目录。

### 13.3 局部错误

- `CAT-13` 不存在的依赖或循环依赖只影响相关软件项；这些项目显示“目录配置错误”并禁用，其他项目继续可用。
- `CAT-14` 软件页应直接显示依赖不存在或循环依赖的原因，并同时写入执行日志。
- `CAT-15` 目录配置错误项不得提供强制安装按钮。
- `CAT-16` 目录修复并重新加载后，错误项自动恢复可选，但不得自动加入已经创建的批次。
- `CAT-17` 局部依赖错误不触发整包回退；整体无法解析、缺少必需字段或稳定标识冲突才拒绝整包。

### 13.4 无有效目录与恢复

- `CAT-18` 首次启动没有有效软件与驱动目录时，软件页和驱动目录不可操作，即使本地已有缓存也不能绕过目录安装。
- `CAT-19` 任一类目录不可用时只禁用由该目录提供的新操作，另外两类目录、历史、日志、缓存和已知紧急撤回信息继续可用，并提供重试更新或手动导入入口。
- `CAT-20` 恢复有效目录后，按稳定标识、版本和架构重新识别缓存；此前被阻止的批次不自动恢复，用户需重新选择。

### 13.5 手动导入与降级

- `CAT-21` 手动导入前显示文件路径、目录版本和项目数量，并提示无法验证文件是否来自项目；同时明确目录会决定工作台随后可执行的管理员操作，用户确认后才继续。
- `CAT-22` 工作台只验证目录结构与内容规则，不提供签名或哈希来源证明。确认加载后，该文件成为当前有效目录；首版仍不提供目录编辑器，也不正式支持用户自制目录。
- `CAT-23` 用户可以导入低于当前版本的目录；确认前应列出将失去的新增或更新项目。
- `CAT-24` 降级后保留被替换目录用于回退。
- `CAT-25` 当前目录缺少的软件保留历史和已安装状态，但显示“已从目录移除”且不能再选择安装。

### 13.6 系统设置目录更新

- `CAT-26` 更新系统设置目录前，分别展示新增、变更和下架项目，用户确认后才加载。
- `CAT-27` 任一类目录的升降级不得改变另外两类目录。
- `CAT-28` 目录更新只影响之后创建的批次或主动执行的设置和优化，不修改正在执行的快照和当前系统状态。

### 13.7 软件优化目录

- `CAT-29` 软件优化目录包包含软件优化方案、目标软件关联、适用版本、选项、选项关系、风险说明、执行规则和状态检测规则，不包含软件安装项、驱动入口或系统设置项。
- `CAT-30` 软件优化目录包在应用设置中拥有独立的更新、手动导入和回退入口，不得依赖软件与驱动目录或系统设置目录同时更新。
- `CAT-31` 软件优化目录更新本身不得自动执行任何优化，也不得改变已经生效的软件配置。
- `CAT-32` 软件优化目录必须自行提供目标软件的稳定标识、安装检测和版本检测规则，并可为非首版必达目标提供只用于识别且明确标为“暂无可用优化”的目标描述；它可以选择关联软件安装项稳定标识，但官网、Microsoft Store、`winget` 或用户自行安装的软件不得因缺少该关联而无法识别或优化。首版声明支持版本内的首版必达目标缺少可执行方案时必须判定为目录或实现错误。
- `CAT-33` 软件优化目录必须为方案和选项声明稳定标识，并可声明方案级与选项级的必需关系和冲突关系；批次快照和历史使用这些标识跨目录版本追踪实际选择。
- `CAT-34` 目标检测、稳定标识、依赖、冲突、执行或状态检测规则无效时，只将受影响方案标为“目录配置错误”并禁用；页面和日志必须说明原因，且不得提供强制执行，其他有效方案继续可用。
- `CAT-35` 没有有效软件优化目录时，软件优化页保留不可操作说明、历史入口和已知紧急撤回状态，但不得识别或执行新方案；软件安装、驱动、系统优化及其他页面继续可用。
- `CAT-36` 恢复有效软件优化目录后重新识别目标软件和方案状态，不自动恢复此前被阻止的优化选择或批次；用户重新选择时按当前目录创建新快照。

### 13.8 系统优化方案与来源

- `CAT-37` 系统设置目录可以定义系统优化方案；每个方案声明稳定标识、成员系统设置项稳定标识、执行顺序和默认勾选状态，但不得复制成员的执行、验证、恢复或当前状态。
- `CAT-38` 系统优化方案引用的任一成员缺失、无效或形成循环时，禁用该总体方案并显示“目录配置错误”，不得静默跳过成员后把残缺组合当作完整方案执行；其他有效的独立系统设置项继续可用。
- `CAT-39` 系统设置项可声明说明来源 URL、项目已知 Windows 适用范围、强制尝试规则、资源管理器或 Windows 重启要求及恢复规则；来源 URL 只用于用户查看和维护者审核，不是运行时脚本、注册表文件或自动更新通道。
- `CAT-40` 系统优化或软件优化的说明与方法来源网页内容变化，不得自动改变目录、当前选择、执行规则或电脑状态；只有维护者审核并发布新的系统设置目录或软件优化目录版本，且用户主动加载后，之后的新执行才采用新规则，既有快照和恢复记录保持不变。软件官网发布数据用于解析“安装最新版”时仍按 `SRC-14` 至 `SRC-26` 处理。

### 13.9 首版内置目录兼容基线

- `CAT-41` 首版内置的软件与驱动目录和软件优化目录必须共同声明至少一个可在目录构建时从官网取得的搜狗稳定安装器基线；该安装器产生的已安装版本必须落入完整覆盖 `OPT-61` 的方案支持范围。支持范围为空或两类目录的基线不相交时属于目录配置错误并阻止首版发布。

## 14. 重启、取消与恢复

- `RST-01` 初始化操作需要重启 Windows 才能完全生效或验证时，状态为“等待重启”；只需重启资源管理器时使用独立的“等待资源管理器重启”，不建立 Windows 重启屏障。
- `RST-02` 后续操作必须等待重启时建立重启屏障，分别保存推荐流程记录、可能存在的系统优化执行记录、安装批次或优化批次，以及所有已执行但等待重启的操作状态。
- `RST-03` 用户重启并登录后，工作台一次性重新打开并载入暂停内容。
- `RST-04` 恢复后可以自动完成无副作用的只读检测和既有结果验证，但启动任何新的修改步骤前必须等待用户明确点击“继续”；不得自动执行剩余管理员操作。
- `RST-05` 恢复时重新检测系统架构、必要硬件状态、本地资源可用性，以及待恢复优化涉及的软件是否存在、实际版本、进程状态、目标状态和当前有效紧急撤回信息。
- `RST-06` 用户可以取消等待重启或待恢复的推荐流程、系统优化执行记录、安装批次或优化批次；取消前显示将放弃的后续操作、已经完成且不会自动恢复的修改，以及仍待重启验证的操作，并要求确认。
- `RST-07` 取消只放弃从未开始的后续操作；已经安装的软件、已经生效的设置、已经完成的软件优化、恢复记录，以及已经执行但仍等待重启验证的操作状态保持不变，直至完成只读验证或由用户另行处理。
- `RST-08` 已取消的流程记录、系统优化执行记录、安装批次和优化批次分别作为只读历史保留，并记录取消时的阶段与逐项状态。
- `RST-09` 用户可从已取消安装批次选择未完成或失败的软件创建新批次，新批次按当前目录、来源、版本、依赖和架构重新评估；未执行设置仍作为新的独立操作重新选择，不继续旧执行记录。
- `RST-10` 原批次及其快照不得被改写。
- `RST-11` 已从当前目录移除的软件不能加入重建批次；其他有效项目不受影响。
- `RST-12` 用户从已取消优化批次重新处理失败或未执行选项时，必须依据当前软件优化目录、目标软件实际版本和状态、选项关系及有效紧急撤回通知创建新优化批次；普通下架或紧急撤回方案只保留原历史，不提供可执行重试。
- `RST-13` 恢复后必须先对已经执行或待重启的步骤完成只读验证，再允许启动后续修改；紧急撤回不阻止验证既有结果，但必须阻止所有受影响且尚未开始的新修改。

## 15. 历史、日志与状态

### 15.1 执行历史

- `HIST-01` 历史应保留批次级结果、目录和来源快照，以及每项操作的最终或暂停状态。
- `HIST-02` 已取消批次和已下架项目继续保留只读历史。
- `HIST-03` 重试创建新的执行记录，不覆盖原失败或暂停记录。
- `HIST-04` 软件安装和软件优化结果都应区分自动检测确认和用户确认；用户对“安装结果待确认”或“优化结果待确认”的选择必须作为不可改写的处理记录保留。
- `HIST-05` “历史与日志”页完整保存并展示优化批次、方案和选项快照、强制执行、强制关闭、强制终止、停止、取消、重启交接、正常关闭暂停、异常退出、最后已持久化步骤、重新检测结果、自动或用户确认、失败、普通下架及紧急撤回记录；软件优化页的最近结果必须链接到对应完整记录。
- `HIST-06` 系统优化历史应保存从总体方案或单项入口发起、实际选择的系统设置项、目录与执行快照、逐项结果、修改前状态、撤销结果、Windows 版本与构建、项目已知适用范围、正常或强制尝试、风险确认、资源管理器重启选择及最终验证结果。

### 15.2 执行日志

- `LOG-01` 执行日志只保存在本机，不自动上传。
- `LOG-02` 日志默认永久保留，不按期限自动删除。
- `LOG-03` 日志尽量详细，至少记录时间、操作、结果、退出码、必要输出、来源、版本、架构、方案与选项标识、强制操作、确认方式和用户处理结果等上下文；正常关闭暂停与异常退出必须区分，并记录最后已持久化步骤及恢复后的重新检测结果。
- `LOG-04` 架构切换日志至少包含切换前架构、切换后架构、检测时间、触发来源和用户处理结果。
- `LOG-05` 用户可主动导出日志，并可在应用设置中立即清空。
- `LOG-06` 清空日志只删除诊断资料，不删除恢复记录、安装或优化历史、批次恢复状态、已生效设置、已完成优化状态或有效紧急撤回信息。
- `LOG-07` 首版不采集或发送使用遥测；执行日志不得被作为遥测自动上传。
- `LOG-08` 系统优化日志至少记录系统优化方案与设置稳定标识、来源入口、Windows 版本与构建、适用性判断、修改目标、应用或恢复方向、强制尝试确认、资源管理器重启选择和逐项验证结果；不得只记录总体方案“成功”而省略成员结果。

### 15.3 统一状态语义

界面、历史和日志应一致使用以下状态：

| 状态 | 含义 |
| --- | --- |
| 无适用项 | 推荐流程某阶段当前没有可执行内容，可以直接跳过 |
| 已安装 | 执行前检测到目标软件已经存在，不代表是最新版 |
| 已生效 | 系统设置当前已经符合目标值 |
| 已优化 | 软件优化选项当前已经符合方案目标，不表示一定由工作台修改 |
| 部分完成 | 总体方案或批次中只有部分项目完成，必须查看逐项结果 |
| 需要重新优化 | 目标软件升级或状态变化后，原先符合的优化目标已不再满足 |
| 版本不适用 | 目标软件版本未知或超出软件优化方案声明的适用范围 |
| 可能不适用 | Windows 版本超出系统设置项的项目已知适用范围，普通执行已禁用 |
| 方案已下架 | 软件优化方案已从当前目录移除，不能用于新的优化操作 |
| 方案已紧急撤回 | 软件优化方案存在已确认的严重风险，所有尚未执行的相关步骤被阻止 |
| 安装失败 | 已执行软件安装，但未达到预期安装状态 |
| 优化失败 | 已尝试执行软件优化选项，但没有达到方案目标 |
| 未执行 | 已选择的初始化步骤尚未开始，保留具体阻止或停止原因 |
| 暂不支持自动处理 | 非首版必达项当前没有可靠受控执行规则；该状态不能用于满足首版发布条件 |
| 安装结果待确认 | 安装程序已经结束，但工作台无法可靠判断结果，等待用户选择“已完成”或“重试” |
| 优化结果待确认 | 软件优化步骤已经结束，但工作台无法可靠判断是否达到目标，等待用户检查后选择“已完成”或“重试” |
| 来源失效 | 网络可用，但批次快照中的链接、发布数据或资源已经无效 |
| 等待联网 | 缺少网络且没有可用本地资源，尚未执行 |
| 等待重启 | 操作需要重启 Windows 后才能完成或验证 |
| 等待资源管理器重启 | 系统设置已经写入，等待资源管理器或 Windows 重启后完成验证 |
| 已恢复 | 系统设置已验证恢复到该次修改前记录的状态 |
| 目录配置错误 | 项目存在无效或循环依赖，禁止执行 |
| 用户拒绝架构回退 | ARM64 用户拒绝为该软件使用 x64 包 |
| 架构已变化 | 旧批次项目不再适用于当前系统架构 |
| 已取消 | 用户取消了待恢复批次，记录只读保留 |
| 已从目录移除 | 项目不在当前目录中，只保留历史或撤销能力 |
| 未识别 | 本次硬件检测没有生成可用概览 |

## 16. 应用与目录更新

### 16.1 应用更新

- `UPD-01` 用户可以从 GitHub 手动下载新版本，也可以在工作台内主动触发一键更新。
- `UPD-02` 应用不得后台静默下载或强制替换自身。
- `UPD-03` 一键更新前说明发行包未签名且项目不提供完整性校验信息。
- `UPD-04` 下载、替换或新版启动失败时自动恢复上一版本。
- `UPD-05` 应用更新和回退不得删除或改写设备级恢复记录、执行历史和待恢复状态。

### 16.2 更新彼此独立

- `UPD-06` 应用更新、软件与驱动目录更新、系统设置目录更新、软件优化目录更新是四个独立动作。
- `UPD-07` 任一更新失败不得清空其他当前数据，也不得改变已经生效的系统设置或软件优化结果。

## 17. 语言

- `LANG-01` 首个公开版本只显示简体中文。
- `LANG-02` 界面文字、目录展示内容、状态名称和用户提示应保留后续增加语言的能力，不与简体中文写死绑定。
- `LANG-03` 增加语言时不得要求重做安装、恢复、目录或批次等核心流程。

## 18. 应用设置页

首版设置页至少提供：

- 应用主动更新入口；
- 软件与驱动目录、系统设置目录、软件优化目录各自的更新、导入与回退入口；
- ARM64 软件包架构偏好；
- 缓存保留期限；
- 缓存位置与手动清理；
- 执行日志导出与立即清空；
- 恢复记录查看与主动删除。
- 标准视图与高级视图的即时切换及偏好保存。

危险或不可逆操作必须说明影响并要求确认；因待恢复状态而不可执行的操作应禁用并显示原因。

## 19. 验收场景

### A. 联网 x64 新设备

用户以管理员身份启动在线版，依次完成驱动阶段、从推荐总体优化中应用若干系统优化、串行安装基础和普通软件，并进入软件优化阶段处理适用方案。流程总结能区分完成、跳过和失败，当前仍可执行的失败项可单独重试。

### B. ARM64 软件包回退

ARM64 Windows 优先安装 ARM64 包；某软件只有 x64 包时才提示回退。用户拒绝后该项被跳过且批次继续，单独重试时重新评估。

### C. 完全离线环境

离线资源版无需预装运行时即可启动。本机内置且依赖完整的软件可安装；缺少资源的软件等待联网，系统优化和无依赖项目继续。

### D. 下载中断与共享缓存

下载失败最多自动重试 2 次，半成品不能被另一个实例使用。网络或 U 盘中断后临时文件被清理，其他软件继续，失败项可重试。

### E. 驱动要求重启

用户从驱动页启动厂商助手后，工作台保留“驱动交接中”状态。外部操作导致网络或显示短暂变化、应用关闭或重启时，流程记录不丢失；返回后由用户选择完成、需要重启或暂时跳过，工作台不自行推断。

### F. 系统优化撤销跨版本保留

用户用便携版应用系统优化，改用安装版并更新设置目录后，仍能按原设置执行快照和恢复记录完成重启验证或撤销。已下架设置继续提供撤销，成功验证后只保留历史。

### G. 无效目录包

整体无法解析、缺少必需字段或稳定标识冲突时拒绝整包并使用上一版；单项依赖错误只禁用相关软件并显示原因，不影响其他项目。

### H. 来源失效

批次中的官网链接失效时不静默换源。该项标记失败，其他项目继续；用户选择新来源后生成新的单项快照，原记录不变。

### I. 停止与强制终止

普通停止让当前安装器结束并停止后续项目；强制终止前显示半安装风险。两种方式都不回滚已经完成的安装。

### J. 发行包切换与更新失败

便携版和安装版可共享恢复记录与缓存。一键更新失败时恢复旧版本，已有历史、恢复记录和待恢复流程不丢失。

### K. 取消待恢复流程

用户在系统优化已执行但仍等待重启验证时取消推荐流程。只有未开始的后续操作被放弃；该设置及其恢复记录继续等待验证，流程记录及已经实际创建的系统优化执行记录、安装批次或优化批次分别保留只读历史。

### L. 导入目录与内置资源

用户导入目录前看到来源无法验证及其会决定管理员操作的风险。当前有效目录移除某个离线资源版内置软件后，该资源不能绕过目录安装；用户切换到兼容的有效目录后才可重新使用。

### M. QQ 官网最新版应用内下载

用户选择 QQ“安装最新版”后，工作台从 `https://im.qq.com/index/#/windows` 对应的官方发布数据取得普通个人版当前稳定版本和适用架构的官方安装文件。安装前显示版本、官网来源和联网要求；下载在工作台内完成，进度条、已下载量、总大小、速度和预计剩余时间持续可见，不以打开浏览器代替下载。官网发布新稳定版后再次解析应取得新版；官网无法解析时暂停 QQ，并提供重新尝试、打开官网和选择其他来源。

### N. 静默安装、结果确认与缓存

支持静默安装的软件在标准视图默认静默完成，高级视图可改用官方安装界面；静默失败时不自动弹窗，而是提供静默重试和打开官方安装程序。安装程序结束后自动检测结果，无法判断时进入“安装结果待确认”。多软件批次同时显示当前下载和整批进度；暂停可以在当前运行期间续传，关闭工作台则清理未完成文件。完成的相同软件、版本、架构和来源可按现有期限复用缓存，缓存的在线安装器仍明确要求联网。

### O. 正常软件优化

用户打开软件优化页后，工作台识别由官网安装程序、Microsoft Store、`winget` 或用户此前自行安装的目标软件，只显示当前已安装软件。适用方案按状态分组，低影响推荐选项默认勾选、高影响选项默认不勾选；用户查看按软件分组的确认摘要并明确开始后，单个或多个方案形成优化批次串行执行。只有验证达到目标的选项显示“已优化”，页面最近结果与“历史与日志”中的同一批次记录可以互相定位。

### P. 优化部分失败且不撤销

同一优化批次内，前一选项已经达到目标、后一选项执行失败时，工作台保留已经完成的修改，不自动恢复，也不把整个软件笼统标为成功或失败；无依赖阻塞的后续方案继续执行。批次结果逐项显示“已优化”“优化失败”或“未执行”。用户重试时，工作台先把重试选择和原批次剩余状态写入不可改写的历史并结束原批次，再按当前目录、软件版本与状态、选项关系和有效紧急撤回信息重新判断，创建新的单项优化批次。

### Q. 版本不适用与强制执行

工作台检测到目标软件版本未知或超出方案范围时显示“版本不适用”。标准视图不提供普通执行命令，只显示原因、安全处理方式和高级视图入口；高级视图提供单独的“强制执行”，并在执行前说明可能无效、损坏配置且无法撤销。用户确认后，历史与日志保存实际软件版本、方案范围、风险提示版本和确认结果，并明确区别于正常执行。

### R. 强制关闭与强制终止优化

方案要求目标软件退出但检测到它仍在运行时，两种视图都先提示用户保存内容、正常关闭并重新检测；只有高级视图可以在单独确认丢失未保存内容的风险后“强制关闭并继续”。另一个优化步骤卡住时，高级视图提供“强制终止优化”，确认中说明可能留下不完整配置。两项命令的名称、确认、结果和日志事件必须不同，普通“停止优化”仍等待当前步骤安全结束。

### S. 优化关闭、重启恢复与取消

用户在优化步骤执行期间正常关闭工作台时，工作台先等待当前步骤到达安全结束点，把后续步骤保持为待处理，再保存批次并退出；应用异常退出而无法确认结果时，重新打开后先把该步骤标为“优化结果待确认”并重新检测，不直接重跑。优化选项要求先重启才能安全继续时，工作台建立重启屏障，保存流程记录、优化批次和待验证状态，不自动重启。重启或重新打开后可以自动完成既有步骤的只读验证，并检测目标软件、版本、进程、目标状态和有效紧急撤回信息，但启动新修改前仍等待用户明确继续。第一实例中的安装或优化批次处于执行、待确认、等待重启或待恢复状态时，第二实例不能启动另一批次，只能进入现有批次进度；原批次完成、停止结束或取消后才释放。用户取消时只放弃尚未执行的步骤；已经完成或仍待重启验证的修改不恢复，原优化批次作为只读历史保留。

### T. 软件优化方案普通下架

软件优化目录普通更新移除某个方案时，该方案不能加入新的优化批次，也不能由失败项重试入口重新执行；已经开始的批次仍按用户确认的快照完成。既有批次和历史保留并显示“方案已下架”，目录更新不得改变已经完成的软件配置或改写原记录。

### U. 软件优化方案紧急撤回

工作台取得更新修订的紧急撤回通知后，立即阻止受影响方案的新执行，并在执行中、暂停或等待重启的既有批次里停止所有尚未开始的相关步骤，即使这些步骤已包含在批次快照中。已经完成的修改不自动恢复，历史继续保留；页面、流程总结和日志显示撤回原因、受影响内容、通知修订及逐项处理结果。

### V. 离线时使用陈旧撤回信息

设备离线或紧急撤回通知检查失败时，工作台继续应用设备上次成功取得的有效紧急撤回信息，显示取得时间并提示信息可能不是最新；已知撤回方案继续受阻。设备没有本地通知时，界面明确显示无法完成最新安全检查，不把未知状态描述为“没有风险”。

### W. 推荐总体优化部分失败与逐项撤销

用户展开推荐总体优化，调整默认选择后开始执行。三项中一项成功、一项失败、一项因依赖未执行时，无依赖后续项继续，总体结果显示“部分完成”并列出逐项原因；成功项可以单独恢复到修改前状态，且不改变同次执行的其他设置。

### X. Windows 11 25H2 右键菜单与资源管理器

Windows 11 25H2 上，“Windows 11 经典右键菜单”和“Windows 10 风格资源管理器”出现在推荐总体优化中但默认未选。用户选择任一项后，工作台先保存恢复数据，再直接应用目录中冻结的受控设置，不要求下载或导入 `.reg`。用户可以立即或稍后重启资源管理器；重启后分别验证，且每项均能恢复到修改前状态。

### Y. 后续 Windows 版本强制尝试

高于 Windows 11 25H2 或无法识别的 Windows 11 上，两项资源管理器设置在标准视图显示“可能不适用”并禁用普通应用；高级视图只有在恢复规则可用时提供“仍然尝试”。用户确认风险后，日志保存实际系统版本、已知范围和确认结果；失败不阻止其他无依赖项目，恢复入口始终保留。

### Z. 搜狗安装与安装后优化

软件安装页从 `https://shurufa.sogou.com/windows` 取得目录声明支持的搜狗输入法安装器，并在安装前展示“关闭搜索候选”和“不安装腾讯元宝”两个推荐选择；两项均由工作台自动完成并验证选择过程。实际运行中自动控制失败时暂停并给出应急手动步骤，但本次结果不得记为自动完成。安装完成后再提示“搜狗输入法推荐优化”，安装结果与优化结果互不改写。

### AA. 搜狗方案完整性与右键扩展归属

搜狗优化方案逐项展示并能够受控执行来源文章中的状态栏、输入习惯、推荐与弹窗、AI 汪仔、候选提示和搜狗右键扩展设置；广告、推荐、弹窗和自启动等低影响项按目录默认勾选，使用习惯、主要功能与搜狗右键扩展默认不勾选。工作台在目录声明支持的搜狗版本上逐项执行并确认结果；Windows 经典右键菜单只出现在系统优化，搜狗 PDF 工具、磁盘管理和压缩扩展只出现在搜狗软件优化，两个页面没有重复执行入口。

### AB. 来源变化与暂不支持项

三篇方法来源文章的内容变化后，当前目录、用户选择、电脑状态、执行快照和恢复记录均保持不变；只有维护者审核并发布新目录、且用户主动加载后，新执行才采用更新规则。首版必达项不得因来源变化被静默省略或改成“暂不支持自动处理”；如果新版本暂时没有可靠实现，应显示“版本不适用”或执行失败并提供手动应急处理，维护者通过新版目录恢复受控能力。

## 21. 首版完成定义

首版必须同时满足以下条件，才能视为达到本规格目标：

- 七个一级页面和推荐流程可用；
- 驱动、系统优化、软件安装、软件优化四个阶段均能独立完成、跳过或明确暂停；
- 在线、离线、x64、ARM64、重启恢复和失败重试的实现均通过自动化检查或可审查的合同验收；真实设备验证按 `REL-08` 独立记录，不包含在本条发布门槛中；
- 用户始终能看清操作状态、风险提示、流程总结与详细本机日志；
- 便携版和安装版均不依赖目标系统预装工作台运行时；Windows 10 22H2 是最低目标版本，更早版本仅警告且不提供正常运行保证；
- 应用发行包、目录包和设备级状态的更新或切换不会破坏恢复能力；
- 首版界面为简体中文，并已验证后续增加语言不需要重做核心流程；
- 两项已确认的 Windows 系统优化（`SET-30`、`SET-31`）、`SW-35` 至 `SW-38` 的搜狗安装阶段偏好，以及 `OPT-61` 所列全部搜狗优化选项均具备完整的受控执行实现、结果确认规则和自动检查；任何一项仅有手动说明或仍为“暂不支持自动处理”时，首版不得发布；
- 除上述首版必达项外，具体软件、其他设置和驱动入口内容至少各有一组正式清单；真实 Windows 和目标软件验收不作为发布条件，未执行时必须按 `REL-08` 在开发者发布记录中标记“未实机验证”；

## 22. 软件优化

- `OPT-01` 应用提供独立的“软件优化”一级页面，与“系统优化”和“软件安装”页面相互区分。
- `OPT-02` 软件优化页只展示项目维护的软件优化方案，不允许用户输入任意脚本、命令、注册表内容或未列入方案的目标路径。
- `OPT-03` 每个软件优化方案必须明确关联目标软件，并说明预期效果；方案只能通过项目预先定义且受精选软件优化目录约束的方式调整目标软件自身设置。
- `OPT-04` 工作台确认某个软件安装完成后，如果存在适用的软件优化方案，应以非阻塞方式提示该软件“可以优化”并提供进入对应方案的入口，不得自动应用优化，也不得改变该软件的安装完成结果。
- `OPT-05` 软件优化页应识别可优化软件，并把已安装且有适用方案的软件与当前不可执行的方案清楚区分。
- `OPT-06` 系统优化与软件优化按功能所有者划界：调整 Windows 自身行为时属于系统优化；通过软件内选项、配置文件、注册表、官方接口或该软件提供的资源管理器扩展调整目标软件自身行为时属于软件优化。同一实际修改不得在两个页面重复提供。
- `OPT-07` 软件卸载和垃圾清理不属于软件优化方案，不得借“其他方式”将其混入软件优化页面。
- `OPT-08` 软件优化方案不得按当前 Windows 用户、软件账号或整台电脑分类、筛选或决定是否收录，也不提供作用范围切换器；设置实际保存在哪里不影响其作为目标软件行为的归属。
- `OPT-09` 每个软件优化选项应以通俗文字说明实际会影响什么；没有可执行方案时显示“暂无可用优化”，不得虚构作用范围，也不得因用户配置或账号配置而排除方案。已识别软件处于首版声明支持版本且存在首版必达方案时，缺少执行规则属于实现错误，不得显示为正常的“暂无可用优化”。
- `OPT-10` 首版软件优化不提供撤销，也不为恢复优化保存目标软件修改前状态；软件优化记录不得复用系统设置的恢复记录或“设置撤销”语义。
- `OPT-11` 每次执行软件优化前，必须显示目标软件、将修改的内容、预期效果、可能影响，以及是否需要关闭软件或重启 Windows；用户明确确认后才能执行，安装完成提示不得自动开始优化。
- `OPT-12` 一个软件优化方案可以包含多个软件优化选项，其中允许选择的选项使用复选框由用户逐项勾选或取消。
- `OPT-13` 本次执行只应用用户已勾选的软件优化选项；未勾选选项保持不变，已选与未选内容均在确认摘要中清楚区分。
- `OPT-14` 执行记录和日志必须保存本次实际勾选的软件优化选项；没有任何可执行选项被勾选时禁用执行命令并说明原因。
- `OPT-15` 项目推荐且影响较小的软件优化选项默认勾选；可能明显改变使用习惯、功能或兼容性的选项默认不勾选。
- `OPT-16` 方案正常执行不可缺少的核心操作应明确标为“必需”并保持选中，不能伪装成可取消选项。
- `OPT-17` 每个默认勾选状态和“必需”标记都属于精选方案定义；确认摘要仍须显示必需操作，不能因其不可取消而隐藏。
- `OPT-18` 软件优化是推荐初始化流程的第四阶段；当前没有可优化软件或适用方案时自动标记为“无适用项”并跳过，但独立软件优化页仍保持可用。已安装且处于声明支持版本的首版必达目标缺少可执行方案时不得跳过，应显示实现错误并阻止首版完成。
- `OPT-19` 批量安装过程中不得逐个弹出优化对话框；每个完成项只显示“可以优化”标记并继续安装，软件安装阶段结束后由第四阶段统一汇总所有可优化软件。
- `OPT-20` 软件优化页应识别当前 Windows 中已安装的软件，不限于通过工作台安装的软件；只要检测到目标软件且存在适用方案，就显示为“可以优化”。
- `OPT-21` 打开软件优化页、完成软件安装或用户主动刷新时重新识别可优化软件；软件来源于官网安装程序、Microsoft Store、`winget` 或用户此前自行安装，不得改变其优化资格判断。
- `OPT-22` 每个软件优化方案必须声明适用的软件版本范围；工作台应检测目标软件实际版本并显示匹配结果。
- `OPT-23` 无法识别目标软件版本或实际版本超出方案范围时，显示“版本不适用”及当前检测信息，但不得仅因版本不适用而禁止用户继续执行方案。
- `OPT-24` 版本不适用时隐藏或禁用普通“执行优化”；高级视图提供单独的“强制执行”按钮，执行前必须说明方案可能无效、损坏目标软件配置且无法由工作台撤销，并要求用户再次确认；标准视图只显示原因、安全处理方式和开启高级视图的入口。
- `OPT-25` 强制执行记录必须保存检测到的软件版本、方案适用范围、风险提示版本和用户确认结果，并在历史与日志中区别于正常版本匹配执行。
- `OPT-26` 每个软件优化方案必须声明执行时是否要求目标软件退出；要求退出且检测到软件仍在运行时，暂停当前方案并提示用户保存内容后正常关闭软件。
- `OPT-27` 软件关闭提示在两种视图中都提供“重新检测”；高级视图另提供“强制关闭并继续”，强制关闭前必须说明可能丢失未保存内容并要求再次确认，标准视图只提供正常关闭说明和开启高级视图的入口。
- `OPT-28` 强制关闭尝试、结果和用户确认必须写入执行日志；无法确认目标软件已经退出时不得继续修改其配置。
- `OPT-29` 用户一次执行的一个或多个软件优化方案都形成独立优化批次，并按确定顺序串行执行，不并行修改多个软件；单个方案也不得绕过批次快照、安全检查、历史或恢复规则。
- `OPT-30` 单个软件优化失败时记录原因，并继续执行没有依赖阻塞的后续方案；批次结束后，只有按当前目录、目标软件版本与状态及有效紧急撤回信息重新判断仍可执行的失败方案，才能创建新的单项优化批次重试。
- `OPT-31` 优化批次、软件安装批次和推荐初始化流程记录是不同对象，各自保存逐项状态和结果，不得因优化失败改写成功的软件安装记录。
- `OPT-32` 优化批次必须保存每个目标软件、实际版本、方案版本和实际勾选选项，用于历史追溯并确定待重试候选；新重试必须按 `OPT-30` 创建批次，不得复用旧快照中的执行规则绕过当前状态判断。
- `OPT-33` 软件优化需要重启 Windows 且继续执行后续操作不安全时，必须进入现有重启屏障，暂停优化批次及推荐流程中尚未安全执行的内容；界面应说明触发原因和未执行内容，提供“立即重启”和“稍后重启”，工作台不得自动重启电脑。
- `OPT-34` 用户勾选的软件优化选项存在必需搭配或互相冲突时，界面必须立即说明原因；只有用户确认后，才能自动补选必需选项或取消冲突选项，不得静默改变选择，也不得把可提前识别的问题拖到执行中途才报错。
- `OPT-35` 执行前检测到软件优化选项已经符合方案目标时，应显示“已优化”并跳过重复修改，同时允许用户查看方案内容和本次检测结果；“已优化”只表示当前状态符合目标，不表示一定由工作台修改。
- `OPT-36` 重新识别时发现目标软件版本已经变化，必须重新检测方案适用性和各选项当前状态，不得沿用旧版本的“已优化”判断；不再符合目标的选项显示“需要重新优化”，新版本超出方案范围时显示“版本不适用”，且工作台不得自动再次应用优化。
- `OPT-37` 软件优化方案由独立的软件优化目录包提供；该目录与软件和驱动目录、系统设置目录分别更新、导入和回退，目录更新本身不得自动应用优化。
- `OPT-38` 优化批次开始时必须冻结用户确认的软件优化方案版本、实际勾选选项、执行规则、状态检测规则和重启要求；之后的软件优化目录普通更新或回退不得改变正在执行、暂停或等待重启的批次，只有新建优化批次才使用当前目录。
- `OPT-39` 软件优化方案被普通下架后，不得再用于新的单项执行或优化批次；既有历史和方案快照继续保留并显示“方案已下架”，已经开始的批次仍按用户确认的快照完成，不得因下架而改写原记录。
- `OPT-40` 当前有效的紧急撤回通知将方案标记为因严重风险紧急撤回时，必须阻止新的执行，并停止执行中、暂停或等待重启批次内所有尚未开始的相关步骤；该规则优先于普通下架和批次快照，界面应显示撤回原因及受影响内容，已经完成的修改和历史继续保留，工作台不得自动恢复。
- `OPT-41` 软件优化方案执行中途失败时，不得自动恢复已经完成的修改；结果必须逐项区分“已优化”“优化失败”和“未执行”并说明原因。重试必须先按 `OPT-30` 重新判断并创建新执行记录，默认只包含仍可执行的失败或未执行选项；原先成功的选项先重新检测，仍符合目标时按“已优化”跳过。
- `OPT-42` 软件优化方式按“软件官方提供的设置接口或命令 → 修改该软件自身的配置文件、注册表项或资源管理器扩展配置 → 自动操作该软件设置界面”的顺序选择；自动操作界面只在前两类方式不可用时作为后备。Windows 自身行为不得路由到软件优化，第三方软件拥有的资源管理器扩展也不得仅因显示在 Windows 界面中而改归系统优化。
- `OPT-43` 每种优化方式的目标、改动内容和操作步骤都必须由项目预先定义，执行前向用户展示并在执行后写入详细日志；软件优化页和目录包不得接受用户输入的任意脚本、命令、注册表项、配置路径或界面操作步骤。
- `OPT-44` 每个软件优化选项执行结束后必须按方案规则重新检查目标状态，只有确认达到目标时才显示“已优化”；无法可靠判断时显示“优化结果待确认”，提供打开目标软件检查的入口和“已完成”。“重试”必须先按 `OPT-30` 重新判断；用户确认重试后，工作台先把该选择和原批次所有剩余状态写入不可改写的历史并结束原批次，释放批次占用，再为当前仍可执行的内容创建新批次。方案已普通下架、紧急撤回或存在其他阻止条件时禁用重试并显示原因。历史与日志必须区分自动检测结果和用户确认结果。
- `OPT-45` 网络可用时，工作台应在启动后以及每次执行、重试或恢复任何软件优化前自动检查项目发布的紧急撤回通知，并在开始新的修改步骤前应用阻止规则；该检查只更新安全阻止信息，不得静默加载软件优化目录或另外两类目录的普通变更。
- `OPT-46` 离线或紧急撤回通知检查失败时，工作台继续使用上次成功取得的通知，显示通知时间并提示信息可能不是最新；已知紧急撤回仍保持阻止，没有本地通知时不得伪称已经完成安全检查。
- `OPT-47` 软件优化页只展示工作台当前识别到的已安装软件，不展示尚未安装软件的方案；有方案的软件进入主要状态分组，没有可靠可执行方案的软件仅显示“暂无可用优化”，不得提供执行入口；首版声明支持版本内的首版必达目标缺少方案时按实现错误处理，不得进入该分组。
- `OPT-48` 进入推荐流程的软件优化阶段时，默认选中所有适用软件中影响较小的推荐选项，高影响选项保持未选；用户可以调整选择，工作台只有在用户查看汇总、点击“开始所选优化”并完成执行前确认后，才创建和执行优化批次。
- `OPT-49` 多个软件的正常优化使用一次按软件分组的批次确认，摘要必须列出每个目标软件、实际已选选项、影响、关闭要求和重启要求；普通方案执行期间不得重复弹出确认，强制执行、强制关闭等新增风险仍须在触发前分别确认。
- `OPT-50` 用户收起或暂不处理“可以优化”提示，不得把对应方案标记为永久忽略；该软件仍在软件优化页持续显示，直到达到优化目标、软件被卸载或方案下架后按新状态处理，首版不提供永久忽略方案的功能。
- `OPT-51` 软件优化页保留每个软件的当前状态和最近一次结果摘要，完整优化历史只在“历史与日志”页维护；从摘要进入完整记录时应定位到对应优化批次，不得创建或改写另一份历史。
- `OPT-52` 首版在同一设备的所有工作台实例之间，同一时间只允许一个软件安装批次或优化批次处于活动或待处理状态。在该批次完成、停止结束或取消前，另一类批次不得开始，也不得由另一个实例绕过；执行、停止、等待结果确认、等待重启和待恢复状态都受此约束。界面应显示当前批次及进入其进度页的入口。
- `OPT-53` 用户选择“停止优化”时，允许当前优化步骤安全结束，随后把尚未开始的步骤标记为“未执行”并停止批次；已经完成的修改不得自动恢复，停止操作和逐项结果必须写入历史与日志。
- `OPT-54` 当前优化步骤卡住时，高级视图提供独立的“强制终止优化”；执行前必须说明可能留下不完整配置且工作台不提供撤销，并要求再次确认。“强制终止优化”不得与用于关闭目标软件进程的“强制关闭并继续”共用名称、确认或日志事件。
- `OPT-55` 优化批次按 `RUN-06` 因关闭工作台进入待恢复状态，或因重启屏障暂停后，重新打开先恢复进度和待处理状态，并可自动完成无副作用的只读检测及既有结果验证；启动任何新的修改步骤前必须等待用户点击“继续”。取消时只放弃尚未执行的步骤，已完成修改不恢复，原批次按 `RST-08` 保留只读历史。
- `OPT-56` 紧急撤回通知必须包含通知修订号、发布时间、软件优化方案稳定标识、受影响版本范围、原因及“撤回”或“解除”状态；同一通知源中相同或更旧修订不得覆盖设备已经接受的较新结果。
- `OPT-57` 工作台把最近有效通知计算出的撤回结果作为设备级有效紧急撤回信息，由便携版与安装版共享；目录更新、导入、回退、应用更新或日志清理均不得清除，只有更新修订的紧急撤回通知可以调整或解除。
- `OPT-58` 不同软件优化方案之间存在必需关系或冲突时，必须在批次确认前说明原因；只有用户确认后才能补选必需方案或取消冲突方案，不得静默调整，也不得等执行中途才发现可预先识别的方案关系错误。
- `OPT-59` 首版提供“搜狗输入法推荐优化”方案；目标软件官网为 `https://shurufa.sogou.com/windows`，用户可见说明来源和维护参考为 `https://coolplume.github.io/posts/f4654180.html`。来源链接应在方案详情、版本不适用说明和运行时手动应急处理中可打开。
- `OPT-60` 搜狗方案必须把来源文章中的每个设置表示为独立可见且可由工作台受控执行的选项；实现缺失不得通过隐藏选项、标记“暂不支持自动处理”或只提供手动入口来规避。
- `OPT-61` 搜狗方案至少逐项覆盖以下内容：隐藏状态栏；关闭输入法指示器和状态栏嵌入语言栏；关闭成对标点自动补全和智能调整数字后标点；调整候选词数量；关闭系统功能快捷键；关闭输入助手总开关、开机自动启用、i 模式换肤、皮肤推荐、皮肤弹泡推荐、桌面右下角推荐和搜索推荐；关闭 AI 汪仔的等号搜索、AI 表情、快捷搜索、划词工具、快捷键唤起和自启动；关闭候选提示中的快速搜索和工具箱；关闭搜狗提供的 PDF 工具、磁盘管理和压缩三个资源管理器右键扩展。
- `OPT-62` 搜狗方案中，广告、推荐、弹窗和自启动等影响较小的项目默认勾选；状态栏外观、输入习惯、候选词数量、标点行为、快捷键、输入助手总开关、i 模式换肤、除自启动外的 AI 功能、候选提示工具和搜狗右键扩展等会改变习惯或功能的项目默认不勾选。默认值属于目录版本，执行前始终允许用户调整。
- `OPT-63` 候选词数量使用方案定义的受控数值选择，并在确认摘要、执行快照和历史中保存实际选择值；不得借该输入开放任意配置内容。
- `OPT-64` 搜狗安装阶段的搜索候选和腾讯元宝选择只按 `SW-35` 至 `SW-38` 处理；安装完成后才检测并提示搜狗推荐优化。软件优化结果显示“已优化”时，详情必须列出实际达到目标的选项，不再附加当前用户、软件账号或整台电脑等范围标签。

- `OPT-66` 来源文章内容变化不会自动改变软件优化目录、执行规则、用户选择或电脑状态；维护者审核后以新的软件优化目录版本发布，既有批次继续使用原快照，目录更新本身仍不得自动执行优化。

- `OPT-68` 软件版本未知或超出方案范围时可以按现有“版本不适用”路径提供应急手动说明，但不得把该版本宣称为受支持，也不得因此降低 `OPT-67` 对首版受支持版本的完整能力要求。
