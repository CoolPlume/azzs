# 事项 02：接通 GitHub 更新查询与自动检查

Type: task
Status: needs-triage
Resolution: open
Owner: issue-02
Consumers: 06
Verification: 使用无界面生命周期合同和 Windows x64 网络实测验证手动查询、四种计划、启动/运行期触发、活动操作跳过、离线/限流错误和非打断提示。
Evidence freshness: 绑定实现提交、GitHub Release 查询时间、当前版本/架构/内容版/发行形态、网络环境和设置持久化代次；Release 规则或网络适配器变化后重跑。

## 问题

设置页已有检查入口，但 Windows 平台 `query_releases()` 仍固定返回 `unavailable`。当前没有自动检查计划、上次检查事实或运行期调度。

## 目标

- 查询工作台本体 GitHub 正式稳定 Release，过滤不匹配架构、内容版和发行形态的制品。
- 支持关闭、启动时、每日、每周；新安装默认启动时；保存上次检查结果。
- 活动安装/优化/恢复/更新事务期间跳过并补偿，不并行、不抢焦点。
- 有更新时在设置页和可关闭的非打断提示中展示版本、日期、摘要和 GitHub Release 入口。
- 自动检查永不触发后台下载、替换或自动切换；保留 ADR-0006 的主动更新边界。

## 不做

- 不把 GitHub 网页打开当作查询成功。
- 不实现未获维护者授权的 tag、Release、静默自更新或签名策略变更。

## 验收

- 查询成功、无更新、有更新、网络失败、限流、超时和活动占用均有类型化结果。
- 关闭/启动时/每日/每周的首次运行、重启、运行期到期和手动覆盖行为可重复验证。

## Comments

- 现有 ADR-0006 继续有效；自动检查只新增“查询和提示”语义。
