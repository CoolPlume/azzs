# 事项 04：建立受控安装能力并接入 QQ

Type: task
Status: ready-for-human
Resolution: open
Owner: issue-04
Consumers: 05, 06
Verification: 使用软件目录/安装批次无界面合同和 Windows x64 官方来源实测验证 QQ 的解析、下载、三层交互、安装后检测、暂停/恢复和结果记录。
Evidence freshness: 绑定实现提交、目录修订、QQ 官方来源地址、安装器版本/哈希或官方发布事实、系统架构、Windows/SDK 和安装结果；来源或安装器 UI 变化后重跑。

## 问题

QQ 目录项已经存在，但没有闭合的受控安装档案、生产 Windows 安装器启动器或可靠完成检测；当前安装适配器对声明型能力 fail-closed。

## 目标

- QQ 作为普通软件、默认不勾选、官方 Windows 稳定桌面版，优先在工作台内解析和下载。
- 建立可复用的受控安装能力：可靠参数化路径、可审计 UI Automation、官方界面回退、安装后置行为和联合结果检测。
- 已知安全选项可提前处理，附加推广默认拒绝；未知、账户、验证码、付款、隐私和条款不自动处理。
- 只使用项目内置能力和类型化安装档案；不允许目录携带脚本、路径或选择器，不随包携带第三方安装器。

## 验收

- QQ x64 官方来源实际下载并启动安装器，安装后能区分成功、失败、待确认和用户交互待处理。
- 安装批次关闭、重启、重试和结果检测不把安装器退出码当作安装成功。

## Comments

- 适用 ADR-0010、ADR-0039、ADR-0040 和新增 ADR-0054。
- 实现交接（2026-08-24）：`bf17591712577225bab4286b19d985f79c07de8f` 已集成到 `445641f1613bea5d22e05332eac2994fce5cf1ee`，QQ 目录和受控档案已声明；当前 Windows 适配器对 `declaration_only` fail-closed，尚无生产安装器启动器、UI Automation 处理器或结果验证器。不得把 QQ 目录可选或安装器退出码写成可安装；真实官方来源/安装器验收前保持延期/待确认。
