# 0.2.0 设计树收敛记录

本记录对应 `grill-with-docs` / `grilling` 的设计树。它记录用户已经作出的产品决策，不替代 `spec.md`、事项或后续执行计划。

## Round 1：范围与体验

| 问题 | 已确认决策 |
| --- | --- |
| Q1 更新对象 | 仅检查工作台本体，GitHub 是 Release 事实源；不把软件目录和第三方安装包纳入本机制。 |
| Q2 检查频率 | 关闭、启动时、每日、每周；不提供小时/分钟级自定义。 |
| Q3 安装来源 | 官方来源受控安装；工作台优先自行处理，必要的官方交互仍由用户完成。 |
| Q4 软件形态 | QQ 与 QQ 音乐使用中国大陆个人用户的稳定 Windows 桌面版。 |
| Q5 硬件删减 | 普通 UI 删除未分类物理磁盘、NAND 颗粒和资料识别等无意义/推断内容；诊断脱敏边界另行遵守。 |
| Q6 复制与表头 | 硬件值可选择复制，并提供复制本节命令；统一“项目 | 信息”表头。 |
| Q7 显示器格式 | 括号固定保留分辨率、Hz、内建/外接和英寸四槽；可靠值不写“刷新率”等冗余字段名，未知槽显示对应“未识别”字段。 |
| Q8 侧栏 | 拖拽、双击恢复默认、键盘等价路径和跨重启持久化。 |

## Round 2：自动检查与安装结果

| 问题 | 已确认决策 |
| --- | --- |
| Q9 基线 | 实测程序是 0.1.1 的 `f2f1998` 构建；当前集成基线与它存在硬件模型差异。 |
| Q10 表格归属 | 机型、Windows 版本及硬件信息统一在同一张表，显示器也混入其中。 |
| Q11 摘要字段 | 接受固定四槽的“分辨率；Hz；内建/外接；英寸”摘要；未知槽显示对应“未识别”字段而不省略。 |
| Q12 资料识别 | 普通页面不显示该内容；不把推断来源或研究说明暴露给用户。 |
| Q13 运行期触发 | 启动时检查之外，运行期间到期也允许只读查询。 |
| Q14 活动任务 | 安装、优化、恢复或更新事务活动时跳过，并在下一次启动/到期窗口补偿。 |
| Q15 提示动作 | 设置页状态 + 非打断提示；用户打开 GitHub Release，自动检查不下载/替换。 |
| Q16 默认频率 | 新安装默认启动时。 |
| Q17 安装自主性 | 工作台优先自行解析、下载、启动、记录；可靠性不足才交给用户。 |
| Q18 自动勾选 | 只处理已知、安全、可可靠识别的选项；未知和敏感交互不碰，提供预期选择/回退。 |
| Q19 结果确认 | 安装器生命周期 + 软件存在/版本事实联合判定；未知进入待确认。 |
| Q20 发布门槛 | 先实现，维护者亲自实机验收；验收不过可延期到下个版本。 |

## Round 3：展示、来源与发布

| 问题 | 已确认决策 |
| --- | --- |
| Q21 NAND/资料 | 普通 UI 删除 NAND、资料识别、接口/PCIe 等推断；必要诊断只保留脱敏结构化事实。 |
| Q22 显示器 | 使用无冗余标签的型号摘要，固定保留可靠分辨率、Hz、内建/外接和英寸；未知槽明确显示“未识别”。 |
| Q23-Q24 行与空值 | 保留确认的类别；固定摘要无事实显示“未识别”，多实例空类别隐藏；删除未分类物理磁盘。 |
| Q25 目录 | QQ/QQ 音乐为普通、默认不勾选、官方 Windows 稳定桌面版，不随包携带安装器。 |
| Q26 架构 | x64 Windows 是本版真实安装验收范围；ARM64 未实机验证。 |
| Q27 三层安装 | 可靠参数化安装 -> 项目可审计 UI Automation -> 官方安装界面用户处理。 |
| Q28 失败处置 | 任一软件验收不稳定就不写入 0.2.0 可用安装承诺，延期处理。 |
| Q29 文档流程 | 先审阅规格/地图/事项/ADR；用户再次确认后才写执行计划和创建总调度会话。 |

## Unresolved facts

- QQ/QQ 音乐官方来源的当前发布分支、安装器类型、版本和架构事实。
- 两个安装器可可靠参数和 UI Automation 身份；未知版本必须安全回退。
- GitHub Release 查询的 Windows 网络、代理、超时和限流语义。
- 多显示器、DPI、剪贴板和安装后置行为的真实 x64 验收证据。
