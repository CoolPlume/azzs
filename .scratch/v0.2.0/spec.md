# 0.2.0 版本规格

状态：已确认

确认日期：2026-08-23

适用版本：0.2.0

## 1. 文档目的

本规格定义 0.2.0 对 0.1.1 实测制品的侧边栏、应用更新检查、硬件信息呈现和指定软件安装能力的收敛。它承接根目录 `CONTEXT.md`、现有 `docs/adr/` 决策以及 0.1.1 的实现边界；除本规格明确的展示和行为细化外，不改变权限、状态恢复、驱动交接、目录安全或第三方插件边界。

本轮实测基线为 `D:\azzs-codex\local-trial\azzs-0.1.1\f2f1998\Azzs.WinUI.exe`，来源提交为 `f2f19988b5bf7ffb1d297cb866ff92d80f87c67d`（`evidence/v011-integration-readable`）。该提交是正式 0.1.1 发布基线 `04eeb5ae8a04038cbb43359bded40504159a358b`（`0.1.1`、`origin/0.1.1`、`v0.1.1`）的祖先；0.2.0 实现应从 `04eeb5a` 开始，`f2f1998` 只作为实测展示对照。当前 `codex/v1-integration` 的较早集成基线不能直接作为 0.2.0 起点。

本文件是用户行为和验收合同，不是执行计划。实现顺序、会话拆分和提交策略在维护者再次确认后另行形成。

## 2. 用户目标

- `V020-G01` 用户可以用拖拽和键盘调整展开态侧边栏宽度，关闭并重新打开工作台后仍恢复该显示偏好。
- `V020-G02` 设置页的手动检查可以查询 GitHub 正式稳定 Release；用户可以选择自动检查计划，自动检查只查询和提示，不后台下载或替换工作台。
- `V020-G03` 硬件信息统一呈现为“项目 | 信息”表，用户可以复制硬件文字；无意义的未分类物理磁盘、NAND 颗粒推断和资料识别内容不再出现在普通页面。
- `V020-G04` 显示器摘要保留型号、分辨率、Hz 数值和内建/外接状态等有意义事实，但括号内不写“刷新率”“物理刷新率上限（EDID）”等冗余字段名。
- `V020-G05` 工作台优先能够安装 QQ 和 QQ 音乐；安装器自动化遵循三层处置和现有账户/隐私边界，x64 Windows 实机验收决定是否纳入本版本可用承诺。

## 3. 范围

### 3.1 纳入

1. 侧边栏拖拽把手、键盘等价路径、216/248/360 DIP 边界和持久化。
2. GitHub 稳定 Release 查询、手动检查、关闭/启动时/每日/每周自动更新检查计划、上次检查事实和非打断提示。
3. 0.1.1 实测硬件模型的呈现收敛：统一两列表、字段删减、显示器摘要、可复制文字。
4. QQ 和 QQ 音乐的官方来源解析、应用内下载、受控安装档案、三层安装器交互和安装结果检测。
5. x64 Windows 的自动化合同、真实安装验收和准确的版本放行记录；ARM64 只保留现有兼容性语义并记录未实机验证。

### 3.2 不纳入

- 自动检查触发后台下载、静默替换、自动切换或自动回滚工作台；仍遵守 ADR-0006 的用户主动更新边界。
- 随发行包携带 QQ、QQ 音乐或其他第三方安装器的可执行二进制；除非另有维护者授权和独立的再分发证据。
- 账户登录、注册、验证码、付款、隐私同意或未知安装器交互的代填、代答或静默确认。
- 坐标点击、任意脚本、目录自带选择器或第三方可执行插件。
- 工作台匹配、下载或安装驱动包；硬件信息仍只服务于概览和驱动入口推荐。
- ARM64 实机安装验收、完整八制品发布门槛、GitHub Release/tag、合入 `main` 或 WiX 条款接受。

## 4. 行为合同

### 4.1 侧边栏

- 继续遵守 ADR-0050：状态主体拥有的显示偏好由应用设置偏好服务唯一读写，`216` DIP 为最小、`248` DIP 为默认、`360` DIP 为最大。
- 展开态提供可发现的拖拽把手，拖拽连续跟手、可反向、可中断；键盘提供等价增减路径，并支持到达边界。
- 首次运行、非法值或偏好读写失败回退到 `248`，不得覆盖其他设置或业务状态。
- 窄窗口进入 compact 导航时保留当前页面、焦点和业务事实；恢复展开态不重置页面。

### 4.2 应用更新检查

- 检查对象仅为工作台本体的 GitHub 正式稳定 Release；软件目录、QQ 和 QQ 音乐安装包不进入本机制。
- 手动检查必须真正执行 Release 查询，不得继续使用“适配器未连接”的固定失败；相同、较低、预发布、draft、nightly 或不匹配架构/内容版/发行形态的制品不是候选。
- 自动更新检查计划包含“关闭、启动时、每日、每周”，新安装默认“启动时”。用户选择“启动时”时，工作台正常进入后执行一次；每日/每周计划在运行期间到期也可以查询。
- 自动检查只取得版本、发布日期、发布说明摘要和匹配 Release 地址，并在设置页状态与可关闭的非打断提示中呈现；发现更新后由用户打开 GitHub Release，不自动下载、替换或切换工作台。
- 安装批次、系统优化、软件优化、恢复或已有应用更新事务活动时，自动检查跳过并记录原因，在下次启动或下一个到期窗口补偿；不与活动操作并行，不抢占焦点。
- 离线、超时、限流或 GitHub 不可访问时，记录“更新检查结果”为暂时无法检查，不伪报无更新；手动检查仍可提供清晰错误和 GitHub 手动入口。
- 现有主动一键更新和故障恢复状态机继续遵守 ADR-0006；本规格不把自动检查连接到下载/替换路径。

### 4.3 硬件信息表

- 硬件页面统一使用“项目 | 信息”两列，至少包含：机型、Windows 版本、CPU、主板、内存、显卡、显示器、固态硬盘、机械硬盘、有线网卡、无线网卡、声卡、NPU。
- 固定摘要行没有可靠事实时显示“未识别”；显示器、固态硬盘和机械硬盘等多实例类别没有记录时隐藏空行。
- “未分类物理磁盘”不再作为用户可见行或摘要；未知介质类型不通过页面猜测为有意义类别，适用时由物理硬件边界 fail-closed。
- 显示器摘要采用固定顺序和无冗余标签的短文本，例如 `型号（2560 × 1440；144 Hz；内建）`。保留可可靠取得的分辨率、Hz 数值和内建/外接状态；未知片段省略，不显示“刷新率”“物理刷新率上限（EDID）”等字段名。
- 固态硬盘普通页面保留型号、容量等直接观测事实；删除接口、PCIe 代际、NAND 颗粒推断、资料识别原文和来源研究说明。
- 普通硬件页面不显示序列号、唯一设备标识、原始 EDID 或其他可追踪识别资料。诊断记录若确有需要，只保存脱敏的结构化观测事实，不复制普通页面的推断文字。
- 硬件字段值支持鼠标/键盘选择复制，并提供复制本节的明确命令；剪贴板属于 UI 适配行为，不进入核心业务状态。
- 页面不另行复制 ADR-0049 的物理性过滤；硬件记录、摘要和驱动推荐继续由 Windows 观测接缝统一提供。

### 4.4 QQ 与 QQ 音乐安装

- QQ 与 QQ 音乐均作为普通软件、默认不勾选的目录项；使用稳定 ID、官方 Windows 稳定桌面版来源，不随发行包携带第三方安装器。
- 工作台优先解析官方来源、取得安装文件、显示进度、启动官方安装器并记录安装操作结果；来源解析不可靠时才能回退到官方安装界面交互，不把普通浏览器链接当作唯一实现。
- 安装处置采用三层：可靠参数化安装；项目内置、可审计的 UI Automation 处理已知且安全的选项；官方安装界面由用户处理。未知复选框、账户、验证码、付款、隐私同意和条款确认不得自动处理。
- 已知附加推广默认拒绝；已知且安全的安装选项可由工作台提前处理，并在启动前/安装过程中提供可理解的预期选择和回退路径。不能可靠识别时停止自动处置，不使用坐标点击、任意脚本或目录选择器。
- 安装结果由安装器生命周期、受控存在性/版本事实和必要的安装后置行为联合判断。仅安装器退出、缓存存在或进程启动不能证明“安装成功”；无法确认时进入“安装结果待确认”，由用户明确处理。
- 0.2.0 的真实安装验收范围优先为 x64 Windows。QQ 或 QQ 音乐任一项实机验收不稳定时，该项不得写入本版本“可用安装”承诺，留待后续版本；静态合同或未实机验证不得冒充通过。

## 5. 架构与数据边界

- UI 只投影核心快照并提交类型化意图；自动检查调度、安装批次、硬件观测和结果状态分别由其既有所有者持有。
- 侧栏宽度只能通过应用设置偏好服务读写；更新计划不能散落到设置页面定时器、硬件页面或全局单例。
- 硬件物理性在 Windows 适配器到核心的唯一接缝判定；硬件信息表不能通过字符串再次过滤或推断类别。
- 软件目录只表达稳定 ID、来源用途、安装档案引用和发布资源；安装语义由项目内置受控能力提供，不允许目录携带代码、脚本、路径或选择器。
- QQ/QQ 音乐安装执行必须提供无副作用测试适配器和真实 Windows 适配器合同；生产适配器未闭合时目录项保持不可用或未发布。

## 7. 发布与未验证边界

- 0.2.0 的长期版本分支继续遵守 ADR-0051，使用裸版本号 `0.2.0`；执行工作树放在 `D:\azzs-codex\worktrees`，不改主工作树中的无关内容。
- x64 是当前唯一优先实现和验收架构；ARM64 代码和目录语义保留，但在本版本证据中写“未实机验证/延期”。
- 必须先有独立 `D:\azzs-codex` x64 `.exe` 和真实验证证据，才能讨论任何 GitHub Release/tag 或安装版发布；本文件本身不构成发布许可。
- 文档完成、合同测试通过、CI 通过、Windows UI 通过、目标软件安装通过和 GitHub 发布状态是不同证据层，不能互相冒充。

## 8. 领域事实待核对

- GitHub Release API/网络适配器在 Windows 原生环境中的稳定查询、超时、限流和代理行为。
- QQ 与 QQ 音乐官方 Windows 来源的发布分支、安装文件类型、架构和版本解析规则。
- 两个安装器的可靠参数、UI Automation 身份、已知安全选项和安装后置行为；未知版本必须回退或暂停。
- 显示器 EDID/分辨率/内建状态在不同 x64 设备、多显示器和 DPI 环境中的可确认边界。
- 0.2.0 x64 候选在维护者真实设备上的最终 UI、安装、复制和恢复验收。

## 9. 证据新鲜度

硬件呈现、更新查询、目录字段或受控安装档案发生变化后，必须绑定新的提交、构建目录、Windows/SDK、来源版本和实机观察；不得复用 `f2f1998` 的制品或旧截图证明新实现。QQ/QQ 音乐安装验收必须绑定实际安装器版本、来源地址、架构、系统版本和结果检测时间。
