# 0.1.1 实施计划

## 目标基线

- 起点：`codex/v1-integration` 的文档基线提交。
- 长期版本分支：`0.1.1`，由事项 08 创建并推送；该名称是用户明确要求的例外，不使用仓库默认的 `codex/` 前缀。
- 目标平台：Windows 11 25H2 原生 x64 优先；ARM64 代码和自动 CI 保留，专属证据继续标为未执行/延期。
- 设计依据：`docs/design/winui3-apple-inspired.md`、`CONTEXT.md`、ADR-0021、`apple-design`、`emil-design-eng`。

## 工作包与依赖

### 阶段 0：版本和文档基线

责任事项：08。创建 `0.1.1`，核对远端不存在同版本长期别名，记录起点 SHA 和保护规则。文档提交先进入集成基线，再由版本分支承接实现。

门禁：`git status --short`、`git ls-remote --heads origin`、GitHub 分支/保护设置读取；不删除历史分支、不改写历史。

### 阶段 1：设置导航稳定性

责任事项：01。先构造无界面异常夹具，确认 `snapshot`/`bind` 的真实异常边界，再实现页面边界恢复。保留当前页和用户状态，提供中文错误、重试和返回；增加进程存活与重复导航合同。

门禁：受影响的 core/UI contract；Windows x64 UI 自动化点击设置；异常路径不能依赖人工重启才能继续。

### 阶段 2：文案和共享视觉

责任事项：02、03，可并行但共享资源文件需要单一集成者解决冲突。先扫描概览及运行时创建的英文常量，再补资源和 presentation contract。随后统一页头、按钮层级、图标、工具提示、焦点和动效资源。

门禁：资源扫描、`ui.presentation.contract`、`ui.design.contract`、`git diff --check`；在浅色/深色/高对比度/减少动画夹具中不截断、不重叠。

### 阶段 3：侧栏显示偏好

责任事项：04，依赖 03 与既有事项 18。由唯一偏好 owner 实现宽度读取、拖拽把手、键盘增减、边界和 compact 投影；持久化失败回退默认，不改变其他设置。实现前检查 `NavigationView` 模板/组合根，避免在页面中直接写设置。

门禁：偏好合同、216/248/360 DIP 边界、重启恢复、写入失败、窄窗、键盘和触摸；不以固定屏幕像素替代 DIP。

### 阶段 4：物理硬件和驱动入口

责任事项：05 完成后再做 06。先固定适配器事实类型和过滤原因，再接入所有硬件投影、推荐器和“无物理设备”状态。未知物理性必须 fail-closed；禁用物理设备仍显示。维持 ADR-0009 的官方外部交接，不下载/安装驱动。

门禁：硬件适配器合同夹具、驱动推荐合同、代表性 Windows x64 设备观察；概览、驱动页、日志三处结果一致。

### 阶段 5：集成验收

责任事项：07。使用最终候选提交进行宽窄窗口、DPI/文本缩放、键盘、触摸、屏幕阅读器、减少动画/透明度、高对比度和无重叠检查。缺陷回流到原 owner，修复后只重跑受影响门禁。

门禁：x64 host guardrails 和 UI 自动化/人工证据；ARM64、安装生命周期、真实多显示器等未执行边界单独记录。

## 总调度分发规则

新总调度会话使用 `gpt-5.6-terra` + `ultra`（维护者本轮明确指定），负责依赖、独立 worktree、执行会话分发、集成和证据收口。执行会话使用 Terra XHigh/Max；共享状态、连续 Windows 根因或复杂冲突升级 Terra Ultra。不得在当前主工作树直接改业务代码。

每个执行简报必须包含：事项编号与目标、起始分支和精确 SHA、允许修改文件范围、必读文档/技能、最小验证命令、提交/推送/普通合并规则、未验证边界和完成回报字段。两个会话不得同时修改同一工作树或同一共享资源文件。

## Git 和发布边界

- 只允许普通 merge；禁止 rebase、force push、`reset --hard`、删除历史分支、改写提交历史。
- 默认集成目标仍为 `codex/v1-integration`；0.1.1 长期记录分支按 ADR-0051 保留，未经授权不合入 `main`、不创建 tag/Release、不接受 WiX 条款。
- 每个内聚工作单元通过最小门禁后提交并推送；事项 Markdown 在证据成立后才改为 `Resolution: completed`。
- 不把自动 ARM64、静态检查或旧提交证据冒充当前 x64 实机视觉/驱动事实通过。

## 完成回报模板

总调度结束每个阶段时记录：最终提交 SHA、修改摘要、实际执行的命令与环境、通过/未通过的门禁、未验证边界、GitHub 分支/PR/CI 链接、下一个已解除阻塞的事项。若遇到阻断，先检查工作树、远端和现有提交，再把最小剩余工作重新分发，不要求维护者重复下达“继续”。
