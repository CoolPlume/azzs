# 0.1.1 实施地图

## Notes

- 基线：`codex/v1-integration`，规划文档建立前工作树干净。
- 目标长期版本分支：`0.1.1`（GitHub 裸版本号）。
- 当前只优先 Windows x64；ARM64 保留现有代码和自动 CI 语义，未执行边界不能外推。
- 本地图只描述事项关系，不替代 `spec.md` 的用户行为合同。

## Decisions-so-far

1. 设置导航闪退以“进程不得退出、当前页面保留、中文提示、可重试/返回”为验收合同，根因留给实现会话用证据确定。
2. 所有用户可见和无障碍文案默认简体中文；品牌、型号、版本和原始系统错误可保留原文并置于中文上下文。
3. 视觉重整沿用 WinUI 3 原生交互和仓库 Apple 风格适配；不仿制 macOS，不引入新的 UI 框架。
4. 侧栏宽度为唯一偏好所有者持有的显示状态：`216` 最小、`248` 默认、`360` 最大，支持拖拽/键盘/持久化。
5. 只有确认物理存在的硬件进入硬件记录和驱动推荐；虚拟、软件、VPN、回环、未知设备被过滤，禁用的物理设备保留并标注。
6. GitHub 每个版本只有一条裸版本号长期分支；历史分支保留，0.1.1 使用 `0.1.1`。

## Fog

- 当前闪退没有转储或最小复现日志；不得在文档中预先断言是 optional、文件、线程或 XAML 资源中的某一个原因。
- Windows WMI/SetupAPI 对“物理存在”的可确认字段和不同虚拟化软件的实际返回值需要在实现会话和代表性设备夹具中核实；未知值必须 fail-closed。
- WinUI `NavigationView` 的可调整宽度实现方式（现有控件接缝、模板部件或受控 `GridSplitter`）由事项 04 在不破坏原生语义的前提下决定。
- 页面标题的最终像素与视觉层级需要在宽窄窗口和 DPI 实机快速反向后收敛，规格只冻结行为和边界。
- 版本分支的 GitHub 保护规则、默认分支策略和现有历史命名需要由事项 08 读取远端后记录，不追溯改名。

## Exit criteria

- 所有事项 `Resolution: completed` 或经维护者明确 `wontfix`，且每项有精确验证证据。
- `0.1.1` 分支存在并可追溯，未创建同版本长期别名。
- 0.1.1 的 x64 候选门禁与未验证边界分开记录；不得以文档完成冒充产品完成。
