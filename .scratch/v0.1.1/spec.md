# 0.1.1 版本规格

状态：已确认

确认日期：2026-08-23

适用版本：0.1.1

## 1. 文档目的

本规格定义 0.1.1 对当前 Windows 初装工作台的修复、界面整理、硬件事实收紧和版本分支治理。它承接首版规格、`CONTEXT.md` 以及 `docs/adr/` 中的既有边界；除本规格明确的细化外，不改变安装、系统优化、软件优化、驱动交接、权限、恢复或目录安全合同。

0.1.1 是一次可交付的修复与体验版本，不是重新定义产品范围的版本。实现会话必须先读取本文件和对应事项，再按依赖推进；不能以“看起来更好”替代可重复的行为证据。

## 2. 用户目标

- `V011-G01` 用户点击“应用设置”时，进程不得闪退或静默退出；设置数据异常时仍能理解发生了什么并留在可恢复的界面。
- `V011-G02` 概览及其他页面的用户可见文案默认使用简体中文，用户能在不依赖英文猜测的情况下完成主要流程。
- `V011-G03` 所有页面共享清晰、克制、原生 WinUI 3 的 Apple 风格适配；按钮、页头和导航不再使用旧式的大面积复古按钮观感。
- `V011-G04` 侧边栏默认更窄，展开状态可由鼠标、触摸或键盘调整宽度，并在重启后保留用户选择。
- `V011-G05` 硬件页面、概览和驱动推荐只把确认存在的物理硬件当作硬件记录；虚拟、软件、VPN、回环和无法确认的设备不被展示或推荐。
- `V011-G06` GitHub 对每个版本保留一个且仅一个以版本号命名的长期分支；0.1.1 使用裸名称 `0.1.1`，不创建 `v0.1.1` 或 `codex/v0.1.1` 的第二条版本分支。

## 3. 范围

### 3.1 纳入

1. 设置页导航和 `ApplicationSettingsService` 快照/绑定的异常边界。
2. 概览页及全局用户可见资源的简体中文化，保留品牌、型号和必要的原始系统错误文本。
3. 共享按钮、命令槽位、页头和标题位置的设计系统重整，覆盖现有页面。
4. `NavigationView` 侧边栏的紧凑默认宽度、可调整宽度、键盘语义和持久化。
5. 物理硬件确认数据契约、Windows 观测过滤、硬件记录投影和驱动推荐输入。
6. 宽窄窗口、DPI、键盘、触摸、屏幕阅读器、减少动画和无重叠/截断验收。
7. 版本分支创建、保护、记录和交接规则；创建长期分支 `0.1.1`。

### 3.2 不纳入

- 工作台直接匹配、下载或安装具体驱动包；仍遵守 ADR-0009，只交接厂商官网或驱动助手。
- 新增产品一级页面、目录内容、系统优化项或软件优化项。
- 以 UI 捕获异常来掩盖核心状态损坏、改变权限边界或自动覆盖用户设置。
- macOS 界面、跨平台 UI 框架、重写无关核心模块或追溯整理历史分支。
- 删除、重命名或合并已有 `v0.1.0`、`codex/v0.1.0-*` 等历史分支。

## 4. 行为合同

### 4.1 应用设置导航失败

- 点击“应用设置”是一个不可导致进程退出的导航意图。页面构造、核心快照读取、可选字段绑定和资源加载的异常必须在唯一 UI 边界转换成类型化的中文错误状态。
- 失败时保留当前可用页面和核心状态，不清空设置、不写入默认值、不自动重试；显示“重试”和“返回/继续当前页面”命令。重试必须从当前状态重新取得快照并受同一代次/取消规则约束。
- 进程继续存活是硬性验收项。不可恢复的装配失败仍按既有启动失败边界处理，不被本事项伪装成设置页成功。

### 4.2 文案

- 所有普通用户和无障碍可见文案使用简体中文，包括按钮、工具提示、错误、空状态、加载、确认、导航和页头。
- 品牌名、硬件型号、版本号、原始系统/WMI 错误文本和外部厂商页面名称可保留原文；原文必须置于中文上下文中，不得成为孤立英文操作说明。
- 资源键、测试标识和日志字段不要求翻译，但不得直接泄漏为用户可见文本。

### 4.3 Apple 风格适配

- 以仓库的 [WinUI 3 的 Apple 风格适配](../../docs/design/winui3-apple-inspired.md) 为实现和验收最终依据，结合 `apple-design` 与 `emil-design-eng` 对即时反馈、直接操作、可中断性、克制材质和减少动画的审查。
- 保留 WinUI 3 原生导航、焦点、键盘、触摸和无障碍语义，不仿制 macOS 窗口或控件。
- 共享按钮使用语义样式、清晰层级和合适的图标；常见工具命令优先使用图标按钮并提供工具提示，破坏性命令保留明确文字和确认。
- 页面头部统一对齐标题、状态摘要和主要命令；不使用超大标题压迫内容，不把页面说明塞进嵌套卡片，不产生重叠或截断。
- 动效遵守仓库既有 0/83/167/250ms 资源、系统减少动画开关和“动画不提交业务状态”边界。侧栏拖拽必须直接跟手、可逆、可中断，设置失败时不靠动画掩盖状态。

### 4.4 侧边栏

- 侧边栏宽度以 DIP 计，最小 `216`、默认 `248`、最大 `360`；首次运行和持久化失败均使用默认值。
- 展开状态可通过明确的拖拽把手调整；拖拽期间内容即时跟随，越界采用边界阻尼或硬性限制但不跳变。键盘提供可发现的增减宽度命令，触摸命中区域满足现有无障碍基线。
- 宽度偏好只有一个可写所有者，由应用设置偏好服务持久化；读取或写入失败只回退显示值，不覆盖其他应用设置。窄窗口进入 compact 模式时保留导航选择和焦点语义。

### 4.5 物理硬件

- 硬件记录必须携带可审计的“物理存在确认”事实。仅当来源明确表明设备真实存在且不是虚拟、软件、VPN、回环或未知设备时，才能进入硬件概览、驱动推荐或硬件日志摘要。
- 虚拟显示适配器、虚拟网卡、VPN/隧道、回环接口、软件枚举项、Hyper-V/VMware 等虚拟设备和无法确认物理性的条目不展示、不参与驱动推荐、不触发驱动入口。
- 真实存在但当前禁用、无驱动或状态异常的物理设备仍显示，并以中文标注当前状态；“禁用”不等同于“虚拟”。
- OEM/整机型号只作为设备摘要，不伪装成独立硬件记录。硬件观测失败时显示“未识别”及原因，但固定驱动获取入口仍保留。
- 该过滤只收紧驱动入口输入，不改变 ADR-0009 的外部交接边界，也不声称驱动安装成功。

### 4.6 版本分支

- GitHub 对每个版本只保留一条长期版本分支，分支名严格等于版本号（例如 `0.1.0`、`0.1.1`、`0.2.0`），不带 `v` 或其他前缀；0.1.1 的目标分支为 `0.1.1`。
- 已有历史分支只保留，不删除、不重命名、不追溯合并。不得同时创建 `v0.1.1`、`codex/v0.1.1` 或其他同版本长期别名。
- 执行会话可使用独立 worktree 和短期事项分支，但只能向唯一的 `0.1.1` 分支提交可追溯的普通合并；禁止 rebase、force push、历史改写、tag 或 Release（除非另有维护者授权）。

## 5. 架构与数据边界

- WinUI 页面只提交类型化导航、重试、宽度调整和驱动入口意图；应用核心拥有状态转换，Windows 适配器只返回观测事实。
- 设置页不得直接读写文件、注册表或设备；快照异常必须经过核心定义的错误类型或等价稳定边界。
- 物理硬件过滤在 Windows 适配器/硬件观测模块集中完成，页面不得使用字符串 substring 再过滤一次或建立第二份设备列表。
- 侧栏显示宽度是显示偏好，不得进入业务批次、目录快照或硬件结论；持久化适配器失败不能改变业务状态。
- 普通目录内容仍不得引入第三方可执行插件；驱动入口仍是官方外部交接。

## 6. 验收矩阵

| 领域 | 必须证明 | 证据边界 |
| --- | --- | --- |
| 设置导航 | 点击设置后进程仍在、当前页保留、异常中文提示可重试/返回 | Windows x64 实机或同等 UI 自动化；仅静态检查不算通过 |
| 文案 | 概览和共享组件无孤立英文用户文案 | 资源扫描 + UI 合同；品牌/型号/原始错误按例外清单记录 |
| 视觉 | 所有页面共享页头/按钮样式，标题和命令无重叠 | UI 设计合同 + Windows 视觉快速反向 |
| 侧栏 | 216/248/360 DIP 边界、拖拽、键盘、重启持久化和 compact | 核心偏好合同 + x64 多 DPI/窄窗检查 |
| 硬件 | 物理确认过滤一致，虚拟/未知不出现，禁用物理设备保留 | 适配器合同夹具 + 代表性 Windows 设备；未知环境不外推 |
| 分支 | GitHub 只有一个 `0.1.1` 长期版本分支，历史分支未删 | `git ls-remote`/GitHub 分支证据绑定日期 |

ARM64、安装生命周期、4K/225% 多显示器、触摸和 Narrator 等仍按仓库发布规则单独记录；未执行不得写成通过。

## 7. 实施顺序

1. 先建立 `0.1.1` 分支和本规格/事项/ADR 的可追溯基线。
2. 并行处理设置导航边界、文案资源和共享视觉/页头；侧栏依赖共享命令与偏好边界。
3. 完成物理硬件契约和 Windows 过滤后，再接入驱动推荐与无硬件状态。
4. 集成后运行跨页面视觉、DPI、输入和无障碍验收，修复只影响验收的增量问题。
5. 以精确提交、验证环境和未验证边界更新事项，保留分支作为 0.1.1 历史记录。

## 8. 证据新鲜度

每张事项票据的 `Evidence freshness` 必须绑定实现提交、构建目录、Windows/SDK、资源或设备夹具以及重跑触发条件。文案、主题、硬件过滤或设置快照合同发生变化后，不得复用旧截图或旧设备观察。
