# 以物理存在确认收紧硬件记录

Status: accepted
Date: 2026-08-23
Related: ADR-0008, ADR-0009, ADR-0027

## Context

硬件观测当前返回少量字符串摘要，Windows 枚举没有统一区分物理、虚拟、软件、VPN、回环和未知设备，驱动推荐又按摘要字符串做 substring 判断。这会让虚拟设备出现在用户可见硬件列表或产生不应有的驱动入口。

## Decision

将“确认存在的物理硬件”设为硬件记录和驱动推荐的必要条件，并在 Windows 适配器到核心的唯一观测接缝集中判定：

- 输出记录必须带物理存在确认、来源/置信度、当前存在状态和必要的过滤原因；物理性未知或来源冲突时 fail-closed。
- 虚拟显示适配器、虚拟网卡、VPN/隧道、回环接口、软件枚举项以及 Hyper-V/VMware 等虚拟设备不进入任何硬件列表、摘要、推荐输入或硬件日志摘要。
- 真实但禁用、无驱动或异常的物理设备保留，并单独呈现其状态；禁用不等同于虚拟。
- OEM/整机型号只作为设备摘要，不创建独立设备记录。
- 页面、驱动目录和推荐器不得复制过滤规则或通过字符串 substring 猜测物理性。

本决策只收紧硬件事实的可见范围，保留 ADR-0009 的外部驱动助手/厂商页面交接边界；它不表示工作台安装或验证了驱动。

## Consequences

- 用户看到的硬件列表更少但更可信，虚拟环境中的未知项不会被伪装成真实硬件。
- 适配器需要维护可审计的分类字段和代表性夹具；不同 Windows 版本或虚拟化平台无法确认时宁可显示“未识别”。
- 无物理设备时固定驱动获取入口仍可用，硬件推荐入口必须说明缺少确认事实的原因。

## Rejected alternatives

- 继续用显示名称 substring 过滤：对驱动名称和虚拟化产品版本脆弱，无法审计。
- 把所有禁用或无驱动设备当成虚拟：会隐藏真实故障设备。
- 让页面各自过滤：形成多份硬件事实，容易出现概览与驱动页不一致。
