# 同时提供手动更新与主动一键更新

Status: accepted

初装工作台同时支持用户从 GitHub 手动下载新发行包，以及在工作台内主动触发一键更新；一键更新只列出正式稳定发行，不展示 draft、预发布或 nightly 等测试发行，手动下载不受这个筛选限制。应用不在后台静默下载或强制替换自身。由于发行包长期不签名且不提供校验信息，一键更新会下载无法由项目提供的信息验证完整性的发行包，因此执行前必须明确告知用户这一事实。下载或替换失败时，一键更新必须恢复上一版本；新版已经启动但无法进入工作台时则遵循下述用户选择与再次失败规则。这里的“无法进入工作台”仅使用 [CONTEXT.md](../../CONTEXT.md) 定义的“已正常进入工作台”健康边界；它不把构造前激活失败或一般启动装配失败纳入更新回滚状态机，也不承诺当前进程内重新装配。所有路径都保持设备级恢复记录不变。

当前运行测试发行时，工作台只在用户明确选择“切换到最新稳定版”后才尝试切换，绝不因发现稳定发行而自动降级或替换。候选必须同时匹配当前发行架构、内容版和便携版或安装版形态；没有匹配的正式稳定制品时，工作台明确显示不能自动更新并提供 GitHub 手动下载入口，不自动切换到另一种制品。

当前已运行正式稳定发行时，工作台只提供可以确认高于当前版本的正式稳定更新；相同、较低或无法比较的版本不作为更新候选，也不在工作台内提供选择旧稳定版的入口。若新版本已经启动但无法进入工作台，工作台不自动恢复旧版本，而是向用户提供重试新版本或恢复旧版本的明确选择；用户选择重试后再次无法进入工作台时自动恢复旧版本。若自动恢复后的旧版本也无法进入工作台，进入更新故障恢复状态并显示恢复界面，保留本机数据。该界面列出失败版本、时间和当前未恢复状态，优先给出匹配的正式稳定制品并保留浏览全部 GitHub Release 的入口；无网络时仍显示可复制的下载地址、故障摘要和诊断导出。它只允许手动下载、诊断导出以及只读查看历史和日志，不允许初始化操作、设置修改、清理或再次启动已失败版本。打开下载入口、下载或导出诊断资料不结束该状态，只有某个版本能够正常使用工作台且原有记录仍可见后才结束。整个恢复过程以静态错误状态呈现，不自动跳转或使用完成动效。上述结果都必须保留设备级状态和更新事实。

工作台拥有的安装批次、优化批次、系统设置执行，以及其等待确认、等待重启或待恢复状态优先于应用更新。此时一键更新进入清楚可见的延后状态，不下载、替换或中断当前任务；来源手动交接不属于该类任务。任务安全结束或由用户完成现有处理后，延后状态结束，但工作台仍等待用户再次主动发起更新。
