# 每个版本只保留一条裸版本号分支

Status: accepted
Date: 2026-08-23
Related: ADR-0045, ADR-0047

## Context

项目已有多个历史分支命名形式。维护者希望从 0.1.1 起按版本保留 GitHub 历史记录，并明确一个版本不能出现多条长期版本分支；如果同时使用 `v`、`codex/` 和裸版本号，版本归档会产生歧义。

## Decision

1. 每个版本只创建一条长期 GitHub 分支，名称严格等于语义版本号，例如 `0.1.1`、`0.2.0`，不加 `v`、`codex/` 或其他前缀。
2. 0.1.1 的唯一长期版本分支为 `0.1.1`；不得创建 `v0.1.1`、`codex/v0.1.1` 或其他同版本长期别名。
3. 已存在的 `v0.1.0`、`codex/v0.1.0-*` 等历史分支只读保留，不删除、不重命名、不追溯整理；该规则从 0.1.1 起生效。
4. 执行会话可以使用独立 worktree 或短期事项分支完成普通 PR 合并，但交付结果只能汇入该版本的唯一长期分支；短期分支不得被登记为同版本的第二条长期分支。
5. 版本分支采用普通 merge 和可恢复的保护规则，禁止 rebase、force push、历史改写；未经维护者另行授权不合入 `main`、创建 tag 或 GitHub Release。

## Consequences

- GitHub 分支名直接表达版本，长期记录和后续审计更容易检索。
- 总调度需要在启动时核对远端分支清单，并在版本事项中记录精确 SHA、合并关系和分支保留状态。
- 既有历史命名不会被“整理”成新规则，检索工具需要同时接受历史别名和新裸名称。

## Rejected alternatives

- 同时维护 `v0.1.1` 与 `0.1.1`：违反一个版本一个分支并制造默认目标歧义。
- 重命名或删除旧分支：破坏已有审计链接和历史记录。
- 只在本地创建版本分支：无法满足 GitHub 长期记录和跨会话交接要求。
