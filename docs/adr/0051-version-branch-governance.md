# 每个版本只保留一条裸版本号分支

Status: accepted
Date: 2026-08-23
Related: ADR-0045, ADR-0047

## Context

项目已有多个历史分支命名形式。维护者希望从 0.1.1 起按版本保留 GitHub 历史记录，并明确一个版本不能出现多条长期版本分支；如果同时使用 `v`、`codex/` 和裸版本号，版本归档会产生歧义。

## Decision

1. 每个版本只创建一条长期 GitHub 分支，名称严格等于语义版本号，例如 `0.1.1`、`0.2.0`，不加 `v`、`codex/` 或其他前缀。
2. 0.1.1 的唯一长期版本分支为 `0.1.1`；不得创建 `v0.1.1`、`codex/v0.1.1` 或其他同版本长期别名。
3. 执行会话可以使用独立 worktree 或短期事项分支完成普通 PR 合并，但短期分支只使用 `feature/`、`fix/`、`docs/` 等语义名称，不使用执行工具、自动化平台或人员身份作为前缀；交付结果只能汇入该版本的唯一长期分支。
4. 当前裸版本分支同时承担版本内集成目标。短期分支不得被登记为同版本的第二条长期分支，也不得代替版本分支长期保留。
5. 每次 GitHub Release 后审计并删除已经合入、没有开放 PR、没有独有提交且工作树干净的短期分支；含未发布独有提交、开放 PR 或未提交内容的分支先保留，不能为追求整洁而丢失历史或工作。
6. 版本分支采用普通 merge 和可恢复的保护规则，禁止 rebase、force push、历史改写；未经维护者另行授权不合入 `main`、创建 tag 或 GitHub Release。

## Consequences

- GitHub 分支名直接表达版本，长期记录和后续审计更容易检索。
- 总调度需要在启动和发布后核对远端分支清单，并在版本事项中记录精确 SHA、合并关系、清理结果和因开放工作而保留的例外。
- 旧提交历史不改写；已经存在但仍承载开放或独有工作的旧命名分支仅临时保留，完成或归档后按相同门禁删除。

## Rejected alternatives

- 同时维护 `v0.1.1` 与 `0.1.1`：违反一个版本一个分支并制造默认目标歧义。
- 不经可达性、PR、独有提交和工作树检查就批量删除旧分支：可能破坏开放工作或丢失唯一提交。
- 只在本地创建版本分支：无法满足 GitHub 长期记录和跨会话交接要求。
