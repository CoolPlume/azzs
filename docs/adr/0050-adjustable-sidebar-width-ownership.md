# 侧边栏宽度作为可持久化显示偏好

Status: accepted
Date: 2026-08-23
Related: ADR-0021, ADR-0029, ADR-0031

## Context

当前 `NavigationView` 使用默认展开宽度，初始观感过长，且没有用户调整或跨重启保存的路径。侧栏宽度只影响导航呈现，但如果由页面、控件模板和设置服务分别写入，会成为第二份状态来源并与页面导航恢复互相干扰。

## Decision

- 将侧栏宽度定义为状态主体拥有的显示偏好，由应用设置偏好服务唯一读写；`NavigationView` 和拖拽把手只投影和提交类型化意图。
- 使用 `216` DIP 最小、`248` DIP 默认、`360` DIP 最大。首次运行、非法值或偏好读写失败均回退 `248`，不覆盖其他设置。
- 展开状态提供可发现的拖拽把手和等价键盘增减命令；拖拽从当前呈现值连续跟手、可中断、可反向，释放后保持边界内。
- 窄窗口进入原生 compact 导航时保留页面选择、焦点和业务状态；恢复宽度不重建或重置业务事实。
- 侧栏宽度不进入批次、目录、硬件或日志业务结论；减少动画、触摸和高对比度模式仍保持完整输入路径。

## Consequences

- 用户可以把侧栏调到适合自己内容密度的宽度，默认窗口更紧凑。
- 需要偏好服务合同、拖拽/键盘输入和跨 DPI 的布局测试；存储故障必须是可见的显示回退而非导航崩溃。
- 页面标题和内容布局必须适应三个宽度边界，不能依赖固定像素或窗口宽度缩放字号。

## Rejected alternatives

- 直接修改全局 `NavigationView` 默认值：不能满足用户调整和持久化。
- 让页面各自保存宽度：会产生多个写入入口和跨页面不一致。
- 以业务设置或硬件状态驱动宽度：把显示偏好错误地提升为业务事实。
