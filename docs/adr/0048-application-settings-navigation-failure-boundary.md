# 应用设置导航在页面边界恢复

Status: accepted
Date: 2026-08-23
Related: ADR-0027, ADR-0029, ADR-0042

## Context

点击应用设置时，当前导航回调会创建设置页并绑定 `ApplicationSettingsService` 快照。用户实测该路径会导致进程闪退。现有证据没有转储，不能把原因预先归结为某一个 optional、持久化文件、XAML 资源或线程问题；但无论根因是什么，未处理的页面绑定异常都不能成为进程生命周期的隐式控制流。

## Decision

把“导航意图到设置页呈现”定义为一个明确的 UI 适配边界：

1. 核心/服务在可行处返回带错误语义的快照结果；仍有异常越过边界时，页面宿主统一捕获并转换为稳定的中文错误投影。
2. 错误投影保留当前页面、当前核心状态和用户已输入内容，不写入默认设置、不清空快照、不宣称设置页已成功打开。
3. 错误状态提供一次可发现的重试和返回/继续当前页面命令。重试重新取得当前快照，并遵守既有取消、代次和订阅生命周期规则。
4. 记录结构化诊断事件；未知异常不能静默吞掉，也不能在页面层重新解释为成功。只有既有启动装配边界才决定进程级失败。

## Consequences

- 页面异常不再直接终止进程，用户可以继续查看当前页面并恢复。
- 需要稳定的错误类型/错误投影和无界面合同测试；日志可以帮助确认实际根因，而不会把猜测写成事实。
- 页面实现必须避免重复订阅、悬空回调和重试递归，组合根仍是唯一装配入口。

## Rejected alternatives

- 在进程入口增加一层粗粒度 `catch (...)`：只能掩盖错误，无法保留正确页面状态。
- 绑定失败时静默使用空或默认设置：可能覆盖用户选择并伪造成功。
- 自动重启应用或强制跳转失败窗口：破坏用户当前上下文，不符合设置导航的可恢复边界。
