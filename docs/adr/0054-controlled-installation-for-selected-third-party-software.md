# 指定第三方软件采用受控三层安装

Status: proposed
Date: 2026-08-23
Related: ADR-0010, ADR-0035, ADR-0039, ADR-0040, ADR-0053

## Context

0.2.0 首先需要能够安装 QQ 和 QQ 音乐。当前目录可以声明来源，但生产 Windows 安装器启动器、安装后置行为和结果检测仍未闭合；QQ 音乐还没有目录条目，且第三方二进制再分发权不明确。用户希望工作台尽量提前处理安装器勾选，同时不希望代填账户或隐私步骤。

## Decision

- QQ 与 QQ 音乐作为普通、默认不勾选的软件项，优先使用官方 Windows 稳定桌面版来源；不随发行包携带第三方安装器。
- 工作台先尝试可靠参数化安装；无参数化能力时，使用项目内置、可审计的 UI Automation 处理已知且安全的选项；不能可靠识别时回退到官方安装界面由用户处理。
- 已知附加推广默认拒绝；未知复选框、账户、验证码、付款、隐私和条款不得自动处理。目录不得携带坐标、脚本、路径或选择器。
- 安装结果由安装器生命周期、安装后置行为和受控存在性/版本事实联合判断；仅退出码、缓存或进程存在不能证明安装成功。
- 0.2.0 先以 x64 Windows 实机验收为安装承诺门槛；任一软件不稳定则延期，不以静态合同或目录可选状态宣称可用。

## Consequences

- 两个软件需要真正的来源解析、受控安装档案、Windows 执行器、UI Automation 合同和结果验证器。
- 官方来源或安装器 UI 变化时可以安全回退到用户处理，而不会静默执行未知操作。
- 版本发布要保留软件安装器版本、架构、来源和用户验收证据；ARM64 仍是未实机验证边界。

## Rejected alternatives

- 随包镜像安装器：当前没有充分的再分发权、签名和更新证据。
- 对所有复选框自动勾选：容易越过隐私、推广或账户边界，且无法对版本变化保持可靠。
- 只打开浏览器链接：不能满足工作台优先自行取得、启动和验证安装的目标。
