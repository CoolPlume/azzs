# 应用更新检查与主动更新保持分离

Status: proposed
Date: 2026-08-23
Related: ADR-0006, ADR-0011, ADR-0045, ADR-0047

## Context

0.1.1 设置页已有手动检查入口，但 Windows 查询适配器尚未接通。维护者希望 0.2.0 增加自动检查，并允许用户自定义检查频率；现有 ADR-0006 又明确禁止后台静默下载或替换工作台。

## Decision

- 自动更新检查只查询工作台本体的 GitHub 正式稳定 Release，并把结果写入更新检查状态。
- 计划为关闭、启动时、每日、每周；新安装默认启动时。运行期到期可以查询，活动初始化操作期间跳过并补偿。
- 检查到新版本时只展示版本、日期、摘要和 GitHub Release 入口，由用户主动打开和决定后续更新；自动检查不下载、不替换、不切换制品。
- 候选继续匹配当前架构、内容版和便携版/安装版形态；不把预发布、draft、nightly 或不匹配制品变成候选。

## Consequences

- 自动检查不会扩大 ADR-0006 的自更新信任和回滚边界。
- 需要持久化计划、上次检查结果、活动操作跳过原因和网络错误；需要可测试调度时钟和 Windows 网络适配器。
- GitHub 查询失败不能伪报“已是最新”，设置页必须保留可理解的失败和手动入口。

## Rejected alternatives

- 后台自动下载或替换：会把查询偏好误变成设备级程序变更，违反 ADR-0006。
- 只打开 GitHub 页面：不能满足“设置里检查更新”的真实查询要求。
- 运行期无视安装批次并行查询：增加退出、互斥和用户注意力风险，没有必要收益。
