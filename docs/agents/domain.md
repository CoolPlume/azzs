# Domain Docs

本文件说明工程技能探索本项目领域文档时应遵循的规则。

## 探索前先读取

- 根目录的 `CONTEXT.md`；如果存在 `CONTEXT-MAP.md`，则读取它指向的、与当前主题相关的各个 `CONTEXT.md`
- 与即将修改区域相关的 `docs/adr/` 中的 ADR
- 多上下文仓库还要检查 `src/<context>/docs/adr/`

如果这些文件不存在，静默继续，不要主动提示缺失或建议提前创建。领域建模技能在术语或决策真正确定时按需创建它们。

## 文件布局

本项目使用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

## 使用术语表

输出中的领域概念（包括事项标题、重构提案、假设和测试名称）使用 `CONTEXT.md` 定义的词汇，不要擅自改用同义词。需要的新概念若尚未定义，应记录为领域建模候选。

## 标记 ADR 冲突

如果输出与现有 ADR 冲突，必须明确指出，不要静默覆盖：

> 与 ADR-0007 冲突，但由于……，建议重新审议。
