# 技术基线与更新策略

状态：已确认  
适用范围：初装工作台首版

## 1. 目的

本文件把“尽可能采用新技术”解释为可持续的工程策略：优先采用最新且稳定、适合产品目标并能降低长期维护成本的技术，而不是无条件采用最新预览。具体版本在开始实现时确定并固定，本文档定义选择顺序和不得突破的边界；模块与测试的详细约束见 [架构与代码质量](architecture-and-code-quality.md)。

## 2. 固定架构方向

- Windows 界面采用 WinUI 3、C++/WinRT 与 XAML，不依赖 .NET 运行时。
- 界面宿主与初始化核心都以 C++26 为目标编译模式。
- 界面与核心在同一个桌面应用内分层，不拆为后台服务或网络前后端。
- 应用采用模块化单体，只有唯一装配入口了解并连接具体实现。
- 可移植核心不依赖 WinUI 3 或 Win32 类型。
- Windows 专属设置、硬件、进程、权限和重启能力位于平台适配边界。
- 目录内容扩展不携带代码；新执行能力随工作台编译发布，不开放第三方代码插件。
- 未来 macOS 界面重新实现，不建设通用共享界面层。

## 3. 技术选择优先级

选择编译器、Windows App SDK、SDK、库或具体语言特性时，按以下顺序判断：

1. 满足安全、恢复和数据完整性要求。
2. 保持模块职责、接口、自动测试和依赖方向清楚，具备可持续维护状态。
3. 满足 Windows 10 22H2 最低目标版本。
4. 同时支持 x64 与 ARM64 发行。
5. 支持工作台自包含发行和离线启动。
6. 采用官方稳定发行并具备清晰维护状态。
7. 在以上条件相同时，选择更新的稳定方案。

“更新”不能覆盖前六项约束。最新稳定版本若已经不满足架构质量、最低目标系统或发行要求，应选择仍满足约束的最新稳定版本，并记录原因。

## 4. C++26 使用规则

- C++ 核心使用 C++26 编译模式，不以旧语言标准作为默认基线。
- 新语言特性必须被所选稳定工具链在 x64 和 ARM64 上可靠支持。
- 采用新特性应带来清楚收益，例如更强类型安全、更简单资源管理或更清晰接口。
- 不为展示语法而重写稳定、清楚且易维护的实现。
- 可移植核心避免依赖单一编译器的非标准扩展。
- 工具链尚未稳定支持的 C++26 特性可以暂缓使用，但不因此把整个核心降级到旧标准。
- 因工具链限制暂缓的特性应记录为明确例外，待稳定支持后重新评估。

### C++/WinRT 界面代码

- XAML 负责界面结构、资源和视觉状态，C++/WinRT 负责 WinUI 3 交互适配。
- C++/WinRT 生成代码和界面宿主使用与核心一致的 C++26 编译模式。
- 界面代码只采用稳定工具链可靠支持、且不破坏 XAML 与 C++/WinRT 工具链的语言特性。
- WinUI 3 类型停留在界面层和 Windows 适配层，不进入可移植核心接口。
- 界面后置代码不得复制目录、依赖、批次、恢复或结果判断规则。
- 发行包不携带或依赖 .NET 运行时。

## 5. 架构质量与受控扩展

- 依赖方向、状态所有权、装配入口、深模块和禁止依赖以 [架构与代码质量](architecture-and-code-quality.md) 为唯一详细规范，本文件不复制第二套模块拓扑。
- 凡既有内置受控能力能够表达的普通软件、来源、设置、驱动入口或优化方案，都通过目录内容扩展，不为单个目录项增加专用界面或核心分支。
- 新操作类型通过项目维护并随工作台发行的受控能力扩展接入；只有存在生产适配器与测试适配器等真实变化点时才建立新接缝。
- 核心流程必须能在无 WinUI 3 和无真实系统副作用的环境中自动检查，真实平台适配器另按相同接口合同验证。
- 循环依赖、界面直接系统操作、重复业务规则、跨功能可变全局状态或受支持扩展牵动无关模块，均视为架构检查失败。

## 6. 稳定与试验边界

### 发布基线

- 只使用 stable/正式发行的编译器、SDK、Windows App SDK 和依赖。
- 不把 preview、nightly、实验分支或无人维护的库作为首版发行必需项。
- 所有构建依赖固定到明确版本，保证同一提交能产生可追溯制品。
- 不在发布构建时动态解析一个会随时间变化的“latest”依赖版本。

### 独立验证

- 尚未成熟但可能带来价值的能力可在独立原型或可删除模块中验证。
- 试验性能力不得改变目录模式、持久化记录或公开核心接口。
- 删除试验性能力不得破坏首版主要流程或数据兼容性。
- 验证成功后仍需按发布基线重新评估，不能因原型可运行就自动进入产品。

## 7. 版本更新

- 每个发布周期主动检查所用工具和依赖的最新稳定版本。
- 更新前确认最低目标系统、x64、ARM64、自包含发行和离线运行没有被破坏。
- 会改变持久化格式、目录契约或核心接口的升级单独评审，不与普通依赖更新混在一起。
- 会扩大模块接口、改变依赖方向或引入新接缝的升级同时接受架构质量评审，不能只依据版本号或性能数据合入。
- 版本升级失败时保持上一套可构建基线，不让仓库长期停留在半迁移状态。
- 发布说明记录会影响开发、打包或运行环境的重大技术升级。

## 8. 不提前锁定

本轮文档不提前固定以下内容：

- 编译器和 Windows SDK 的精确版本号；
- Windows App SDK 的精确版本号；
- 尚未证明必要的第三方框架；
- 尚未形成真实替换需求的依赖注入框架、插件系统或抽象层；
- macOS 的界面技术和平台适配实现。

这些选择在实现启动前，根据当时最新稳定版本和本文件的优先级决定。

## 9. 验收

- 核心构建明确使用 C++26 模式。
- WinUI 3 界面由 C++/WinRT 与 XAML 构建，发行包不依赖 .NET。
- x64 与 ARM64 使用同一套稳定源码和依赖基线。
- 发布构建不依赖 preview、nightly 或浮动 latest。
- 可移植核心接口不包含 WinUI 3 或 Win32 类型。
- 核心可在不启动 WinUI 3 和不访问真实系统资源时通过自动检查。
- 架构依赖检查、接口合同测试和受控扩展隔离检查均通过。
- 项目没有运行时第三方代码插件入口，目录包不能携带可执行代码。
- 所选技术没有把最低目标版本提高到 Windows 10 22H2 以上。
- 所有试验性能力都可在不改变持久化数据和核心契约的情况下移除。
