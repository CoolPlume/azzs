# WinUI 3 的 Apple 风格适配

状态：已确认  
适用范围：初装工作台首版

## 1. 目的

本文档把 Apple 对安全、理解、掌控、成就感和克制愉悦的设计方法适配到 WinUI 3 桌面工具。目标是让管理员操作显得清楚、安静、可预测，而不是把 Windows 应用伪装成 macOS。

## 2. 适配立场

- 学习 Apple 对即时反馈、空间连续、可中断动效、层级和细节的处理。
- 保留 Windows 用户对窗口、导航、键盘、右键、焦点、触摸和系统配置操作的既有预期。
- 优先使用 WinUI 3 与 Fluent Design 的原生控件和平台能力。
- 界面实现使用 C++/WinRT 与 XAML，不依赖 .NET；设计规则不要求在界面后置代码中复制核心业务逻辑。
- 不复刻 macOS 交通灯按钮、标题栏、Dock 式导航或只能靠手势发现的主要操作。
- 不使用“像 Apple”作为偏离 Windows 可用性和无障碍规范的理由。

## 3. 体验目标

### 安全与可预测

用户始终知道当前操作、风险、结果和恢复路径。危险确认准确说明影响，不用模糊的“确定/取消”代替具体命令。

### 理解

每个页面都能回答“我在哪里、现在是什么状态、下一步是什么、如何退出”。界面使用项目统一状态术语，不要求用户阅读教程才能完成主要任务。

### 成就

“驱动 → 系统优化 → 软件安装 → 软件优化”长流程持续显示当前阶段、当前项目、已完成数量、剩余内容和暂停原因。完成总结清楚区分成功、失败、跳过和等待重启。

### 克制的愉悦

愉悦来自响应速度、排版、对齐、连续动效和可靠恢复，不来自彩屑、装饰动画或夸张视觉效果。

## 4. Windows 平台基础

- 一级导航采用 WinUI 3 的 Windows 原生导航模式。
- XAML 表达页面结构、资源和视觉状态，C++/WinRT 负责交互适配。
- 命令栏、信息提示、对话框和教学提示优先使用相应 WinUI 3 控件语义。
- 命令按钮优先使用熟悉的 Windows/Fluent 图标；不熟悉的图标提供工具提示。
- 风险动作使用清楚的文字标签，不能只用图标或颜色表达。
- 鼠标、键盘、触摸和窗口缩放是并列输入场景，不把触摸手势作为唯一入口。
- 直接操控只用于拖动、调整大小等天然交互，不把批量安装或系统优化设计成手势任务。

## 5. 信息层级与布局

- 工具界面保持安静、紧凑、可扫描，优先服务重复操作和状态比较。
- 普通路径先呈现当前结论、推荐选择和下一步操作；来源、检测依据、具体修改和低频控制下沉一层，按需展开。
- 页面区段使用无框架布局；卡片只用于重复项目或真正独立的工具单元。
- 不嵌套卡片，不把整个页面区段做成漂浮卡片。
- 卡片圆角不超过 8px，除非 WinUI 3 主题规范明确要求其他值。
- 固定格式控件使用稳定尺寸、网格轨道和最小宽度，动态内容不能推动工具栏跳动。
- 标题大小与容器匹配；紧凑面板不使用宣传页尺度的大标题。
- 文本允许合理换行；文本放大和窄窗口下不得截断、重叠或遮挡其他控件。
- 不使用装饰性渐变、光球、散景或与任务无关的插图占据主要空间。
- 界面不使用“当前用户”“软件账号”或“整台电脑”作为优化项目的分类标签；每个项目直接说明会改变什么、可能影响哪些使用习惯，以及是否需要重启相关程序。

## 6. 标准视图与高级视图

- 标准视图是默认信息层级，优先呈现推荐任务、常用选择、必要状态和安全操作。
- 高级视图由用户在应用设置中启用，显示更多状态细节和控制项。
- 首次运行默认使用标准视图；用户选择高级视图后保存该偏好，并在后续启动时继续使用。
- 两种视图即时切换，不要求重启应用，也不中断正在显示或执行的任务。
- 高级视图可以额外显示来源与历史版本、架构选择、缓存位置、目录导入或回退、详细日志等低频能力。
- 两种视图使用同一套领域状态和执行记录，不维护彼此独立的数据副本。
- 切换视图不得清除选择、执行进度、错误、日志上下文或恢复状态。
- 阻塞状态、关键风险和必须处理的错误不能因处于标准视图而隐藏。
- 高级视图不是权限边界；所有操作继续处于同一个常驻管理员会话和精选目录约束下。
- 标准视图必须能完成推荐流程和常见独立操作；高级视图可增加低频手动控制，但不能开放任意命令、脚本或下载地址，也不能绕过风险确认与恢复规则。
- 系统优化页顶部显示“推荐总体优化”的效果摘要和推荐操作，用户可以展开逐项查看、勾选或取消；下方继续提供全部单项系统优化。
- “推荐总体优化”只组合已有系统优化项，与下方单项共用同一选择、检测、执行结果、恢复记录和撤销状态；从任一入口修改后，另一入口立即同步，不创建重复项目。
- 经典右键菜单和 Win10 风格资源管理器属于视觉与交互变化明显的系统优化，默认不勾选；用户展开总体方案或浏览单项时仍能看到其效果说明。
- 系统优化项超出目录标明的已知 Windows 适用范围时，标准视图显示“可能不适用”并禁用执行；只有该项具备明确恢复规则时，高级视图才可显示检测依据并提供风险确认后的“仍然尝试”，且不能预选或静默执行。
- 软件官网信息解析完成后，标准视图在安装命令附近显示当前稳定版本、官网来源和联网要求。
- 高级视图可以继续显示软件包架构、完整安装包或在线安装器类型，以及本次解析得到的实际下载地址；这些细节不得挤压或遮挡主要安装命令。
- 软件优化页只展示当前已安装的软件；标准视图按“可以优化”“需要处理”“已优化”分组，显示效果摘要、主要状态、可选项和正常执行入口。
- 高级视图沿用相同分组和选择，只补充软件版本、方案匹配、检测依据和具体修改；未安装软件的方案不因切换高级视图而出现。
- 已安装但没有可靠方案的软件放入默认收起的“暂无可用优化”区域，避免干扰主要任务，同时保留工作台确实识别到该软件的反馈；首版声明支持版本内的首版必达目标缺少方案时显示实现错误，不得用该空状态弱化问题。
- “强制执行”“强制关闭并继续”和“强制终止优化”只在高级视图显示；标准视图保留原因、停止优化等安全处理方式和开启高级视图的入口，切换后不得丢失当前上下文。

### 系统优化与软件优化的归属

- 按功能所有者划分页签，而不是按影响用户数量划分：Windows 自身提供的行为归入系统优化，目标软件提供的行为归入该软件的软件优化。
- Windows 右键菜单样式和资源管理器样式归入系统优化；搜狗输入法等软件添加的资源管理器右键扩展仍归入对应软件的软件优化。
- 同一优化只出现在一个归属页；另一页需要解释关联时仅提供跳转，不复制选择、状态或执行入口。
- 软件安装阶段的偏好与安装后的软件优化分开呈现。例如搜狗输入法安装卡片负责“不开启搜索候选”和“不安装腾讯元宝”，安装完成后才在软件优化页提供状态栏、推荐、自启动及右键扩展等配置。
- 非首版必达项暂时没有可靠受控执行方式时，保留项目名称、预期效果和“暂不支持自动处理”状态，并提供清楚的官方设置或来源说明入口；首版必达项不得使用该状态代替实现。
- 普通路径必须让工作台直接完成首版必达项；只有已经具备受控能力、但本次因运行时异常或尚未识别的新版本失败后，才展开重试、原因和手动应急处理。手动应急不得使用与正常完成相同的视觉状态或结果文案。

## 7. 反馈体系

界面统一使用四类反馈：状态、完成、警告和错误。

- 控件在按下时立即进入 pressed 状态，提交结果随后呈现。
- 长任务持续反馈，不使用长时间无变化的加载状态。
- 应用内下载持续显示软件名称、版本、下载进度和当前状态；页面切换不移除或重置该反馈。
- 下载反馈同时呈现“已下载量 / 总大小”、当前速度和预计剩余时间；未知值显示“正在计算”，数值更新不得推动周围控件跳动。
- 当前下载项显示与数值同步的进度条；总大小未知时使用不确定进度状态，已知后原位切换为确定进度。
- 进度条提供可访问名称与状态，更新节奏兼顾及时反馈和屏幕阅读器可用性。
- Microsoft Store、`winget` 等托管安装来源只呈现其可靠提供的阶段和进度；缺少下载量、速度或剩余时间时显示“无法估算”，不伪造数值。
- 多软件批次另显示按项目数计算的整批进度条及“已处理数量 / 总数量”，并持续标明当前软件；不使用不可预测的安装时长伪造整体剩余时间。
- 当前下载项提供“暂停下载”和“继续下载”，并与“停止批次”保持明确区分；暂停后进度条停留在已有位置，不显示仍在下载的假反馈。
- 安装批次与优化批次在同一设备的所有工作台实例间互斥；现有批次等待结果确认、重启或恢复时也不能由另一实例绕过，界面显示当前批次并提供进入其进度页的入口。
- 正常关闭工作台时，正在执行的软件优化步骤沿用“停止优化”的安全结束边界，但后续步骤保持待处理而不是标为“未执行”；异常退出导致结果未知时，重新打开后显示“优化结果待确认”并先重新检测，不直接重跑。
- 校验尽量在受影响控件附近发生，不把所有错误推迟到提交后统一显示。
- 错误信息说明发生了什么、影响什么以及用户现在可以做什么。
- 静默安装失败时就地提供“重试静默安装”和“打开官方安装程序”，不以突然弹出安装界面代替用户选择。
- 软件安装完成后的“可以优化”使用非模态、可直接进入对应方案的就地提示；批量安装期间不逐项弹窗，优化阶段统一汇总。
- 搜狗输入法等包含首版必达安装阶段偏好的软件，在下载安装前显示本次选择，并由工作台在声明支持的安装器版本上自动完成；受控操作本次失败时显示“安装偏好处理失败”、重试和手动应急步骤，不把应急操作记为自动完成，也不把这些偏好混入安装后的软件优化批次。
- 收起“可以优化”提示只关闭当前提示，不创建永久忽略状态，也不从软件优化页隐藏该软件；被收起的提示不反复弹出打扰用户。
- 推荐流程进入软件优化阶段时，默认预选所有适用软件中的低影响推荐项，高影响项保持未选；只有用户查看汇总并点击“开始所选优化”后才进入确认和执行。
- 软件优化页只显示当前状态和最近一次结果；“查看全部历史”进入“历史与日志”页并定位到对应优化批次，不复制第二套完整历史。
- 界面、流程总结、历史和日志使用相同的状态名称。
- 网络、显示或外部安装器造成短暂中断时，保留可理解的恢复状态。
- 需要重启资源管理器才能确认的系统优化完成写入后，就地提供“立即重启资源管理器”和“稍后处理”；立即重启前说明任务栏和已打开的资源管理器窗口会短暂关闭，稍后处理则显示“等待资源管理器重启”并保留后续入口。

## 8. 动效

### 使用条件

动效必须解释状态变化、空间关系、层级或操作结果；没有信息价值时不添加动效。

### 响应与可中断

- 按下反馈目标为约 80-100ms。
- 小型状态变化目标为约 120-180ms。
- 面板和页面内转场目标为约 180-240ms。
- 动效从当前屏幕状态开始，用户反向操作时不得等待上一段动画结束。
- 动效期间不锁定输入；业务状态不能依赖动画完成事件才能保持正确。

### 运动性格

- 默认使用无过冲、接近临界阻尼的运动，保持安静和确定。
- 只有直接拖动、甩动等用户带入速度的交互允许轻微回弹。
- 列表、菜单、对话框和普通按钮不添加无原因弹跳。
- 进入与退出沿同一空间路径，浮层从触发控件附近出现并返回。
- 不使用大范围背景移动、循环漂浮或突然亮度变化。

## 9. 材质与深度

- 系统支持时，Mica 只用于应用根背景，建立窗口与桌面的层级关系。
- 系统支持时，Acrylic 只用于菜单、弹出层和短暂浮层，不作为大面积内容背景。
- Windows 10 22H2、减少透明度或材质能力不可用时，使用实体主题背景和明确边界；功能与信息层级不能依赖 Mica 或 Acrylic 才成立。
- 内容面板优先使用实体背景，不在半透明表面上继续叠加半透明卡片。
- 模态任务使用遮罩明确打断；并行、非阻塞面板不使用遮罩。
- 材质必须服务层级和可读性，不用模糊掩盖信息密度问题。
- 减少透明度或高对比度开启时，改用实体背景和清楚边界。

## 10. 字体与图标

- 使用 Segoe UI Variable 和 Windows 原生类型层级。
- 所有字距保持 `0`，不采用负字距。
- 字号不随窗口宽度缩放；使用固定类型层级、文本缩放和响应式布局适配。
- 通过字号、字重和行高建立层级，不靠极端字号差异。
- 正文和状态文本优先可读性；半透明表面上的文字保持足够对比度。
- 使用 Windows/Fluent 原生图标体系，保持相同图标在全应用中含义一致。

## 11. 无障碍

- 为所有交互控件定义正确的 Tab 顺序、可见焦点和屏幕阅读器名称。
- 状态变化通过无障碍通知暴露，不只依赖颜色或动画。
- 主要流程支持只用键盘完成。
- 遵守 Windows 文本缩放、高对比度、减少动画和减少透明度设置。
- 减少动画时使用短交叉淡化或即时状态变化，仍保留必要反馈。
- 在 100%-200% 文本缩放和窄窗口下验证无截断、溢出与重叠。
- 颜色不是状态的唯一编码，图标也必须配合可访问名称或文本。

## 12. 风险操作

- 普通、可恢复操作不使用确认对话框。
- 推荐总体优化在执行前显示已选项目摘要，允许返回调整；其中低影响项目可以默认勾选，明显改变 Windows 外观、交互或工作习惯的项目默认不勾选。
- 经典右键菜单和 Win10 风格资源管理器默认不勾选，并在执行前说明视觉变化、资源管理器重启和恢复方式；无论应用还是恢复，每次操作都保存该次修改前的实际状态和恢复记录。
- 超出已知 Windows 适用范围的系统优化只有在具备明确恢复规则时才在高级视图提供“仍然尝试”；确认内容必须说明可能无效或改变未知设置，并明确保留恢复记录。
- 软件优化不提供撤销，因此执行前使用一次确认摘要，列出已选选项、影响、关闭软件和重启要求；安装完成提示不得触发自动优化。
- 多软件优化使用一份按软件分组的批次确认摘要，普通方案不逐个弹窗；强制执行、强制关闭等额外风险只在实际触发前分别确认。
- 软件优化方案中的独立可选变更使用复选框，不用一组含义模糊的按钮代替；未勾选内容与已选内容保持清楚区分。
- 低影响推荐项默认勾选，高影响项默认不勾选；必需操作显示清楚的“必需”状态且不呈现为可交互复选框。
- 预选不等于执行，也不应提前创建优化批次；“开始所选优化”是明确提交点，执行前仍显示完整确认摘要。
- 软件优化方案版本不适用时不显示普通执行路径；标准视图说明原因，高级视图提供明确的“强制执行”，并在确认中说明可能无效、损坏配置且无法由工作台撤销。
- 目标软件仍在运行时先提供正常关闭后的“重新检测”；高级视图中的“强制关闭并继续”作为独立危险命令，说明可能丢失未保存内容且不默认聚焦。
- 可撤销操作优先提供结果反馈和撤销入口。
- 强制终止、删除恢复记录、目录降级或导入、未签名应用更新等操作显示具体影响后确认。
- “停止批次”与“强制终止”保持为两个含义明确的命令。
- 软件优化使用“停止优化”和“强制终止优化”，并与“强制关闭目标软件”明确区分；普通停止等待当前步骤安全结束，强制终止说明不完整配置风险。
- 不把不同风险合并成一次笼统确认，也不默认聚焦危险主按钮。
- 只有强制执行、不可撤销、可能丢失内容或明显改变系统行为等高风险操作使用阻断式确认；普通推荐选择、可恢复系统优化和手动说明入口使用就地摘要与反馈。
- 标准视图和高级视图使用相同的风险确认与恢复规则。

## 13. 内容语言

- 使用简短、具体、面向结果的简体中文。
- 按钮使用明确动词，例如“停止批次”“启动驱动助手”“删除恢复记录”。
- 页面不放置功能宣传、长篇操作教程或键盘快捷键说明段落。
- 帮助信息只在当前决定确实需要时出现，并紧邻其影响对象。
- 错误和警告不用责备用户的语气，也不隐去实际风险。
- “未实机验证”仅记录在开发者发布证据中，不得显示在普通用户界面或面向用户的 GitHub 发布说明中；面向用户的文案也不得声称已经完成真实设备验证。

## 14. 视觉验收矩阵

- 标准视图与高级视图可即时切换，切换后状态完整保留，所选视图可跨应用重启保持。
- 鼠标、键盘、触摸和屏幕阅读器均可完成主要流程。
- 浅色、深色、高对比度、减少动画和减少透明度状态正确。
- 100%-200% 文本缩放及不同窗口宽度下没有截断或重叠。
- 长任务的进度、停止、强制终止、失败恢复和重启暂停清晰可辨。
- 当前下载同时显示确定或不确定进度条、已下载量与总大小、速度和预计剩余时间；整批进度按已处理项目数单独呈现。
- 暂停下载、继续下载、停止批次和强制终止具有不同名称和状态；静默安装失败后的重试与打开官方安装程序入口就地可见。
- 推荐流程按“驱动 → 系统优化 → 软件安装 → 软件优化”呈现；系统优化页顶部的“推荐总体优化”可以展开逐项选择，并与下方单项保持同一状态、结果和恢复记录。
- 经典右键菜单和 Win10 风格资源管理器始终默认不勾选；超出已知 Windows 适用范围时，标准视图显示“可能不适用”且不能执行，高级视图只有在具备明确恢复规则并经过风险确认后才能“仍然尝试”。
- 相关系统优化完成后，“立即重启资源管理器”和“稍后处理”含义明确；选择稍后处理时能持续看到“等待资源管理器重启”并返回完成验证。
- 软件优化页在标准视图与高级视图中保持相同分组、选择和执行状态，未安装软件不出现，“暂无可用优化”区域默认收起且可访问。
- Windows 自身行为与第三方软件行为按功能所有者分属系统优化和软件优化；软件提供的资源管理器右键扩展不会被误放到系统优化或在两页重复。
- 搜狗输入法的两个安装阶段偏好具有正常自动执行与失败反馈；安装后全部首版必达选项均有可执行控件、逐项结果和必要状态确认，不能仅打开设置页或显示“暂不支持自动处理”。
- 收起安装结果附近的优化提示后，软件优化页仍保留相应状态，当前提示不会反复出现，也没有含义不清的永久忽略入口。
- 最近一次优化结果与“历史与日志”中的对应记录可互相定位，两个页面不会出现彼此独立或矛盾的历史副本。
- 标准视图不出现强制执行、强制关闭或强制终止优化命令，但能看到完整原因、安全处理方式和高级视图入口；切换视图后上下文不丢失。
- 安装与优化批次不能同时运行；停止优化、强制终止优化和强制关闭目标软件具有不同名称、状态、确认和日志结果。
- 按下反馈即时，转场可被新输入打断，不因动效锁定操作。
- Mica 与 Acrylic 使用范围符合层级规则，没有半透明表面叠加。
- 不支持材质效果的目标系统使用实体背景回退，且不影响功能或可读性。
- 字距为 `0`，字号未随视口宽度缩放，页面没有营销式或装饰性布局。
