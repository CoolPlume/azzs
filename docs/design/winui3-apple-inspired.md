# WinUI 3 的 Apple 风格适配

状态：已确认  
适用范围：初装工作台首版

## 1. 目的

本文档把 Apple 对安全、理解、掌控、成就感和克制愉悦的设计方法，以及 Emil Kowalski 对频率、目的、响应、可中断性和细节一致性的设计工程原则，适配到 WinUI 3 桌面工具。目标是让管理员操作显得清楚、安静、可预测，而不是把 Windows 应用伪装成 macOS。具体 WinUI 3 能力、性能工具和官方依据见 [WinUI 3 动效工程研究](../research/winui3-motion-engineering.md)。

## 2. 适配立场

- 学习 Apple 对即时反馈、空间连续、可中断动效、层级和细节的处理。
- 保留 Windows 用户对窗口、导航、键盘、右键、焦点、触摸和系统配置操作的既有预期。
- 优先使用 WinUI 3 与 Fluent Design 的原生控件和平台能力。
- 界面实现使用 C++/WinRT 与 XAML，不依赖 .NET；设计规则不要求在界面后置代码中复制核心业务逻辑。
- 不复刻 macOS 交通灯按钮、标题栏、Dock 式导航或只能靠手势发现的主要操作。
- 不使用“像 Apple”作为偏离 Windows 可用性和无障碍规范的理由。

## 3. 体验目标

### 安全与可预测

用户始终知道当前操作、风险、结果和恢复路径。危险确认准确说明影响，不用模糊的“确定/取消”代替具体命令。

### 理解

每个页面都能回答“我在哪里、现在是什么状态、下一步是什么、如何退出”。界面使用项目统一状态术语，不要求用户阅读教程才能完成主要任务。

### 成就

“驱动 → 系统优化 → 软件安装 → 软件优化”长流程持续显示当前阶段、当前项目、已完成数量、剩余内容和暂停原因。完成总结清楚区分成功、失败、跳过和等待重启。

### 克制的愉悦

愉悦来自响应速度、排版、对齐、连续动效和可靠恢复，不来自彩屑、装饰动画或夸张视觉效果。

## 4. Windows 平台基础

- 一级导航采用 WinUI 3 的 Windows 原生导航模式。
- XAML 表达页面结构、资源和视觉状态，C++/WinRT 负责交互适配。
- 命令栏、信息提示、对话框和教学提示优先使用相应 WinUI 3 控件语义。
- 命令按钮优先使用熟悉的 Windows/Fluent 图标；不熟悉的图标提供工具提示。
- 风险动作使用清楚的文字标签，不能只用图标或颜色表达。
- 鼠标、键盘、触摸和窗口缩放是并列输入场景，不把触摸手势作为唯一入口。
- 直接操控只用于拖动、调整大小等天然交互，不把批量安装或系统优化设计成手势任务。
- 界面宿主遵从 Windows 每显示器 DPI 与显示缩放；显示缩放和用户设置的文本缩放分别适配，不用固定物理像素或按分辨率同比放大字号代替响应式布局。
- Windows 负责选择图形适配器；工作台不提供手动 GPU 选择器，也不把集成、独立或混合图形设备作为功能前提。

## 5. 信息层级与布局

- 工具界面保持安静、紧凑、可扫描，优先服务重复操作和状态比较。
- 普通路径先呈现当前结论、推荐选择和下一步操作；来源、检测依据、具体修改和低频控制下沉一层，按需展开。
- 页面区段使用无框架布局；卡片只用于重复项目或真正独立的工具单元。
- 不嵌套卡片，不把整个页面区段做成漂浮卡片。
- 卡片圆角不超过 8px，除非 WinUI 3 主题规范明确要求其他值。
- 固定格式控件使用稳定尺寸、网格轨道和最小宽度，动态内容不能推动工具栏跳动。
- 标题大小与容器匹配；紧凑面板不使用宣传页尺度的大标题。
- 文本允许合理换行；显示缩放、文本放大和窄窗口下不得截断、重叠或遮挡其他控件。
- 不假定单显示器、固定分辨率或固定 DPI。4K、225% 显示缩放是首版必达场景；标题、命令栏、状态带、列表、表单、进度区、对话框和浮层在该场景下保持可读、可见且可操作。
- 窗口跨不同分辨率、DPI 或显示缩放的显示器移动，或显示器接入、断开、主显示器改变时，重新测量布局而不重启工作台；当前页面、选择、焦点、未提交输入、批次显示和滚动语义保持。原窗口位置不可见时，将窗口放回可用工作区。
- 不使用装饰性渐变、光球、散景或与任务无关的插图占据主要空间。
- 界面不使用“当前用户”“软件账号”或“整台电脑”作为优化项目的分类标签；每个项目直接说明会改变什么、可能影响哪些使用习惯，以及是否需要重启相关程序。

## 6. 标准视图与高级视图

- 标准视图是默认信息层级，优先呈现推荐任务、常用选择、必要状态和安全操作。
- 高级视图由用户在应用设置中启用，显示更多状态细节和控制项。
- 首次运行默认使用标准视图；用户选择高级视图后保存该偏好，并在后续启动时继续使用。
- 两种视图即时切换，不要求重启应用，也不中断正在显示或执行的任务。
- 高级视图可以额外显示来源与历史版本、架构选择、缓存位置、目录导入或回退、详细日志等低频能力。
- 两种视图使用同一套领域状态和执行记录，不维护彼此独立的数据副本。
- 切换视图不得清除选择、执行进度、错误、日志上下文或恢复状态。
- 软件安装页在两种视图中显示相同的软件、分类和勾选状态，不存在“仅高级视图可选”的软件；高级视图只在同一软件项上补充版本、来源、架构、安装包类型、安装方式等细节和低频控制。
- 需要额外提示的普通软件也遵守同一规则：两种视图都显示简短必要提示且默认不勾选，高级视图只能补充依据和来源细节，不能把提示或选择能力留给某一种视图。
- 阻塞状态、关键风险和必须处理的错误不能因处于标准视图而隐藏。
- 当前有效软件目录属于本机试用目录时，两种视图都持续显示相同的“正在使用本机试用目录”标题、未通过正式发布检查的核心影响和对后续新任务的作用；高级视图只能补充修订、目录应用关联和未通过的发布条件，不能把该身份变成高级视图专属细节。
- 高级视图不是权限边界；所有操作继续处于同一个常驻管理员会话和精选目录约束下。
- 标准视图必须能完成推荐流程和常见独立操作；高级视图可增加低频手动控制，但不能开放任意命令、脚本或下载地址，也不能绕过风险确认与恢复规则。
- 系统优化页顶部显示“推荐总体优化”的效果摘要和推荐操作，用户可以展开逐项查看、勾选或取消；下方继续提供全部单项系统优化。
- “推荐总体优化”只组合已有系统优化项，与下方单项共用同一选择、检测、执行结果、恢复记录和撤销状态；从任一入口修改后，另一入口立即同步，不创建重复项目。
- 经典右键菜单和 Win10 风格资源管理器属于视觉与交互变化明显的系统优化，默认不勾选；用户展开总体方案或浏览单项时仍能看到其效果说明。
- 系统优化项超出目录标明的已知 Windows 适用范围时，标准视图显示“可能不适用”并禁用执行；只有该项具备明确恢复规则时，高级视图才可显示检测依据并提供风险确认后的“仍然尝试”，且不能预选或静默执行。
- 软件官网信息解析完成后，标准视图在安装命令附近显示当前稳定版本、官网来源和联网要求。
- 高级视图可以继续显示软件包架构、完整安装包或在线安装器类型，以及本次解析得到的实际下载地址；这些细节不得挤压或遮挡主要安装命令。
- 软件优化页只展示当前已安装的软件；标准视图按“可以优化”“需要处理”“已优化”分组，显示效果摘要、主要状态、可选项和正常执行入口。
- 高级视图沿用相同分组和选择，只补充软件版本、方案匹配、检测依据和具体修改；未安装软件的方案不因切换高级视图而出现。
- 已安装但没有可靠方案的软件放入默认收起的“暂无可用优化”区域，避免干扰主要任务，同时保留工作台确实识别到该软件的反馈；首版声明支持版本内的首版必达目标缺少方案时显示实现错误，不得用该空状态弱化问题。
- “强制执行”“强制关闭并继续”和“强制终止优化”只在高级视图显示；标准视图保留原因、停止优化等安全处理方式和开启高级视图的入口，切换后不得丢失当前上下文。

### 系统优化与软件优化的归属

- 按功能所有者划分页签，而不是按影响用户数量划分：Windows 自身提供的行为归入系统优化，目标软件提供的行为归入该软件的软件优化。
- Windows 右键菜单样式和资源管理器样式归入系统优化；搜狗输入法等软件添加的资源管理器右键扩展仍归入对应软件的软件优化。
- 同一优化只出现在一个归属页；另一页需要解释关联时仅提供跳转，不复制选择、状态或执行入口。
- 软件安装阶段的偏好与安装后的软件优化分开呈现。例如搜狗输入法安装卡片负责“不开启搜索候选”和“不安装腾讯元宝”，安装完成后才在软件优化页提供状态栏、推荐、自启动及右键扩展等配置。
- 非首版必达项暂时没有可靠受控执行方式时，保留项目名称、预期效果和“暂不支持自动处理”状态，并提供清楚的官方设置或来源说明入口；首版必达项不得使用该状态代替实现。
- 普通路径必须让工作台直接完成首版必达项；只有已经具备受控能力、但本次因运行时异常或尚未识别的新版本失败后，才展开重试、原因和手动应急处理。手动应急不得使用与正常完成相同的视觉状态或结果文案。

### 调试模式与图形化软件目录编辑器

- 设置页使用“调试模式”开关表达开启或关闭，不使用需要猜测当前状态的普通命令按钮。默认关闭，切换即时生效并保存；开启时在设置导航与调试工具区显示克制、持续且可访问的状态标记。
- 开启前就地说明日志会显著增多、占用更多磁盘并包含更丰富的设备与执行上下文；不使用阻断式确认。日志位置、导出诊断资料和清空日志使用含义明确的图标与文字命令。诊断导出一次生成一个可传回的自包含文件，导出前就地显示覆盖时间、大小、已执行脱敏和已知采集缺口，不要求用户另外整理截图或环境说明。
- 调试模式独立于标准视图和高级视图。切换任一视图都不改变调试状态；只有调试模式开启时显示图形化软件目录编辑器入口，普通软件安装页仍是选择与安装界面，不混入维护控件。唯一例外是调试模式已关闭、但用户真正关闭工作台时仍有未保存目录修改：“返回编辑”或保存失败可以临时恢复原编辑会话以处理这份修改，但不重新开启调试日志、不改变已保存的调试模式偏好，用户再次离开后入口继续隐藏；临时会话中的“应用”保持不可用，并就地说明需要先明确重新开启调试模式。
- 编辑器是独立的密集工作台：分类与搜索用于定位，软件列表用于扫描和选择，详情区使用与字段类型匹配的输入、菜单、复选框和来源列表；不把整页或分区包装成漂浮卡片，也不嵌套卡片。
- 编辑器命令栏把“保存草稿”和“应用”作为两个独立的图标加文字命令，并分别呈现草稿生命周期与当前目录身份：草稿持续区分“未保存更改”“恢复的未保存修改”“已保存未应用”和“校验失败”，当前目录持续区分普通有效目录与“本机试用目录”。编辑与保存只作用于目录编辑草稿，软件安装页和当前选择仍呈现当前有效目录；已经保存但尚未应用的草稿在正常关闭和重新打开后原位恢复为“已保存未应用”，并提供继续编辑、应用和删除草稿的明确命令，不自动聚焦或执行其中任何一个。异常退出或断电后找回的内容必须显示为“恢复的未保存修改”，不能使用“已保存”文案、绿色完成样式、勾选或庆祝反馈；它不得覆盖此前草稿或当前目录，且“应用”保持不可用并就地提示先保存。显式保存成功后才改为“已保存未应用”并清除恢复状态；放弃只移除恢复部分。没有找回可用内容或恢复失败时不得显示为已找回。本次运行期间离开编辑器页面、切换标准视图与高级视图或关闭调试模式时不显示未保存修改确认，也不自动保存、放弃或应用；修改继续由核心保留，重新打开编辑器后原位显示“未保存更改”。只有用户真正关闭工作台时才使用居中的 WinUI `ContentDialog` 或等价模态确认，提供“保存草稿并关闭”“放弃未保存修改”和“返回编辑”；保存是数据保留主操作，放弃操作不得默认聚焦且只丢弃上次保存后的修改，返回编辑取消关闭。保存失败时关闭对话框并在编辑器原位置显示错误、继续保留修改。若编辑器入口此前已经随调试模式关闭而隐藏，保存失败或“返回编辑”只临时恢复原编辑会话，不更改调试模式开关或日志粒度；处理后再次离开时入口仍隐藏，此时“应用”保持禁用并提示先重新开启调试模式。只有调试模式开启且用户应用当前已保存内容并通过核心运行时加载校验后才切换。
- 运行时加载结果与正式发布门禁结果分组显示。存在运行时整包级阻止问题时，在“应用”附近显示简短原因并提供定位入口，不提供强制应用；只有发布级问题时，命令明确显示“应用为本机试用目录”。应用失败时原位置保留旧目录、草稿和错误；只有局部依赖错误时新目录仍完整切换，受影响项就地显示为禁用，不从旧目录拼接同名项。应用成功后说明新目录用于之后的列表、规划和新批次，当前及待恢复批次不受影响；本机应用不改变 `release_state` 或正式发布结论。
- 本机试用目录使用不可关闭的 WinUI `InfoBar` 或等价静态状态带，在软件安装页、推荐流程的软件阶段、设置页的软件与驱动目录当前状态或导入区域，以及编辑器当前目录区持续显示。标题使用“正在使用本机试用目录”，正文使用“它已通过本机加载检查，但尚未通过正式发布检查。软件列表和之后创建的任务将使用它；已有任务不受影响。”设置页手动导入成功后在原区域立即更新；关闭调试模式只隐藏编辑器入口。只要该目录仍是当前有效目录，状态带就在两种视图及重新启动后继续显示，直至另一份有效目录明确替换。
- 新增、复制、删除、启用、禁用、移动和验证使用熟悉的 Fluent 图标，陌生图标提供工具提示；删除等破坏性操作不默认聚焦，字段错误和依赖错误紧邻对应条目显示并可从汇总定位。
- 列表行、工具栏、验证摘要和详情区使用稳定尺寸与响应式轨道；长名称、地址、错误和本地化文字可换行或截断后按需展开，在文本缩放、显示缩放与窄窗口下不重叠，至少覆盖 4K、225% 显示缩放。
- 编辑、筛选、选择、保存草稿、校验结果和日志刷新属于高频操作，使用即时状态变化，不播放页面转场、逐项错峰、缩放、弹簧或庆祝动效。“应用”按下后立即显示进度或结果；业务切换由核心完成，不等待动效结束。软件目录应用或导入为本机试用目录成功后只保留按钮原生 pressed 反馈并原位更新静态身份，不使用绿色完成样式、完成勾选、Toast、音效、淡入、弹跳或庆祝动效；编辑器焦点留在“应用”，设置页焦点返回并留在触发导入的命令，屏幕阅读器只礼貌播报一次“本机试用目录已启用，只影响之后的新任务”，后续导航或恢复不重复播报。偶发打开来源详情或错误详情才可使用统一的小型浮层动效。
- 图形化编辑器只呈现核心目录状态和校验结果；界面不显示“强制应用无效目录”、任意命令、脚本、插件或未建模参数入口，调试模式也不改变现有风险和安全语义。

## 7. 反馈体系

界面统一使用四类反馈：状态、完成、警告和错误。

- 控件在按下时立即进入 pressed 状态，提交结果随后呈现。
- 长任务持续反馈，不使用长时间无变化的加载状态。
- 应用内下载持续显示软件名称、版本、下载进度和当前状态；页面切换不移除或重置该反馈。
- 下载反馈同时呈现“已下载量 / 总大小”、当前速度和预计剩余时间；未知值显示“正在计算”，数值更新不得推动周围控件跳动。
- 当前下载项显示与数值同步的进度条；总大小未知时使用不确定进度状态，已知后原位切换为确定进度。
- 进度条提供可访问名称与状态，更新节奏兼顾及时反馈和屏幕阅读器可用性。
- Microsoft Store、`winget` 等托管安装来源只呈现其可靠提供的阶段和进度；缺少下载量、速度或剩余时间时显示“无法估算”，不伪造数值。
- 来源解析失败时，在当前软件卡片内就地显示准确原因以及“重新尝试”“查看原始地址”“选择其他来源”；来源手动交接不显示应用内下载进度、安装中状态或完成动效。用户返回后主动选择“重新检测”，结果立即更新为“外部安装已识别”或保留原失败状态，不使用阻断式确认，也不把外部操作绘制成工作台完成的安装。识别成功后可以原位显示该软件自身的软件优化入口，但其他软件的依赖选择只在用户下一次触发规划后更新；外部安装标记继续可见。关闭或重启后恢复时直接显示最近状态：成功时保留外部安装标记，尚未成功时显示原失败状态和“重新检测”；两种情况都不自动执行或播放入场、进度、完成反馈。
- 重新检测仍未发现目标软件时，在原位置保留失败原因，只提供“重新检测”和“暂时跳过”；标准视图与高级视图都不提供强制标记成功。暂时跳过使用未完成状态的静态反馈，不显示成功图标或完成动效，也不启用依赖与软件优化入口。
- 暂时跳过的软件持续出现在概览与推荐流程总结的“未完成”区段，并可定位回软件卡片执行“重新检测”；正常关闭、异常退出、Windows 重启或切换发行形态后静态恢复同一状态，不自动检测、不弹出启动提醒，也不使用循环或吸引注意力的动效。识别成功后从未完成区段移出，但历史入口继续可用。
- 推荐流程中的来源手动交接识别成功后，在当前上下文就地显示“继续”，不自动跳转或播放完成转场；用户点击后才进入后续步骤。独立软件安装页只更新软件状态，不显示流程专属命令。
- 用户点击“继续”或在独立软件页主动重新规划后，依赖已经满足的软件恢复为可选择状态但保持未勾选；列表原位更新并说明此前阻塞已解除，不播放完成动效，也不自动创建批次、下载或安装。
- 多软件批次另显示按项目数计算的整批进度条及“已处理数量 / 总数量”，并持续标明当前软件；不使用不可预测的安装时长伪造整体剩余时间。
- 当前下载项提供“暂停下载”和“继续下载”，并与“停止批次”保持明确区分；暂停后进度条停留在已有位置，不显示仍在下载的假反馈。
- 安装批次与优化批次在同一设备的所有工作台实例间互斥；现有批次等待结果确认、重启或恢复时也不能由另一实例绕过，界面显示当前批次并提供进入其进度页的入口。
- 正常关闭工作台时，正在执行的软件优化步骤沿用“停止优化”的安全结束边界，但后续步骤保持待处理而不是标为“未执行”；异常退出导致结果未知时，重新打开后显示“优化结果待确认”并先重新检测，不直接重跑。
- 校验尽量在受影响控件附近发生，不把所有错误推迟到提交后统一显示。
- 错误信息说明发生了什么、影响什么以及用户现在可以做什么。
- 需要额外提示的普通软件在软件卡片内使用非模态、可扫描的就地提示；用户选中后在安装批次确认摘要中再次显示本次相关提示，不为每次勾选弹出对话框。只有实际执行高风险命令时才使用对应的阻断式确认。
- 静默安装失败时就地提供“重试静默安装”和“打开官方安装程序”，不以突然弹出安装界面代替用户选择。
- 软件安装完成后的“可以优化”使用非模态、可直接进入对应方案的就地提示；批量安装期间不逐项弹窗，优化阶段统一汇总。
- 搜狗输入法等包含首版必达安装阶段偏好的软件，在下载安装前显示本次选择，并由工作台在声明支持的安装器版本上自动完成；受控操作本次失败时显示“安装偏好处理失败”、重试和手动应急步骤，不把应急操作记为自动完成，也不把这些偏好混入安装后的软件优化批次。
- 收起“可以优化”提示只关闭当前提示，不创建永久忽略状态，也不从软件优化页隐藏该软件；被收起的提示不反复弹出打扰用户。
- 推荐流程进入软件优化阶段时，默认预选所有适用软件中的低影响推荐项，高影响项保持未选；只有用户查看汇总并点击“开始所选优化”后才进入确认和执行。
- 软件优化页只显示当前状态和最近一次结果；“查看全部历史”进入“历史与日志”页并定位到对应优化批次，不复制第二套完整历史。
- 界面、流程总结、历史和日志使用相同的状态名称。
- 网络、显示或外部安装器造成短暂中断时，保留可理解的恢复状态。
- 需要重启资源管理器才能确认的系统优化完成写入后，就地提供“立即重启资源管理器”和“稍后处理”；立即重启前说明任务栏和已打开的资源管理器窗口会短暂关闭，稍后处理则显示“等待资源管理器重启”并保留后续入口。

## 8. 动效

### 8.1 先按频率决定是否需要动效

每段动效在实现前先回答“用户多久会看到一次”。频率判断高于“看起来更精致”：

- 键盘触发的命令、键盘焦点移动、一级导航、连续勾选或取消、下载数值与日志刷新必须即时完成，不播放页面、位移、缩放或弹簧动效。
- 每天频繁出现的列表导航、悬停和小型状态刷新只保留平台原生状态或极短颜色、透明度反馈，不移动内容。
- 偶发的对话框、Flyout、教学提示、错误详情和从汇总进入详情可以使用标准短动效。
- 有效动效偏好允许时，稀少的流程完成只播放一次克制的勾选与淡入；系统关闭动画时直接显示最终勾选和结果文字。任何路径都不使用彩屑、烟花、弹跳、音效、循环或需要等待结束的庆祝。
- 业务列表不逐项错峰入场。多个状态同时更新时同步呈现，不能为了视觉效果延迟用户读取或操作。

无动效不等于无反馈。即时路径仍须保留焦点、选中、按下、文字、图标和无障碍状态。

### 8.2 目的白名单

动效只能服务下列目的之一：确认输入已被接收、解释状态变化、保持空间或层级连续、说明同一对象从汇总进入详情，或避免偶发内容突然出现。无法用一句话说明目的，或目的只是“更高级”“更好看”，就不添加。

动画永远不是业务状态机。安装、优化、下载、恢复、导航和结果状态先由核心确定，动画只呈现已经确定的视觉状态；完成事件不能提交业务状态、开始系统操作或决定成功。

### 8.3 统一时长与运动资源

所有页面使用同一组语义动效资源，不在控件或页面中散落相近但不同的时长与曲线：

| 语义 | 时长 | 使用范围 |
| --- | ---: | --- |
| 即时 | 0ms | 键盘、高频导航、选择、数值和日志刷新 |
| 极短反馈 | 83ms | 平台 pressed/hover 状态、颜色或透明度 |
| 小型状态 | 167ms | 偶发内容变化、最小交叉淡化 |
| 浮层与详情进入 | 167–250ms | 对话框、Flyout、详情层级和一次性完成反馈 |
| 退出 | 83–167ms | 与进入路径一致但更快地离开 |

- 普通自定义界面动效最长 250ms；超出时必须说明不可替代的交互目的，并提供性能和无障碍证据。
- 进入和屏幕内移动采用 Windows 平台提供的快速响应、末端减速曲线；退出通常短于进入。界面动画不使用启动迟缓的曲线。
- 只有不确定进度等确需恒定运动的场景使用线性速度，并同时显示文字状态。
- 时长、曲线、减少动画和输入方式由一个界面层动效服务或资源层统一提供；页面不得复制曲线控制点或自行解释系统设置。

### 8.4 WinUI 3 实现顺序

1. 优先使用 WinUI 3 原生控件及其默认 pressed、hover、focus 和标准浮层行为。
2. 语义一致时使用平台 Theme animation 或 Theme transition。
3. 只有需要从当前状态改向、输入驱动或表达高级视觉关系时，才使用 Composition。
4. Storyboard 只用于控件视觉状态或确需依赖属性的局部情况，不能成为页面动效默认方案。
5. 默认禁止会持续驱动布局的依赖动画；若确实无法替代，必须单独记录原因、Release 构建性能证据和无动画回退。

XAML 始终拥有布局、焦点、命中测试、控件语义和无障碍结构。Composition 只增强现有 XAML 元素的呈现，不创建第二套业务界面树，也不把主要文字、状态或命令移入缺少等价无障碍结构的独立 Visual。

自定义动效优先只改变 `Opacity`、`Translation`/`Offset`、`Scale`、`Rotation` 和视觉层裁剪。普通路径不得持续动画 `Width`、`Height`、`Margin`、`Padding`、网格尺寸或其他会使布局每帧重新计算的属性。下载进度、日志和硬件检测同时更新时，允许的动效仍须保持响应。

ConnectedAnimation 只用于两个界面中用户能认出的同一对象，并关闭冲突的默认页面转场。启动失败时导航仍然完成并直接显示静态目标界面，不重试动画、不返回旧页面，也不把导航判为失败。

### 8.5 按下、浮层与工具提示

- 鼠标或触摸按下优先使用原生控件 pressed 状态；只有自定义可点击表面缺少足够反馈时，才增加约 83ms、范围约 0.95–0.98 的轻微缩放。键盘触发同一命令时不缩放。
- 元素进入时不得从 `Scale = 0` 出现；确需缩放时从 0.95–0.98 配合透明度开始，避免凭空弹出。
- 由控件触发的 Popover 或 Flyout 从触发位置建立空间关系并沿原路径退出；没有单一触发点的居中模态对话框保持居中原点。
- 首个工具提示保留避免误触的短延迟；同一工具栏已有提示后，连续查看相邻提示应即时切换且不重复播放入场动效。
- Hover 只增强支持悬停的鼠标或笔输入。触摸与键盘路径必须能发现并完成同一功能，不得把风险、文字或主要命令藏在悬停中。

### 8.6 可中断、反向与唯一所有者

- 用户新输入始终优先。动效从当前可见状态改向新目标，不跳回旧起点，不把输入排队到上一段结束。
- 反复打开和关闭面板、快速切换详情或连续改变选择时，同一视觉属性只保留一个动效所有者；Theme、Storyboard 与 Composition 不得争用同一属性。
- 实现不能平滑改向时，立即停止并显示新状态优于继续播放错误的连续性。
- 默认采用无可见过冲、接近临界阻尼的运动；只有直接拖动、甩动等由用户带入速度的交互经过单独评审后才允许轻微回弹。
- 列表、菜单、对话框、普通按钮和完成反馈不得无原因弹跳，也不使用大范围背景移动、循环漂浮或突然亮度变化。

### 8.7 减少动画与能力降级

- 界面层集中读取并监听 Windows `UISettings.AnimationsEnabled`。系统在应用运行中关闭动画后立即生效；应用设置以后只能进一步减少，不能覆盖系统关闭决定。
- 系统关闭动画时，页面、面板、共享元素、弹簧、位移、缩放和旋转立即完成，保留静态焦点、选中、按下、状态图标、结果文字和无障碍通知。
- 不确定进度不能只靠旋转表达，必须同时显示“正在下载”“正在安装”或“正在优化”等文字。
- 图形能力不足、Windows 选用集成显卡或混合图形设备处于低性能路径、或后台负载较高时，可以关闭复杂材质、Composition 效果与动效并改用实体背景和静态反馈；信息、命令、无障碍和业务结果不得随视觉增强一起降级。

### 8.8 性能与验证

- 用户输入后的首次视觉响应以 100ms 内为目标，最迟不超过 200ms；60Hz 设备上的允许动效以连续 60 FPS 为目标。
- 自动检查至少验证集中时长资源、键盘与高频路径为即时、系统动画关闭分支、禁止的布局属性动画、单一动效所有者，以及动画完成事件不承载业务操作。
- 快速反向、反复触发、鼠标/键盘/触摸、窗口缩放、显示缩放与文本缩放、4K、225% 显示缩放、混合 DPI 多显示器间迁移，以及下载、日志和目录解析并发时的行为都必须纳入验收场景；受限 CPU 并行期间的输入、焦点、滚动和取消同样保持响应。
- 条件允许时，在 Release 构建中使用 WPR/WPA 的 XAML Frame Analysis 检查慢帧；没有真实 Windows 证据时只在开发者发布证据中标记“未实机验证”，不把肉眼判断或自动检查冒充实机性能通过，也不因此改变本项目既定发布门槛。

## 9. 材质与深度

- 系统支持时，Mica 只用于应用根背景，建立窗口与桌面的层级关系。
- 系统支持时，Acrylic 只用于菜单、弹出层和短暂浮层，不作为大面积内容背景。
- Windows 10 22H2、减少透明度或材质能力不可用时，使用实体主题背景和明确边界；功能与信息层级不能依赖 Mica 或 Acrylic 才成立。
- 内容面板优先使用实体背景，不在半透明表面上继续叠加半透明卡片。
- 模态任务使用遮罩明确打断；并行、非阻塞面板不使用遮罩。
- 材质必须服务层级和可读性，不用模糊掩盖信息密度问题。
- 减少透明度或高对比度开启时，改用实体背景和清楚边界。

## 10. 字体与图标

- 使用 Segoe UI Variable 和 Windows 原生类型层级。
- 所有字距保持 `0`，不采用负字距。
- 字号不随窗口宽度缩放；使用固定类型层级、显示缩放、文本缩放和响应式布局适配。
- 通过字号、字重和行高建立层级，不靠极端字号差异。
- 正文和状态文本优先可读性；半透明表面上的文字保持足够对比度。
- 使用 Windows/Fluent 原生图标体系，保持相同图标在全应用中含义一致。

## 11. 无障碍

- 为所有交互控件定义正确的 Tab 顺序、可见焦点和屏幕阅读器名称。
- 状态变化通过无障碍通知暴露，不只依赖颜色或动画。
- 主要流程支持只用键盘完成。
- 遵守 Windows 显示缩放、文本缩放、高对比度、减少动画和减少透明度设置。
- 应用自身进一步减少动效时可以使用短交叉淡化或即时状态变化；Windows 系统动画开关关闭时直接呈现最终状态，仍保留必要反馈。
- 在 Windows 支持的常用显示缩放与文本缩放、窄窗口及 4K、225% 显示缩放下验证无截断、溢出与重叠。
- 颜色不是状态的唯一编码，图标也必须配合可访问名称或文本。

## 12. 风险操作

- 普通、可恢复操作不使用确认对话框。
- 用户主动关闭工作台时若目录编辑器仍有普通或恢复的未保存修改，使用一次阻断式确认避免丢失内容；“保存草稿并关闭”成功后才退出，“放弃未保存修改”明确标为会丢失本次编辑且不默认聚焦，“返回编辑”不改变任何内容。此确认只处理保存与关闭，不提供应用目录的命令，也不用于本次运行期间的页面导航、标准视图与高级视图切换或关闭调试模式；这些高频切换保持即时并保留核心中的未保存修改。
- 推荐总体优化在执行前显示已选项目摘要，允许返回调整；其中低影响项目可以默认勾选，明显改变 Windows 外观、交互或工作习惯的项目默认不勾选。
- 经典右键菜单和 Win10 风格资源管理器默认不勾选，并在执行前说明视觉变化、资源管理器重启和恢复方式；无论应用还是恢复，每次操作都保存该次修改前的实际状态和恢复记录。
- 超出已知 Windows 适用范围的系统优化只有在具备明确恢复规则时才在高级视图提供“仍然尝试”；确认内容必须说明可能无效或改变未知设置，并明确保留恢复记录。
- 软件优化不提供撤销，因此执行前使用一次确认摘要，列出已选选项、影响、关闭软件和重启要求；安装完成提示不得触发自动优化。
- 多软件优化使用一份按软件分组的批次确认摘要，普通方案不逐个弹窗；强制执行、强制关闭等额外风险只在实际触发前分别确认。
- 软件优化方案中的独立可选变更使用复选框，不用一组含义模糊的按钮代替；未勾选内容与已选内容保持清楚区分。
- 低影响推荐项默认勾选，高影响项默认不勾选；必需操作显示清楚的“必需”状态且不呈现为可交互复选框。
- 预选不等于执行，也不应提前创建优化批次；“开始所选优化”是明确提交点，执行前仍显示完整确认摘要。
- 软件优化方案版本不适用时不显示普通执行路径；标准视图说明原因，高级视图提供明确的“强制执行”，并在确认中说明可能无效、损坏配置且无法由工作台撤销。
- 目标软件仍在运行时先提供正常关闭后的“重新检测”；高级视图中的“强制关闭并继续”作为独立危险命令，说明可能丢失未保存内容且不默认聚焦。
- 可撤销操作优先提供结果反馈和撤销入口。
- 强制终止、删除恢复记录、目录降级或导入、未签名应用更新等操作显示具体影响后确认。
- “停止批次”与“强制终止”保持为两个含义明确的命令。
- 软件优化使用“停止优化”和“强制终止优化”，并与“强制关闭目标软件”明确区分；普通停止等待当前步骤安全结束，强制终止说明不完整配置风险。
- 不把不同风险合并成一次笼统确认，也不默认聚焦危险主按钮。
- 只有强制执行、不可撤销、可能丢失内容或明显改变系统行为等高风险操作使用阻断式确认；普通推荐选择、可恢复系统优化和手动说明入口使用就地摘要与反馈。
- 标准视图和高级视图使用相同的风险确认与恢复规则。

## 13. 内容语言

- 使用简短、具体、面向结果的简体中文。
- 按钮使用明确动词，例如“停止批次”“启动驱动助手”“删除恢复记录”。
- 页面不放置功能宣传、长篇操作教程或键盘快捷键说明段落。
- 帮助信息只在当前决定确实需要时出现，并紧邻其影响对象。
- 错误和警告不用责备用户的语气，也不隐去实际风险。
- “未实机验证”仅记录在开发者发布证据中，不得显示在普通用户界面或面向用户的 GitHub 发布说明中；面向用户的文案也不得声称已经完成真实设备验证。

## 14. 视觉验收矩阵

- 标准视图与高级视图可即时切换，切换后状态完整保留，所选视图可跨应用重启保持。
- 鼠标、键盘、触摸和屏幕阅读器均可完成主要流程。
- 浅色、深色、高对比度、减少动画和减少透明度状态正确。
- Windows 支持的常用显示缩放与文本缩放、不同窗口宽度及 4K、225% 显示缩放下没有截断或重叠。
- 将窗口在不同分辨率、DPI 与显示缩放的多个显示器间移动，或断开原显示器后，窗口保持可见，当前页面、焦点、滚动语义、输入、选择、进度和状态完整。
- 集成显卡、独立显卡和混合图形设备均保持相同功能与输入路径；材质、动效等视觉增强回退时仍保持可读性、状态和命令可用。
- 长任务的进度、停止、强制终止、失败恢复和重启暂停清晰可辨。
- 当前下载同时显示确定或不确定进度条、已下载量与总大小、速度和预计剩余时间；整批进度按已处理项目数单独呈现。
- 暂停下载、继续下载、停止批次和强制终止具有不同名称和状态；静默安装失败后的重试与打开官方安装程序入口就地可见。
- 推荐流程按“驱动 → 系统优化 → 软件安装 → 软件优化”呈现；系统优化页顶部的“推荐总体优化”可以展开逐项选择，并与下方单项保持同一状态、结果和恢复记录。
- 经典右键菜单和 Win10 风格资源管理器始终默认不勾选；超出已知 Windows 适用范围时，标准视图显示“可能不适用”且不能执行，高级视图只有在具备明确恢复规则并经过风险确认后才能“仍然尝试”。
- 相关系统优化完成后，“立即重启资源管理器”和“稍后处理”含义明确；选择稍后处理时能持续看到“等待资源管理器重启”并返回完成验证。
- 软件优化页在标准视图与高级视图中保持相同分组、选择和执行状态，未安装软件不出现，“暂无可用优化”区域默认收起且可访问。
- 需要额外提示的普通软件在两种视图中保持相同的可见性、默认未选状态和选择结果；卡片提示与安装批次摘要均可见，连续勾选时不出现重复阻断弹窗。
- 来源解析失败时在软件卡片内就地提供原始地址交接与主动重新检测；整个过程没有虚假的下载进度、安装状态、完成动效或文件导入入口，检测结果准确显示为“外部安装已识别”或原失败状态。检测失败时不存在强制标记成功，暂时跳过不会启用依赖或软件优化入口，两种视图的处理一致。
- 暂时跳过的软件在概览与流程总结的未完成区段跨正常关闭、异常退出、Windows 重启和发行形态切换保留，可返回原软件卡片重新检测；恢复时没有自动检测、阻断弹窗或循环提醒，识别成功后当前未完成状态消失但历史仍可查看。
- Windows 自身行为与第三方软件行为按功能所有者分属系统优化和软件优化；软件提供的资源管理器右键扩展不会被误放到系统优化或在两页重复。
- 搜狗输入法的两个安装阶段偏好具有正常自动执行与失败反馈；安装后全部首版必达选项均有可执行控件、逐项结果和必要状态确认，不能仅打开设置页或显示“暂不支持自动处理”。
- 收起安装结果附近的优化提示后，软件优化页仍保留相应状态，当前提示不会反复出现，也没有含义不清的永久忽略入口。
- 最近一次优化结果与“历史与日志”中的对应记录可互相定位，两个页面不会出现彼此独立或矛盾的历史副本。
- 标准视图不出现强制执行、强制关闭或强制终止优化命令，但能看到完整原因、安全处理方式和高级视图入口；切换视图后上下文不丢失。
- 安装与优化批次不能同时运行；停止优化、强制终止优化和强制关闭目标软件具有不同名称、状态、确认和日志结果。
- 键盘、一级导航、连续勾选、进度数值和日志刷新即时完成，不出现页面、位移、缩放或弹簧动效。
- 鼠标和触摸按下反馈即时；自定义可点击表面的缩放克制，键盘触发时不缩放。
- 偶发浮层、详情和完成反馈使用统一的 83/167/250ms 语义资源，普通自定义动效不超过 250ms，退出通常短于进入。
- Popover/Flyout 从触发位置建立空间关系，模态对话框保持居中；元素不从零缩放出现。
- 转场可从当前状态立即改向，不排队、不锁定输入，动画完成事件不承担业务操作或结果判断。
- Windows 运行期间关闭动画后立即切换到静态反馈；触摸不依赖悬停即可发现和完成全部主要操作。
- 有效动效偏好允许时，流程完成只使用一次勾选与短淡入；Windows 系统动画关闭时直接显示最终勾选和结果文字。两种路径都不出现彩屑、弹跳、音效、循环或阻塞输入的庆祝。
- 下载、日志、目录解析等高负载并发时，导航、滚动、浮层与取消操作仍保持响应；真实 WinUI 性能证据未取得时只在开发者发布证据中标记“未实机验证”。
- 调试模式开关的当前状态、额外日志影响、日志位置和目录编辑器入口清楚可见；目录编辑工作台在两种视图模式下保持同一数据和选择，分别清楚呈现未保存、恢复的未保存修改、已保存未应用、校验失败等草稿状态和普通有效目录、本机试用目录等当前目录身份，高频编辑、保存与日志刷新即时。保存草稿后软件列表不变；正常关闭和重新打开后仍原位显示“已保存未应用”，可继续编辑、明确应用或删除且不自动执行。存在未保存修改时，离开编辑器页面、切换标准视图与高级视图或关闭调试模式均不显示关闭确认、不丢失修改、不自动保存或应用，重新打开编辑器后仍显示“未保存更改”；只有主动关闭工作台才显示一次“保存草稿并关闭／放弃未保存修改／返回编辑”确认，保存失败不关闭工作台并返回编辑器显示错误，放弃只移除未保存部分，任何选项都不应用目录。异常退出或断电后找回的内容明确显示“恢复的未保存修改”，不使用完成语义、不覆盖此前草稿或当前目录；保存前应用保持不可用，显式保存后才转为“已保存未应用”，放弃只移除恢复部分，失败不得伪报已找回。若调试模式已关闭，保存失败或返回编辑只临时恢复原编辑会话，不重新开启调试模式或极详细日志，再次离开后入口继续隐藏。显式应用成功后才完整切换，无效字段可准确定位且不能强制或部分成为当前目录；删除草稿不改变当前目录、既有批次或历史。
- 运行时可加载但正式发布门禁未通过的草稿可以明确应用或从设置页导入为本机试用目录；软件安装页、推荐流程软件阶段、设置页的软件与驱动目录当前状态或导入区域，以及编辑器使用不可关闭、可换行且不只依赖颜色或图标的静态文字状态带。设置页导入后原位立即显示；关闭调试模式、切换视图和重新启动后该状态继续可见。焦点留在相应的“应用”命令或返回触发导入的命令，屏幕阅读器只礼貌播报一次，界面不使用绿色完成、勾选、Toast、音效、淡入、弹跳、循环或庆祝反馈。
- 诊断导出一次产生一个文件，并在导出前清楚显示覆盖时间、大小、脱敏状态和采集缺口；仅查看该文件即可还原工作台可观察的测试环境、操作顺序、错误阶段与最后可信状态，界面不要求用户另外整理截图或环境清单。
- 外部安装识别成功本身只更新目标软件状态；依赖软件只在用户触发下一次规划后原位恢复为可选择且保持未勾选，仍缺其他依赖的软件继续显示准确阻塞原因，任何项目都不自动创建批次、下载或安装。
- Mica 与 Acrylic 使用范围符合层级规则，没有半透明表面叠加。
- 不支持材质效果的目标系统使用实体背景回退，且不影响功能或可读性。
- 字距为 `0`，字号未随视口宽度缩放，页面没有营销式或装饰性布局。
