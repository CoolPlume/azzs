# 软件目录维护指南

状态：维护者持续填写

适用范围：[`catalog/software-catalog.toml`](../../catalog/software-catalog.toml) 中的基础软件和普通软件

`catalog/software-catalog.toml` 是软件目录的权威维护文件。维护者可以直接填写，也可以在工作台调试模式中使用图形化软件目录编辑器维护同一目录模型；工作台直接读取并进行模式校验，不需要开发者把 Markdown 表格手工抄写成另一份目录，也不要求在 C++ 中逐项硬编码。图形化编辑采用“保存草稿”与“应用”两阶段：保存只更新目录编辑草稿，显式应用并通过运行时加载校验后才替换工作台当前使用的软件目录；尚未通过正式发布门禁的内容会明确成为本机试用目录。

普通使用模式、标准视图和高级视图都不提供目录维护或手动导入控件。用户明确开启调试模式后，可以进入独立图形化编辑器或使用调试工具区的目录手动导入；编辑器只编辑本文件模式允许的字段，使用相同校验并产出 TOML 兼容结果，不是另一份软件清单或任意代码入口。

本指南不是运行时目录。它不对维护者填写的链接、说明或包作真实性、质量、来源或内容审查；既有的禁止内容边界仍然适用。

## 1. 最短填写流程

维护者可以直接按下列步骤编辑 TOML，也可以在调试模式的图形化编辑器中填写相同字段并查看同一套校验结果。

1. 打开 [`catalog/software-catalog.toml`](../../catalog/software-catalog.toml)，复制文件末尾的注释模板。
2. 填写软件名称、基础或普通软件、分类标识、发行分支、版本规则、离线版安排和用户说明；需要新分类时先在文件顶部新增一条分类。
3. 为每个启用的软件填写一个 `primary` 来源；普通在线来源只写 `purpose` 和 `address`，项目备用包或无法自动得出版本的维护者提供包再填写 `version`。
4. 有其他来源时再增加 `alternative`；维护者上传到本项目 GitHub 的包使用 `project_backup`。
5. 不确定或还没有地址时保留 `enabled = false`。补齐前该条目不会显示，也不能执行。

地址可以是打开后直接下载的链接、会发生跳转的链接、普通软件官网或下载页、GitHub 仓库、Releases 页面、具体 Release 或资产地址。维护者不填写“官网页面”“直链”“GitHub Releases”等地址类型，也不需要追踪会随版本改变的最终安装包链接。

文件已为 Game Cheats Manager、Cheat Engine、Office Tool Plus、Internet Download Manager、几何画板、Java、.NET、DirectX 和 PowerShell 7 保留 `enabled = false` 的未启用条目，因此根字段当前为 `release_state = "draft"`。以后补齐软件分支、来源与必要安装档案后再改为 `enabled = true`；这些候选软件都可以按目录与制品构建清单添加 `project_backup` 或 `large_offline`，但不代表每种制品都必须携带。`draft` 可以在调试模式中通过运行时加载校验后应用到本机试用，但不能进入正式发行包；首版范围条目和结构性发布门槛全部满足后才能把根字段改为 `release_state = "release"`。

## 2. 文件级字段

| 字段 | 填写方式 |
|---|---|
| `schema_version` | 目录结构版本；维护者不要自行修改，工作台不支持该版本时拒绝加载 |
| `catalog_id` | 目录身份，固定为 `software` |
| `revision` | 目标正式目录的修订号；维护目录发布状态为 `draft` 时可继续编辑，切换为 `release` 时必须高于上一份正式目录，同一正式修订不得对应两份不同内容 |
| `release_state` | `draft` 用于继续填写和本机试用，`release` 才可能进入正式发行包；改变该值不代替完整发布检查 |
| `default_locale` | 未指定翻译时采用的目录文字语言，首版固定为 `zh-CN` |

## 3. 分类表

分类在文件顶部集中定义，软件只引用稳定 `category_id`，不会在每个软件中重复分类名称：

```toml
[[categories]]
id = "communication"
name = "沟通"
```

新增分类时分配不可复用的 `id` 并填写默认简体中文名称。同一 `id` 只能出现一次；需要翻译时把翻译写在该分类下面，不能在各个软件内分别翻译分类。

## 4. 软件字段

| 字段 | 填写方式 |
|---|---|
| `id` | 首次添加时分配的稳定标识；发布后不改名、不复用 |
| `enabled` | `true` 表示进入目录，`false` 表示仍在补充 |
| `name` | 用户看到的软件名称 |
| `tier` | `basic` 为默认勾选的基础软件，`normal` 为默认不勾选的普通软件 |
| `category_id` | 引用文件顶部已经定义的稳定分类标识；不随翻译或分类显示名称改变 |
| `branch` | 个人版、教育版、企业版或国际版等产品分支；只在该分支内判断最新版 |
| `version_policy` | `latest_stable`、`latest_stable_with_history`、`fixed` 或 `maintainer_provided` |
| `fixed_version` | 仅固定版本时填写 |
| `dependencies` | 依赖的软件稳定标识列表；没有依赖时写空数组 |
| `bundled_editions` | 超大离线版携带时加入 `large_offline`，否则留空数组 |
| `notice` | 选择和批次确认时需要显示的简短提示，可留空 |
| `optimization_note` | 安装完成后可提供的软件优化说明，可留空 |
| `install_profile` | 仅有安装阶段偏好或特殊安装能力时引用项目内置受控安装档案；通常由开发者一次性补入，维护者不要随意修改 |
| `education` | 可选的官方教育资源地址和取得说明；未填写时界面隐藏 |

基础软件与普通软件已经决定默认选择状态，不重复填写 `default_selected`。是否存在项目 GitHub 备用包只由 `project_backup` 来源决定，不再另设布尔开关。`install_profile` 中的条款、隐私和附加推广按受控处置规则处理；已知可靠的附加推广默认拒绝。登录、注册、验证码、付款和个人资料步骤一律由用户在官方安装界面完成，不应作为维护者可填写的自动化规则。

## 5. 来源用途

`purpose` 只说明这条地址在产品中的用途，不说明地址的技术形态：

| 值 | 含义 |
|---|---|
| `primary` | 该软件唯一的首选来源 |
| `alternative` | 用户可以主动选择的普通备选来源 |
| `project_backup` | 本项目 GitHub 维护的备用包；只能由用户主动选择，不能静默替代首选来源 |

即使两条来源都位于 `github.com`，也可能分别是软件上游来源和本项目备用包；工作台不得从域名、跳转目标或文件名猜测用途。每个启用的软件必须恰好有一个 `primary` 来源，其他来源不会自动接管失败的首选来源。

`project_backup` 必须记录明确的 `version`。`version_policy = "maintainer_provided"` 且工作台无法从地址可靠得到版本时，对应来源也必须填写 `version`；这不要求维护者填写地址类型、架构或安装包类型。

## 6. 工作台自动解析地址

工作台按同一受控流程识别地址，无需维护者选择处理方式：

1. 先识别已支持的托管来源。
2. 再识别 GitHub 仓库、Releases、具体 Release 和资产地址。
3. 请求地址并跟随受控跳转；响应确实是安装文件时进入应用内下载。
4. 响应是普通网页时，交给项目内置的软件或站点解析能力取得稳定版本和安装文件。
5. 无法得到唯一且完整的结果时停止，不把网页当作安装包，也不按文件扩展名猜测。

这里的“任意地址”指任意受支持形式的 HTTP 或 HTTPS 地址，不包括命令、脚本、`javascript:`、`data:`、`file:` 或其他协议。目录不能携带网页选择器脚本、JavaScript、DLL 或第三方插件；需要适配新网站时，应在项目内增加受控解析能力，维护者无需改填最终直链。

解析成功后，工作台自行得到解析方式、当前稳定版本、实际下载地址或托管机制、架构、完整安装包或在线安装器、联网要求和解析时间。版本、架构或包类型无法确定时不能创建安装批次。

来源显示名称也由解析结果确定，不要求维护者填写。工作台优先使用提供方或仓库名称；无法取得时使用“来源用途 + 主机名”，多个结果仍重名时追加仓库或短路径信息，确保用户能区分并查看原始地址。

## 7. 版本与历史版本

- `latest_stable`：每次联网解析当前稳定版，排除 beta、preview、nightly、草稿版和预发布版。
- `latest_stable_with_history`：默认仍安装最新版，同时展示对应 `[[software.sources.history]]` 中保留的少量历史稳定版。
- `fixed`：只提供 `fixed_version` 指定的版本。
- `maintainer_provided`：采用维护者提供包所声明或可解析出的版本，不宣称它是官网最新版。

同一版本和架构同时存在完整安装包与在线安装器时优先完整安装包。最新版只有在线安装器时仍选择最新版，并提示安装过程需要联网；不得悄悄改装旧版完整包。完整安装包只有在安装所需依赖也齐全时才算离线软件包。

历史版本必须写在提供它的 `[[software.sources]]` 下面，使用 `[[software.sources.history]]`；因此用户先选择来源，再查看该来源保留的版本。历史版本地址同样由工作台自动识别，不填写地址类型；每条记录只需版本号、地址、保留原因和是否继续展示。

## 8. 解析失败时的状态

| 状态 | 使用场景 |
|---|---|
| `等待联网` | 当前没有可用网络或连接中断 |
| `来源规则待实现` | 地址可保留，但项目尚无可用的受控解析能力 |
| `暂时无法解析` | 超时、限流或来源服务暂时异常 |
| `来源失效` | 地址、发布数据、跳转或目标资源已经无效 |
| `没有适用安装包` | 找到了发布内容，但没有符合分支、稳定版本或系统架构的安装包 |
| `安装包信息待确认` | 找到了候选文件，但版本、架构或包类型无法唯一确定 |

这些状态都不会触发静默换源。工作台保留重新尝试、查看原始地址和选择其他已列来源的入口；项目 GitHub 备用包始终需要用户主动选择。

“查看原始地址”只打开维护者填写的地址；浏览器可能显示页面或直接开始下载。所得安装文件由用户在工作台之外自行运行；工作台不接收该文件的拖放、文件选择或缓存导入，也不代为启动。这个交接发生在安装批次之外，用户返回后可以主动重新检测目标软件：检测成功只显示“外部安装已识别”，不宣称工作台完成了下载或安装，也不据此认定最新版、来源或架构；检测失败则保留原解析失败状态，只提供再次“重新检测”和“暂时跳过”，即使用户确认已经安装也不能强制标记成功。暂时跳过不满足依赖、不进入软件优化发现或产生安装成功记录，并持续列入设备级未完成列表。识别成功可以满足只要求软件存在的依赖并进入软件优化发现，具体版本仍由工作台另行检测；此时移出未完成状态但保留交接历史。工作台只更新该软件存在事实，独立软件页等待用户下次主动规划，推荐流程等待用户点击“继续”，之后才让依赖已经满足的软件恢复为可选择且保持未勾选。交接记录和未完成状态跨工作台关闭、Windows 重启及便携版与安装版切换保留；恢复时不自动访问地址、检测或继续流程。维护者不需要为这条应急路径另填最终直链、安装参数或检测规则。

## 9. 教育资源与较长说明

需要时在对应软件下添加：

```toml
[software.education]
address = "https://example.com/education"
description = "帮助用户取得官方教育版的说明"
```

工作台负责展示地址和说明，并在需要认证时交给用户完成登录、资格验证和领取。维护者可以直接修改这两项；未配置时不显示空入口。安装后的较长优化说明应放入对应软件优化目录，`optimization_note` 只用于简短提示。

## 10. 后续增加语言

顶层 `default_locale = "zh-CN"` 表示当前软件名称、分类名称、提示、优化提示和教育版说明都是简体中文默认文字。`category_id` 和软件 `id` 不随翻译改变。分类翻译写在分类表下：

```toml
[categories.localizations."en-US"]
name = "Communication"
```

软件自己的文字写在对应软件下：

```toml
[software.localizations."en-US"]
name = "Software name"
notice = "Optional notice"
optimization_note = "Optional optimization note"
education_description = "Optional education instructions"
```

缺少某个翻译字段时回退到 `default_locale`，不能因为增加语言而复制来源、版本、依赖或安装规则。

## 11. 校验与发布门禁

每份候选目录分别得到“运行时加载结果”和“正式发布门禁结果”，两者不能互相代替。运行时通过是正式发布通过的必要但不充分条件；运行时失败时发布结果只能是失败或不可判定，不能通过。运行时加载校验内部采用两阶段：先校验文件级字段、分类与软件稳定标识以及每个未启用条目的最小结构，再只对 `enabled = true` 的条目检查分支、版本规则、唯一首选来源和受控能力字段是否完整。未知的展示或说明内容可以忽略；未知 `schema_version`，或会改变目标、来源、依赖、受控能力、执行、检测、恢复、重启、撤回或其他操作语义的未知内容，都会拒绝整份候选目录并保留当前有效目录。字段或引用缺失同样拒绝整份待加载目录；依赖不存在或形成循环时按既有规则只禁用受影响的软件，其他有效项目仍可使用。`enabled = false` 的未启用条目不会进入运行目录；它们缺少首选地址不会使日常维护文件无法打开。

`release_state = "draft"` 或其他仅发布级问题会使正式发布门禁失败，但本身不构成运行时整包错误。在调试模式的图形化编辑器中，运行时通过的已保存草稿可以由维护者明确应用为“本机试用目录”；调试工具区手动导入的同类软件目录也使用这一身份。如果同一内容还存在未知模式、未知执行语义、重复稳定标识、启用条目缺少必需字段等运行时整包问题，仍然拒绝应用或导入，不能因准备本机试用而绕过。

切换为 `release_state = "release"` 前必须确认所有首版必达软件均已启用、依赖存在且无循环、项目备用包具有明确版本、`install_profile` 引用可解析，并完成模式检查。维护或导入时可局部禁用的依赖错误仍会阻止项目自己的正式目录发布；未知 `schema_version`、未知执行语义、重复稳定标识或文件级结构错误则始终拒绝整份目录，不能通过禁用单个条目绕过。

## 12. 工作台与开发者负责的内容

维护者无需填写网址类型、跳转链、最终下载地址、架构识别、安装包类型、静默参数、安装结果检测或网页解析规则。工作台和项目内置受控能力负责：

- 校验 TOML 模式、稳定标识和来源用途；
- 自动识别地址并生成完整、类型化的来源解析结果；
- 在创建安装批次时冻结原始地址、来源用途、解析方式、实际资源、版本、架构、包类型、联网要求、解析时间和解析能力版本；
- 实现静默或交互式安装、安装阶段选择、安装器交互的自动处置、工作台确认与官方界面回退、完成边界与安装后置行为判断、依赖规划、结果检测、日志和恢复；
- 在地址无法处理时给出准确状态，而不是要求维护者改填易变化的最终直链。

发行流程可以把该 TOML 原样收入版本化的软件与驱动目录包，但不得再维护一份由开发者手工抄写的同类数据。生成的索引或缓存只能由工具产生，禁止手工修改，也不能成为名称、分类、版本规则、来源用途或原始地址的第二事实来源。

## 13. 调试模式中的图形化编辑器

在设置页开启“调试模式”后，调试工具区提供图形化软件目录编辑器和目录手动导入。它适合维护者反复查看和修改软件列表，但不会改变本指南的字段含义：分类、软件、依赖、版本规则、来源用途、原始地址、离线安排、说明、教育资源和本地化仍映射到同一版本化目录模型。

编辑器可以添加、复制、修改、启用、禁用和删除软件条目，并就地显示缺失字段、重复标识、无效或循环依赖、未知执行语义及发布门禁问题。未知展示或说明内容不妨碍加载；未知执行语义始终拒绝候选目录。编辑内容先形成“目录编辑草稿”；它不同于 `enabled = false` 的未启用条目，也不同于文件级 `release_state = "draft"` 的维护目录发布状态。

“保存草稿”只保存候选内容并显示“已保存未应用”，不会改变软件安装页、当前选择、规划或既有批次。正常关闭并重新打开工作台后，已经保存但尚未应用的草稿仍显示“已保存未应用”，可以继续编辑、明确应用或删除，绝不会自动应用；删除草稿不改变当前有效目录、既有批次或历史。再次编辑但尚未保存时，本次运行期间切换页面、切换标准视图与高级视图或关闭调试模式不会弹出关闭确认，也不会保存、放弃或应用修改；重新打开编辑器后仍显示“未保存更改”。只有用户真正关闭工作台时才会看到“保存草稿并关闭”“放弃未保存修改”和“返回编辑”；保存成功后才关闭，放弃只丢弃上次保存后的修改并保留此前草稿，返回编辑取消关闭，任何选择都不会应用目录。异常退出或电脑断电后，工作台会尽量找回尚未保存的编辑内容，并明确显示为“恢复的未保存修改”；它与此前已保存草稿和当前有效目录分离，不覆盖二者，也不自动保存或应用。恢复后必须先明确保存才能应用；保存成功后转为“已保存未应用”并清除恢复状态，放弃只移除恢复部分，未能找回时不得显示为已找回。保存后再次编辑时必须重新保存才能应用；“应用”只处理当前已保存草稿，并在每次点击时分别重新计算运行时加载结果和正式发布门禁结果。运行时整包校验通过后才完整替换当前有效目录；整包失败时旧目录继续使用，草稿和可定位错误保留。依赖不存在或形成循环时仍按 `CAT-13` 至 `CAT-17` 加载整份新目录并禁用受影响项，不从旧目录保留这些项，这不属于部分应用。

运行时通过但正式发布门禁未通过时，应用命令明确写作“应用为本机试用目录”。应用或从调试工具区导入成功后，编辑器、软件安装页、推荐流程的软件阶段，以及设置页的软件与驱动目录当前状态持续显示“正在使用本机试用目录”，并列出未通过的发布条件；设置页在导入后原位立即更新。之后的软件列表、规划和新建批次使用它，既有批次继续使用原快照。该身份属于同一当前有效目录，不建立另一份目录数据，也不改变 `release_state` 或正式发布结果。关闭调试模式只隐藏编辑和导入入口，本机试用目录继续生效且未发布状态继续可见，直至另一份有效目录明确替换它。

关闭调试模式只隐藏入口；同一次运行中的未保存修改继续由核心保留，已经保存但尚未应用的草稿继续持久化保留。重新打开编辑器时分别显示“未保存更改”“恢复的未保存修改”或“已保存未应用”，三者都不得自动成为当前有效目录。

未经相同核心校验达到加载门槛的内容不能成为当前有效目录；调试模式也不提供任意命令、脚本、解析代码、插件、静默参数或结果检测规则输入。

图形化编辑结果必须保持 TOML 兼容并可由 Git 查看和管理，不能只保存在界面私有数据库中。维护者可以在图形界面和文本编辑之间切换，但不得同时维护两份需要人工同步的软件目录。关闭调试模式只隐藏编辑工具，不会静默删除已经保存的目录数据。
